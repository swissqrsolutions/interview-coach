Dependency Injection in Angular, inject()

Angular · Tier 1 · Quellen: angular.dev (v22) Guides „Dependency injection“, „Hierarchical injectors“, „Injection context“, „Defining dependency providers“; API inject, InjectionToken, EnvironmentInjector, runInInjectionContext, provideAppInitializer, Injectable, Service; Angular-CHANGELOG 22.0.0

Kern: Dependency Injection (DI) ist das Muster, bei dem Angular Abhängigkeiten erzeugt und an Klassen gibt. Ein Injector sucht für ein Token einen Provider und liefert die Instanz. Angular hat zwei Hierarchien: Element-Injectors im Komponentenbaum und Environment-Injectors für App und Routen. In Angular 22 ist @Service() die Kurzform für einen Root-Service.

1. Wo sitzen die Injectors?

  1. Element-Injectors: Jede Komponente und Direktive kann providers haben. Angular sucht zuerst hier, vom Element nach oben.
  2. Route-Injector: Eine Route mit providers (oder ein lazy NgModule) erzeugt einen Environment-Injector für ihr Feature.
  3. Root-Injector: enthält appConfig.providers und alle providedIn: 'root'- bzw. @Service()-Services. Eine Instanz pro App.
  4. Platform-Injector: geteilt von mehreren Apps auf einer Seite. Selten genutzt.
  5. NullInjector: das Ende der Kette. Er wirft NullInjectorError: No provider for X (NG0201).

2. Die Reise eines inject() (die Geschichte zum Merken)

  1. inject(Token): Eine Komponente ruft inject(ReportService) in einem Feld auf. Das ist ein Injection Context.
  2. Element-Kette: Angular prüft den Element-Injector der Komponente, dann den des Parent, bis zur Wurzel.
  3. Environment-Kette: Nichts gefunden? Dann Route-Injector, Root-Injector, Platform-Injector.
  4. Provider: Der erste passende Provider gewinnt. Er sagt, wie die Instanz entsteht: Klasse, Wert, Factory oder Alias.
  5. Instanz: Existiert sie schon in diesem Injector, kommt sie zurück. Sonst wird sie erzeugt, mit eigenen Abhängigkeiten.
  6. Merken: Die Instanz bleibt im Injector. Darum ist ein Service ein Singleton pro Injector, nicht pro App.

3. Beispiel: Token, Service und Provider auf drei Ebenen

// Angular 14 bis 21: @Injectable({ providedIn: 'root' }) · Angular 22: auch @Service()
export interface ApiConfig { baseUrl: string; }
export const API_CONFIG = new InjectionToken<ApiConfig>('API_CONFIG', {
  providedIn: 'root',
  factory: () => ({ baseUrl: '/api' }),            // Standardwert
});

@Injectable({ providedIn: 'root' })
export class ReportService {
  private http = inject(HttpClient);
  private cfg  = inject(API_CONFIG);
  readonly id  = Math.random().toString(36).slice(2, 6);
  load() { return this.http.get<Report[]>(`${this.cfg.baseUrl}/reports`); }
}

// Route mit eigenem Injector
{ path: 'admin', loadComponent: () => import('./admin').then(m => m.Admin),
  providers: [{ provide: API_CONFIG, useValue: { baseUrl: '/admin-api' } }] }

// Komponente mit eigener Instanz
@Component({ selector: 'app-preview', providers: [ReportService], template: '' })
export class Preview {
  svc = inject(ReportService);
  parent = inject(ReportService, { skipSelf: true });
  logger = inject(Logger, { optional: true });     // null statt Fehler
}
Erwartetes Ergebnis (laut Doku, nicht ausgeführt):
- Normale Seiten: ReportService.cfg.baseUrl = "/api", eine Instanz (gleiche id überall).
- Unter /admin: API_CONFIG = "/admin-api" für alles, was der Route-Injector neu erzeugt.
  Achtung: ReportService ist 'root' und wurde dort schon mit "/api" erzeugt.
- Preview: svc.id !== parent.id (eigene Instanz im Element-Injector).
- logger === null, wenn es keinen Logger-Provider gibt.
  1. InjectionToken ist ein Token für Dinge ohne Klasse, z. B. Konfiguration. Mit factory ist es tree-shakable und hat einen Standard.
  2. Ein 'root'-Service wird im Root-Injector erzeugt. Er sieht nur Tokens aus Root, nicht aus dem Route-Injector. Das ist eine häufige Falle.
  3. providers an der Komponente erzeugen eine neue Instanz pro Komponenten-Instanz.
  4. skipSelf überspringt den eigenen Injector. optional liefert null statt Fehler.

4. Details, die Interviewer fragen

  1. inject() vs Konstruktor-Injection: Beide funktionieren. inject() ist typsicher ohne Dekoratoren, funktioniert in Funktionen und erleichtert Vererbung. Angular empfiehlt es heute.
  2. Injection Context: Orte, an denen inject() erlaubt ist: Konstruktor, Feld-Initialisierer, Provider-Factory, funktionale Guards, Resolver und Interceptors. Sonst: NG0203.
  3. runInInjectionContext: führt eine Funktion mit einem bestimmten Injector aus. Nützlich in Tests oder dynamischem Code.
  4. Provider-Arten: useClass (Klasse), useValue (fester Wert), useFactory (Funktion), useExisting (Alias auf anderes Token).
  5. multi: true: mehrere Provider für ein Token, das Ergebnis ist ein Array. Beispiel: HTTP_INTERCEPTORS.
  6. providedIn: 'root': Service im Root-Injector, tree-shakable. Ohne Nutzung fliegt er aus dem Bundle.
  7. @Service() (v22): Dekorator, der eine Klasse automatisch im Root-Injector bereitstellt, also wie @Injectable({providedIn: 'root'}). Abhängigkeiten holt man mit inject().
  8. providedIn: 'platform': ein Service für mehrere Apps. 'any' und providedIn: SomeNgModule sind seit v15 deprecated (im Quellcode als DEPRECATED markiert, aber noch nicht entfernt).
  9. Auflösungs-Optionen: optional, self (nur eigener Injector), skipSelf (ab Parent), host (bis zur Host-Komponente).
  10. providers vs viewProviders: viewProviders sind nur für die eigene View sichtbar. Projizierter Content sieht sie nicht.
  11. Environment vs Element: Environment-Injectors kennen keine Komponenten. Element-Injectors leben mit der Komponente und sterben mit ihr.
  12. App-Start: provideAppInitializer(() => inject(Config).load()). Der alte Weg APP_INITIALIZER mit multi: true (Angular 14) ist deprecated.
  13. makeEnvironmentProviders: bündelt Providers für eine Bibliothek, z. B. provideReporting(). Sie sind nur in Environment-Injectors erlaubt.
  14. Angular 14: inject() ging dort schon im Konstruktor und in Feldern. Üblich war aber Konstruktor-Injection.

5. Vergleich

  • providedIn: 'root': ein Singleton, tree-shakable. Standard für fast alle Services.
  • Route-providers: eine Instanz pro Feature, lebt solange der Route-Injector lebt.
  • Komponenten-providers: eine Instanz pro Komponente, z. B. Formular-State. Stirbt mit der Komponente.
  • Klasse vs InjectionToken: Klasse für Services, Token für Interfaces, Werte und Funktionen.
  • inject() vs Konstruktor: gleiche Auflösung. inject() passt zu funktionalen APIs.

6. In der Produktion

  1. NullInjectorError: Ein Provider fehlt, z. B. ein Token ohne factory oder ein Service ohne providedIn. Lösung: Provider in appConfig ergänzen. (Für HttpClient war das bis v20 typisch; seit v21 ist HttpClient ohne Provider injizierbar.)
  2. Zwei Instanzen statt einer: Service steht zusätzlich in Komponenten- oder Route-providers. State geht verloren. Lösung: nur providedIn: 'root'.
  3. NG0203: inject() in einem subscribe oder setTimeout. Lösung: im Feld injizieren oder runInInjectionContext.
  4. Zyklische Abhängigkeit (NG0200): A braucht B, B braucht A. Lösung: gemeinsamen Teil in einen dritten Service auslagern.
  5. Falsche Konfiguration im Feature: Root-Service sieht Route-Token nicht. Lösung: Service in Route-providers legen oder Token in Root.

7. Diagnose: Werkzeuge und Befehle

  • Angular DevTools, Injector Tree: zeigt Element- und Environment-Injectors und welche Provider wo liegen.
  • Fehlermeldung lesen: NullInjectorError: R3InjectorError(Standalone[App])[ReportService -> HttpClient] zeigt die Kette.
  • ng.getInjector(element) in der Konsole (Dev-Modus): Injector eines DOM-Elements holen.
  • In Tests: TestBed.inject(Service) und TestBed.runInInjectionContext(...).
  • ng generate @angular/core:inject: Migration von Konstruktor-Injection zu inject().

8. Senior-Punkte

  1. Scope ist eine Design-Entscheidung: Root für geteilten State, Route für Feature-State, Komponente für lokalen State.
  2. InjectionToken statt globaler Konstanten. So kann man pro Umgebung oder Test austauschen.
  3. Bibliotheken bieten provideX() mit makeEnvironmentProviders an. Keine Module mehr.
  4. inject() bevorzugen: funktionale Guards und Interceptors brauchen es ohnehin. Mit @Service() in v22 wird es der Normalfall.
  5. DI macht Tests einfach. Jede Abhängigkeit lässt sich per Provider durch einen Fake ersetzen.

10. Fallen

  • „Ein Service ist immer ein Singleton.“ → Falsch. Singleton pro Injector. Mehrere Provider ergeben mehrere Instanzen.
  • „inject() geht überall.“ → Falsch. Nur im Injection Context, sonst NG0203.
  • „Ein Root-Service sieht Tokens aus der Route.“ → Falsch. Er sucht ab dem Root-Injector.
  • „providers und viewProviders sind gleich.“ → Falsch. viewProviders sind für projizierten Content unsichtbar.
  • „providedIn: 'any' ist der richtige Weg für lazy Instanzen.“ → Veraltet seit v15. Route-providers nutzen.

11. Fragen

Was ist Dependency Injection in Angular?

Angular erzeugt Abhängigkeiten und gibt sie an Klassen. Ein Injector löst Tokens über Provider auf.

Was ist ein Token, was ein Provider?

Das Token ist der Schlüssel, z. B. eine Klasse. Der Provider sagt, wie die Instanz entsteht.

Wie sucht Angular einen Provider?

Zuerst die Element-Injectors nach oben, dann die Environment-Injectors bis zum NullInjector.

Was ist der Unterschied zwischen Element- und Environment-Injector?

Element-Injectors gehören zu Komponenten im DOM-Baum. Environment-Injectors gehören zu App, Plattform und Routen.

Was bewirkt providedIn: 'root'?

Ein Singleton im Root-Injector. Tree-shakable: ungenutzt fliegt er aus dem Bundle.

Was ist ein Injection Context?

Ein Ort, an dem inject() erlaubt ist: Konstruktor, Feld, Factory, funktionale Guards, Resolver und Interceptors.

Warum inject() statt Konstruktor?

Funktioniert in Funktionen, braucht keine Dekorator-Metadaten, macht Vererbung einfacher.

Wozu dient ein InjectionToken?

Für Abhängigkeiten ohne Klasse: Konfiguration, Interfaces, Funktionen. Mit factory hat es einen Standardwert.

Nennen Sie die Provider-Arten.

useClass, useValue, useFactory, useExisting. Dazu multi: true für Listen.

Was machen self, skipSelf, host und optional?

self: nur eigener Injector. skipSelf: ab Parent. host: bis zur Host-Komponente. optional: null statt Fehler.

Was ist der Unterschied zwischen providers und viewProviders?

viewProviders sind nur für die eigene View sichtbar, nicht für projizierten Content.

Wie bekommt jede Komponente eine eigene Service-Instanz?

Den Service in providers der Komponente eintragen. Er lebt und stirbt mit ihr.

Wie lädt man Konfiguration vor dem App-Start?

provideAppInitializer mit einer Funktion, die ein Promise oder Observable liefert. Früher APP_INITIALIZER, heute deprecated.

Was bedeutet NG0201?

Kein Provider gefunden, NullInjectorError. Die Meldung zeigt die Kette der Abhängigkeiten.

Was ist runInInjectionContext?

Es führt eine Funktion mit einem gegebenen Injector aus. So geht inject() auch ausserhalb des Konstruktors.

Was ist @Service() in Angular 22?

Eine Kurzform für @Injectable({providedIn: 'root'}). Mit autoProvided: false stellt man die Klasse nicht automatisch bereit.

Was ist makeEnvironmentProviders?

Eine Hülle für Providers, die nur in Environment-Injectors erlaubt sind. Basis für provideX()-Funktionen.

Szenario: Nach dem Wechsel in ein lazy Feature ist der Warenkorb leer. Warum?

Das Feature hat den Service in eigenen providers und bekommt eine neue Instanz. Lösung: nur providedIn: 'root'.

Szenario: Ein Test meldet NullInjectorError für HttpClient. Lösung?

Bis v20: im TestBed provideHttpClient() und provideHttpClientTesting() ergänzen. Seit v21 reicht provideHttpClientTesting(). Oder den Service durch einen Fake ersetzen.

Szenario: Ein Team will eine Bibliothek für fünf Apps mit eigener Konfiguration. Wie bauen Sie DI dafür?

Ein InjectionToken für die Config und eine Funktion provideReporting(config) mit makeEnvironmentProviders. Services sind providedIn: 'root'.
