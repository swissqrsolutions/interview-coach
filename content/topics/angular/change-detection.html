Change Detection: Zone.js, OnPush, Zoneless

Angular · Tier 1 · Quellen: angular.dev (v22) Guides „Zoneless“, „Skipping component subtrees“ (OnPush), „Slow computations“, „Signals“; API ChangeDetectorRef, provideZonelessChangeDetection, NgZone, PendingTasks, ChangeDetectionStrategy; Angular-CHANGELOG 22.0.0

Kern: Change Detection ist der Prozess, der Templates mit dem aktuellen State abgleicht und das DOM aktualisiert. Klassisch sagt Zone.js Angular, wann geprüft wird, und Angular prüft den ganzen Baum. OnPush und Signals begrenzen, was geprüft wird; Zoneless entfernt Zone.js ganz. In Angular 22 sind Zoneless (seit v21) und OnPush (seit v22) Default.

1. Wo sitzt die Change Detection?

  1. Auslöser: Ein Event, eine HTTP-Antwort, ein Timer oder ein Signal ändert State.
  2. Scheduler: Er entscheidet, wann geprüft wird. Mit Zone.js nach jeder async Aufgabe, zoneless nur nach einer Benachrichtigung.
  3. ApplicationRef.tick(): startet die Prüfung von der Wurzel nach unten.
  4. Eager-Komponenten (bis v21 hiess die Strategie Default): werden bei jedem Tick geprüft.
  5. OnPush-Komponenten: werden nur geprüft, wenn sie als dirty markiert sind. Sonst überspringt Angular den ganzen Teilbaum. Seit v22 ist OnPush der Default, wenn changeDetection fehlt.

2. Die Reise eines Klicks (die Geschichte zum Merken)

  1. Klick: Der Nutzer klickt einen Button mit (click)="add()". Der Handler ändert State.
  2. Markieren: Ein Template-Listener markiert die Komponente und alle Vorfahren als dirty. So erreicht die Prüfung auch OnPush-Komponenten.
  3. Planen: Mit Zone.js merkt NgZone, dass die Aufgabe fertig ist. Zoneless plant der Scheduler den Tick selbst.
  4. tick(): Angular geht den Baum von oben nach unten durch. Saubere OnPush-Teilbäume überspringt es.
  5. Vergleichen: Für jedes Binding vergleicht Angular alt und neu mit ===. Kein Deep Compare.
  6. DOM-Update: Nur geänderte Bindings ändern das DOM.
  7. Dev-Modus: Ein zweiter Durchlauf prüft, ob sich etwas geändert hat. Wenn ja: ExpressionChangedAfterItHasBeenCheckedError.

3. Beispiel: drei Arten, einen Zähler zu ändern

// Angular 22: zoneless ist Default (seit v21), kein Provider nötig.
// Angular 20: providers: [provideZonelessChangeDetection()] und "zone.js" aus polyfills entfernen

@Component({
  selector: 'app-counter',
  // v22: OnPush ist Default; in v20/v21 hier ChangeDetectionStrategy.OnPush setzen
  template: `
    <p>Feld: {{ plain }}</p>
    <p>Signal: {{ count() }}</p>
    <button (click)="plain = plain + 1">Feld +1</button>`,
})
export class Counter {
  plain = 0;
  count = signal(0);
  constructor() {
    setTimeout(() => { this.plain = 100; }, 1000);          // A
    setTimeout(() => { this.count.set(100); }, 2000);       // B
  }
}
Erwartetes Ergebnis (laut Doku, nicht ausgeführt):
nach 1 s (A): "Feld: 0"       -- zoneless + OnPush: kein Auslöser, kein Update
nach 2 s (B): "Feld: 100", "Signal: 100"
              -- Signal-Änderung plant Change Detection, die View zeigt beide Werte
Klick:        "Feld: 101"     -- Template-Listener markiert die Komponente

Gleicher Code mit Zone.js und Eager-Strategie (früher Default, z. B. Angular 14):
nach 1 s (A): "Feld: 100"     -- Zone.js hat setTimeout gepatcht und tick() ausgelöst
  1. Ohne Zone.js weiss Angular nichts vom setTimeout. Ein normales Feld ist kein Auslöser.
  2. Ein Signal, das im Template gelesen wird, ist ein Auslöser. Angular markiert die Komponente und plant einen Tick.
  3. Template-Listener ((click)) bleiben Auslöser, auch zoneless.
  4. Mit Zone.js funktioniert A, weil Zone.js jede async API patcht. Das ist bequem, aber prüft oft unnötig.

4. Details, die Interviewer fragen

  1. Zone.js: eine Bibliothek, die Browser-APIs patcht: setTimeout, Promises, addEventListener, XHR. Nach jeder Aufgabe meldet NgZone onMicrotaskEmpty. Angular ruft dann tick().
  2. Eager-Strategie (bis v21 Default): Jede Komponente wird bei jedem Tick geprüft. Einfach, aber bei grossen Bäumen teuer. Seit v22 ist ChangeDetectionStrategy.Default deprecated und ein Alias für Eager.
  3. OnPush als Default (v22): Komponenten ohne changeDetection sind OnPush. Die ng update-Migration setzt bei bestehenden Komponenten Eager, damit sich nichts ändert.
  4. OnPush: Die Komponente wird nur geprüft, wenn: ein Input eine neue Referenz bekommt, ein Event in ihr oder einem Kind passiert, markForCheck() läuft, die async-Pipe einen Wert bekommt oder ein gelesenes Signal sich ändert.
  5. markForCheck(): markiert die Komponente und alle Vorfahren. Die Prüfung kommt im nächsten Tick.
  6. detectChanges(): prüft diese Komponente und ihre Kinder sofort, synchron.
  7. detach() / reattach(): nimmt eine View aus der automatischen Prüfung. Nur für Sonderfälle, z. B. sehr häufige Datenströme.
  8. Signals und OnPush: Ein Signal markiert nur die lesende Komponente als dirty. Vorfahren werden nur durchlaufen, nicht neu geprüft. Das heisst lokale Change Detection.
  9. Zoneless: provideZonelessChangeDetection(). In v20.0 Developer Preview, ab v20.2 stabil, ab v21 Default. In v18–v19 hiess es provideExperimentalZonelessChangeDetection(). Wer ab v21 Zone.js behalten will, setzt provideZoneChangeDetection().
  10. Auslöser zoneless: markForCheck() (auch durch async-Pipe), ComponentRef.setInput(), Signal-Update im Template, Template- oder Host-Listener, Anhängen einer dirty View.
  11. NgZone zoneless: onStable, onMicrotaskEmpty und onUnstable feuern nie. Ersatz: afterNextRender oder afterEveryRender.
  12. SSR zoneless: Der Server weiss nicht mehr, wann die App fertig ist. Async-Arbeit meldet man mit PendingTasks (run(), add()) oder dem RxJS-Operator pendingUntilEvent() (Developer Preview). HttpClient macht das selbst.
  13. runOutsideAngular: Code läuft ausserhalb der Zone und löst keinen Tick aus. Gut für mousemove oder Animationen mit Zone.js.
  14. Angular 14: Nur Zone.js, Default (Standard) und OnPush (opt-in), markForCheck. Keine Signals, kein zoneless. In v22 ist es umgekehrt: OnPush Standard, Eager opt-in.

5. Vergleich

  • Zone.js + Eager (früher Default): funktioniert „magisch“, prüft aber den ganzen Baum nach jeder async Aufgabe.
  • Zone.js + OnPush: gleiche Auslöser, aber saubere Teilbäume werden übersprungen. Erfordert unveränderliche Daten.
  • Zoneless + OnPush + Signals: Prüfung nur nach echter Benachrichtigung. Kleinere Bundles ohne Zone.js, bessere Stack Traces, kein Patchen.
  • markForCheck vs detectChanges: später im nächsten Tick vs sofort synchron.
  • async-Pipe vs toSignal: beide melden Änderungen. toSignal ist ein Signal und passt besser zu computed.

6. In der Produktion

  1. App ruckelt bei Mausbewegung: Ein mousemove-Listener löst Hunderte Ticks aus. Lösung: runOutsideAngular oder zoneless.
  2. Daten erscheinen nicht: OnPush-Komponente, Objekt wurde mutiert. Lösung: neue Referenz oder Signal.
  3. Nach Umstieg auf zoneless bleibt UI stehen: Code ändert Felder in setTimeout oder Callbacks von Bibliotheken. Lösung: Signals oder markForCheck().
  4. SSR hängt oder rendert leer: zoneless ohne PendingTasks für eigene async Arbeit. Lösung: Aufgaben registrieren.
  5. Teure Getter im Template: Eine Methode im Template läuft bei jedem Tick. Lösung: computed() oder eine pure Pipe.
  6. ExpressionChanged-Fehler nach Refactoring. Lösung: Datenfluss nur von oben nach unten.

7. Diagnose: Werkzeuge und Befehle

  • Angular DevTools Profiler: zeigt jeden Change-Detection-Zyklus, Dauer pro Komponente und Auslöser.
  • ng.profiler.timeChangeDetection() in der Konsole (nach enableDebugTools): misst die Dauer eines Ticks.
  • Chrome Performance Tab: lange Tasks und Layout Thrashing finden.
  • provideCheckNoChangesConfig({ exhaustive: true, interval: … }) (Developer Preview): findet im Dev-Modus Änderungen ohne Benachrichtigung, nützlich vor zoneless und OnPush.
  • Lint-Regel @angular-eslint/prefer-on-push-component-change-detection.

8. Senior-Punkte

  1. OnPush überall: Seit v22 ist es Framework-Standard. Es zwingt zu unveränderlichen Daten und klarem Datenfluss. Nach dem Update gesetzte Eager-Angaben schrittweise entfernen.
  2. Zoneless ist das Ziel, aber eine Migration. Erst OnPush und Signals, dann Zone.js entfernen.
  3. Signals statt markForCheck: Der Code sagt selbst, was sich geändert hat.
  4. Kosten messen mit dem Profiler, nicht raten. Oft sind teure Templates das Problem, nicht die Anzahl der Ticks.
  5. Bibliotheken prüfen: Manche Drittanbieter verlassen sich auf Zone.js. Das blockiert zoneless.

10. Fallen

  • „OnPush prüft nur bei Input-Änderung.“ → Falsch. Auch bei Events, async-Pipe, markForCheck und Signals.
  • „Angular vergleicht Objekte tief.“ → Falsch. Es vergleicht mit ===, also Referenzen.
  • „Zone.js macht die Change Detection.“ → Falsch. Zone.js sagt nur wann. Angular prüft selbst.
  • „Zoneless ist in v20.0 stabil.“ → Falsch. v20.0 Developer Preview, stabil ab v20.2, Default ab v21.
  • „Ohne Angabe ist eine Komponente Default/Eager.“ → Seit v22 falsch. Ohne Angabe ist sie OnPush.
  • „detectChanges und markForCheck sind gleich.“ → Falsch. Sofort und lokal vs später im nächsten Tick.
  • „ExpressionChanged-Fehler gibt es in Produktion.“ → Nein. Nur der Dev-Modus prüft doppelt, der Bug bleibt aber.

11. Fragen

Was ist Change Detection?

Der Abgleich von Templates mit dem State. Angular vergleicht Bindings und aktualisiert nur geänderte DOM-Knoten.

Welche Rolle spielt Zone.js?

Es patcht async Browser-APIs. Nach jeder Aufgabe meldet NgZone das, und Angular ruft tick() auf.

Wie läuft ein tick()?

Von der Wurzel nach unten. Eager-Komponenten immer, OnPush-Komponenten nur wenn dirty.

Was ist in Angular 22 die Standard-Strategie?

OnPush. Die alte Strategie heisst Eager; ChangeDetectionStrategy.Default ist deprecated. ng update setzt bei alten Komponenten Eager.

Wann wird eine OnPush-Komponente geprüft?

Neue Input-Referenz, Event in ihr oder einem Kind, markForCheck, async-Pipe, Änderung eines gelesenen Signals.

Was ist der Unterschied zwischen markForCheck und detectChanges?

markForCheck markiert bis zur Wurzel für den nächsten Tick. detectChanges prüft sofort diese View und ihre Kinder.

Was ist ExpressionChangedAfterItHasBeenCheckedError?

Ein Wert ändert sich nach der Prüfung im selben Zyklus. Der Dev-Modus erkennt das mit einem zweiten Durchlauf.

Was ist Zoneless Change Detection?

Angular ohne Zone.js. Prüfung nur nach Benachrichtigungen wie Signal-Update, markForCheck oder Template-Event.

Wie aktiviert man zoneless?

Ab v21 ist es Default, man muss nichts tun. In v20 provideZonelessChangeDetection() setzen und zone.js aus den Polyfills entfernen.

Welche Vorteile hat zoneless?

Weniger unnötige Prüfungen, kleineres Bundle, bessere Stack Traces, keine gepatchten APIs.

Was passiert mit NgZone.onStable bei zoneless?

Es feuert nie. Ersatz sind afterNextRender oder afterEveryRender.

Warum braucht SSR bei zoneless PendingTasks?

Der Server muss wissen, wann die App stabil ist. Ohne Zone.js meldet man offene Arbeit über PendingTasks.

Wie helfen Signals der Change Detection?

Angular weiss genau, welche Komponente ein Signal liest. Es markiert nur diese und prüft lokal.

Was macht runOutsideAngular?

Code läuft ausserhalb der Zone und löst keinen Tick aus. Für häufige Events oder Animationen.

Warum sind Methoden im Template problematisch?

Sie laufen bei jeder Prüfung. Besser computed() oder eine pure Pipe.

Warum braucht OnPush unveränderliche Daten?

Angular vergleicht Referenzen. Eine Mutation behält die Referenz, also sieht OnPush nichts.

Was ist ein pure Pipe?

Eine Pipe, die nur bei neuer Eingabe-Referenz neu rechnet. Standard für eigene Pipes.

Szenario: Nach Umstieg auf zoneless aktualisiert ein Websocket-Feed die UI nicht mehr. Warum?

Der Callback ändert ein normales Feld ohne Benachrichtigung. Lösung: Wert in ein Signal schreiben oder toSignal nutzen.

Szenario: Ein Dashboard mit 500 Zeilen ruckelt bei jeder Mausbewegung. Was tun Sie?

Profiler zeigt viele Ticks. Lösung: OnPush, Listener mit runOutsideAngular, computed statt Template-Methoden, Virtual Scroll.

Szenario: Eine OnPush-Komponente zeigt einen Wert aus einem Service nicht an. Lösung?

Der Service ändert ein Feld ohne Benachrichtigung. Den Wert als Observable mit async-Pipe oder als Signal bereitstellen.
