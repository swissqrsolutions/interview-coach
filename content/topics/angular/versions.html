Angular 14 bis 20: was ist neu

Angular · Tier 1 · Quellen: angular.dev (v20) „Release schedule / Versioning“, „Signals“, „Built-in control flow“, „Deferrable views“, „Zoneless“, „Hydration“, „Incremental hydration“, „Build system migration“, „Update guide“ (angular.dev/update-guide); API-Statusangaben (stable / developer preview / experimental)

Kern: Zwischen Angular 14 und 20 hat sich das Programmiermodell geändert: Standalone statt NgModules, Signals statt vieler RxJS-Subscriptions, eingebauter Control Flow (@if, @for) statt *ngIf, @defer für Lazy Loading im Template, Zoneless statt Zone.js. Dazu ein neuer Build mit esbuild und Vite sowie stabile SSR mit Hydration.

1. Wo sitzen die Änderungen?

  1. Struktur: Komponenten importieren ihre Abhängigkeiten selbst. Globale Dinge kommen über provideRouter, provideHttpClient.
  2. Reaktivität: Signals sind Werte, die ihre Leser kennen. Angular weiss so, welche View sich ändert.
  3. Templates: eingebauter Control Flow statt Strukturdirektiven, @defer für verzögertes Laden, @let für lokale Variablen.
  4. Change Detection: Mit Signals braucht Angular Zone.js nicht mehr.
  5. Build: Der application-Builder mit esbuild ersetzt webpack. Builds sind deutlich schneller.
  6. Rendering: SSR mit Hydration übernimmt das Server-HTML, statt es neu zu bauen.

2. Die Reise von 14 nach 20 (die Geschichte zum Merken)

  1. v14 (Juni 2022): Typed Forms, Standalone als Developer Preview, inject() in Konstruktoren und Feldern, Seitentitel per Route, CanMatch.
  2. v15: Standalone stabil. provideRouter, provideHttpClient, funktionale Guards und Interceptors. Directive Composition API, NgOptimizedImage stabil.
  3. v16: Signals als Developer Preview, DestroyRef, takeUntilDestroyed, Required Inputs, withComponentInputBinding, Hydration als Preview, esbuild als Preview.
  4. v17: Control Flow (@if, @for, @switch) und @defer. Der esbuild-application-Builder wird Standard für neue Projekte. Hydration stabil. Neue Doku auf angular.dev. signal und computed stabil.
  5. v18: Zoneless experimentell. Control Flow und @defer stabil. Event Replay. @let kam in 18.1. Form-Events über control.events.
  6. v19: standalone: true ist Default. Signal-Inputs, -Outputs und -Queries stabil. linkedSignal, resource experimentell. Inkrementelle Hydration als Preview. provideAppInitializer.
  7. v20 (Mai 2025): effect, linkedSignal, toSignal stabil. Zoneless als Developer Preview (stabil ab 20.2). Inkrementelle Hydration stabil. afterRender heisst jetzt afterEveryRender. *ngIf, *ngFor, *ngSwitch deprecated.

3. Beispiel: dieselbe Komponente in Angular 14 und Angular 20

// ---- Angular 14 ----
@Component({
  selector: 'app-report-list',
  template: `
    <app-spinner *ngIf="loading"></app-spinner>
    <li *ngFor="let r of reports$ | async; trackBy: trackById">{{ r.name }}</li>`,
})
export class ReportListComponent implements OnInit, OnDestroy {
  @Input() region!: string;
  reports$!: Observable<Report[]>;
  loading = true;
  private destroy$ = new Subject<void>();
  constructor(private api: ReportApi) {}
  ngOnInit() { this.reports$ = this.api.list(this.region).pipe(finalize(() => this.loading = false)); }
  trackById(_: number, r: Report) { return r.id; }
  ngOnDestroy() { this.destroy$.next(); this.destroy$.complete(); }
}
// + Deklaration in einem NgModule

// ---- Angular 20 ----
@Component({
  selector: 'app-report-list',
  imports: [Spinner, Chart],
  changeDetection: ChangeDetectionStrategy.OnPush,
  template: `
    @if (reports.isLoading()) { <app-spinner /> }
    @for (r of reports.value() ?? []; track r.id) {
      <li>{{ r.name }}</li>
    } @empty { <li>Keine Reports</li> }
    @defer (on viewport) { <app-chart [data]="reports.value()" /> }
    @placeholder { <p>Chart lädt beim Scrollen</p> }`,
})
export class ReportList {
  region  = input.required<string>();
  reports = httpResource<Report[]>(() => `/api/reports?region=${this.region()}`); // experimentell in v20
}
Erwartetes Ergebnis (laut Doku, nicht ausgeführt):
- Beide Versionen zeigen dieselbe Liste.
- v20: Ändert sich region, lädt httpResource automatisch neu; alter Request wird abgebrochen.
- v20: Der Chart-Code liegt in einem eigenen Lazy Chunk und lädt erst im sichtbaren Bereich.
- v20: @empty zeigt "Keine Reports" ohne extra *ngIf.
- ng build (v20): "Application bundle generation complete" mit Initial- und Lazy-Chunks (esbuild).
  1. @for verlangt track. In v14 war trackBy optional und wurde oft vergessen.
  2. Signal-Input statt @Input: Änderungen von region fliessen automatisch weiter.
  3. Kein destroy$, kein ngOnInit, kein NgModule.
  4. @defer ersetzt manuelles Lazy Loading einer Komponente. Der Compiler erzeugt den Chunk selbst.
  5. httpResource ist in v20 experimentell. In Produktion wäre toSignal(http.get(...)) die sichere Wahl.

4. Details, die Interviewer fragen

  1. Signals: signal() (schreibbar), computed() (abgeleitet, lazy, gecacht), effect() (Seiteneffekt). linkedSignal() ist schreibbar, setzt sich aber bei Quelländerung zurück.
  2. resource / httpResource: laden asynchrone Daten als Signals mit value, isLoading, error. In v20 experimentell.
  3. Control Flow: @if/@else, @for mit Pflicht-track und @empty, @switch. Schneller als *ngFor und ohne Import. Migration: ng generate @angular/core:control-flow.
  4. @defer: Trigger on idle (Standard), viewport, interaction, hover, timer, immediate, oder when cond. Blöcke @placeholder, @loading, @error. Mit prefetch on … lädt der Code früher.
  5. Bedingung für @defer: Die Komponenten im Block müssen standalone sein und dürfen sonst nirgends eager referenziert sein.
  6. Zoneless: provideZonelessChangeDetection(). v18–19 experimentell, v20.0 Preview, ab 20.2 stabil, ab v21 Default.
  7. SSR und Hydration: provideClientHydration(). Der Browser übernimmt das Server-DOM, statt es neu zu bauen. Kein Flackern, besserer LCP.
  8. Event Replay (stabil seit v19, mit withEventReplay()): Klicks vor der Hydration werden gespeichert und danach ausgeführt.
  9. Inkrementelle Hydration: withIncrementalHydration() und @defer (hydrate on viewport). Teile bleiben statisch, bis sie gebraucht werden. Stabil in v20.
  10. Render-Modus pro Route: RenderMode.Server, Client, Prerender in den Server-Routen. Stabil in v20.
  11. Build: v14 nutzte webpack (esbuild nur experimentell). Ab v17 ist der application-Builder mit esbuild und Vite-Dev-Server Standard. Migration: ng update @angular/cli --name use-application-builder.
  12. Style Guide v20: Dateinamen ohne Suffix (user.ts statt user.component.ts), inject() bevorzugt.
  13. Weitere v20-Punkte: Template-Ausdrücke mit **, in, void und Template-Literalen. Vitest als experimenteller Test-Runner.
  14. Updates: ng update immer eine Major-Version pro Schritt. Der Update-Guide auf angular.dev listet alle Schritte von 14 nach 20.

5. Vergleich

  • *ngIf/*ngFor vs @if/@for: Direktiven mit Import und optionalem trackBy vs eingebaut, Pflicht-track, schneller.
  • RxJS-State vs Signals: Subscriptions und async-Pipe vs synchrone Werte ohne Unsubscribe. RxJS bleibt für Ströme.
  • NgModule vs Standalone: Modul als Scope vs Komponente als Scope.
  • Zone.js vs Zoneless: automatisch, aber breit vs gezielt über Benachrichtigungen.
  • webpack-Builder vs application-Builder: langsam, alt vs esbuild, schnell, SSR eingebaut.
  • Lazy Route vs @defer: Lazy pro URL vs Lazy pro Template-Bereich.

6. In der Produktion

  1. Upgrade-Sprung zu gross: 14 direkt auf 20 geht nicht. Lösung: Version für Version mit ng update, Tests nach jedem Schritt.
  2. Bibliotheken bremsen: Eine UI-Bibliothek unterstützt die neue Version nicht. Lösung: Kompatibilität vorher prüfen, ggf. ersetzen.
  3. Unterstützung endet: v20 hat LTS nur bis 28.11.2026. Danach keine Security-Fixes. Lösung: Upgrade einplanen.
  4. Hydration-Fehler (NG0500): Server- und Client-DOM unterscheiden sich, z. B. durch direkte DOM-Manipulation. Lösung: DOM nur über Angular, sonst ngSkipHydration.
  5. @defer-Komponente wird trotzdem eager geladen: Sie wird ausserhalb des Blocks referenziert. Lösung: nur im Block nutzen.
  6. Experimentelle APIs in Produktion: httpResource kann sich ändern. Lösung: hinter eigenem Service kapseln.

7. Diagnose: Werkzeuge und Befehle

  • ng version: installierte Versionen von Angular, CLI, TypeScript, RxJS.
  • ng update: zeigt verfügbare Updates und führt Migrationen aus.
  • angular.dev/update-guide: Schritt-für-Schritt-Liste von Version A nach B.
  • Migrationen: @angular/core:standalone, :control-flow, :signal-input-migration, :inject.
  • Angular DevTools: Signal-Graph, Hydration-Status, @defer-Blöcke.
  • ng build-Ausgabe: Chunks und Budgets prüfen nach dem Wechsel auf esbuild.

8. Senior-Punkte

  1. Upgrade ist ein Dauerprozess: zwei Majors pro Jahr. Wer jedes Mal mitgeht, hat kleine Schritte.
  2. Neues Modell schrittweise: neuer Code mit Standalone, Signals, Control Flow. Alter Code per Schematic, Feature für Feature.
  3. Stabilität prüfen: stable, developer preview, experimental. Nur stable in Kernpfade.
  4. Signals und RxJS nebeneinander sind normal. toSignal und toObservable verbinden sie.
  5. SSR nur mit Grund: SEO, erste Ladezeit. Sonst kostet es Betrieb und Komplexität.

9. Aus dem Projekt

„Meine letzte produktive Angular-Version war 14 bei CARIAD; Signals, Control Flow und Zoneless habe ich nur gelernt, nicht in Produktion eingesetzt.“ (Prüfen und durch dein echtes Beispiel ersetzen.)

10. Fallen

  • „Signals ersetzen RxJS.“ → Falsch. Signals für State, RxJS für Ströme und Zeit.
  • „*ngIf geht in v20 nicht mehr.“ → Falsch. Es ist deprecated, funktioniert aber noch.
  • „Zoneless ist in v20 Standard.“ → Falsch. Erst ab v21 für neue Projekte.
  • „Standalone kam mit v17.“ → Falsch. Preview in v14, stabil in v15, Default in v19.
  • „Man kann direkt von 14 auf 20 updaten.“ → Falsch. Eine Major-Version pro Schritt.
  • „Angular 20 ist die neueste Version.“ → Nicht mehr. v21 und v22 sind erschienen; v20 ist nur noch LTS.

11. Fragen

Was sind die grössten Änderungen seit Angular 14?

Standalone, Signals, eingebauter Control Flow, @defer, Zoneless, esbuild-Build und stabile Hydration.

Was sind Signals?

Reaktive Werte, die ihre Leser kennen. signal, computed und effect, dazu linkedSignal.

computed vs effect?

computed leitet einen Wert ab, lazy und gecacht. effect führt Seiteneffekte aus, z. B. Logging oder DOM-Bibliotheken.

Was ist linkedSignal?

Ein schreibbares Signal, das sich bei Änderung seiner Quelle neu berechnet. Stabil in v20.

Was ist der neue Control Flow?

@if, @for, @switch direkt im Template. @for braucht track und hat @empty.

Warum ist track in @for Pflicht?

Ohne Identität baut Angular bei Änderungen DOM-Knoten neu. track macht Updates schnell und stabil.

Was ist @defer?

Ein Template-Block, dessen Komponenten in einem eigenen Chunk liegen und erst bei einem Trigger laden.

Welche @defer-Trigger gibt es?

on idle, viewport, interaction, hover, timer, immediate und when. Dazu prefetch.

Was ist Hydration?

Der Browser übernimmt das Server-HTML und hängt Listener an, statt das DOM neu zu bauen.

Was ist inkrementelle Hydration?

Teile der Seite bleiben statisch und werden erst bei einem Trigger hydriert, über @defer (hydrate on …). Stabil in v20.

Was ist Event Replay?

Nutzer-Events vor der Hydration werden gespeichert und danach abgespielt. Stabil seit v19.

Was hat sich am Build geändert?

Der application-Builder mit esbuild und Vite ersetzt webpack. Standard für neue Projekte seit v17.

Was ist in v20 deprecated?

*ngIf, *ngFor und *ngSwitch. HttpClientModule ist schon seit v18 deprecated.

Was wurde in v20 umbenannt?

afterRender heisst afterEveryRender. Der Zoneless-Provider heisst provideZonelessChangeDetection ohne „Experimental“.

Wie lange wird eine Angular-Version unterstützt?

18 Monate: 6 Monate aktiv, 12 Monate LTS. v20 LTS endet am 28.11.2026.

Was ist resource bzw. httpResource?

Signal-APIs für asynchrone Daten mit value, isLoading und error. In v20 experimentell.

Szenario: Sie sollen eine Angular-14-App auf 20 bringen. Plan?

ng update Schritt für Schritt bis 20, nach jedem Schritt Tests. Dann Migrationen: Standalone, Control Flow, inject, Signal-Inputs. Zuletzt esbuild-Builder und Zoneless prüfen.

Szenario: Der Interviewer fragt: „Sie kennen nur Angular 14?“ Was antworten Sie?

Produktiv 14, die neuen Konzepte habe ich gelernt und kann sie erklären: Standalone, Signals, Control Flow, @defer, Zoneless. Die Grundlagen DI, RxJS, Routing und Forms sind gleich geblieben.

Szenario: Nach dem Aktivieren von SSR erscheint NG0500 in der Konsole. Was tun Sie?

Hydration-Mismatch: Server- und Client-DOM unterscheiden sich. Direkte DOM-Manipulation oder ungültiges HTML suchen. Notfalls ngSkipHydration für die Komponente.
