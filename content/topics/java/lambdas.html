Lambdas und Method References

Kern: Ein Lambda ist eine anonyme Funktion, die man wie einen Wert übergibt, zum Beispiel s -> s.length(). Sein Typ ist immer ein Functional Interface, und es gibt Verhalten ohne Boilerplate-Klassen weiter. Technisch erzeugt javac keine eigene Klasse, sondern ein invokedynamic, und die JVM baut die Implementierung zur Laufzeit über LambdaMetafactory.

Antwort-Muster

Frage: Wie funktioniert ein Lambda intern?

  1. Mechanismus: javac macht den Rumpf zu einer privaten Methode und setzt ein invokedynamic. Beim ersten Aufruf baut LambdaMetafactory eine Hidden Class.
  2. Zahl: invokedynamic gibt es seit Java 7, Hidden Classes für Lambdas seit Java 15. Nur die erste Verlinkung kostet.
  3. Trade-off: Ohne Capture gibt es dieselbe Instanz, mit Capture pro Auswertung ein neues Objekt. Das ist ein Implementierungsdetail.
  4. Produktion: Lange Lambdas lagere ich in benannte Methoden aus, damit Stack Traces lesbar bleiben.

1. Die Reise eines Lambdas

  1. Erster Aufruf: Die JVM trifft das erste Mal auf invokedynamic. Die Stelle ist noch nicht verlinkt.
  2. Bootstrap: Die JVM ruft LambdaMetafactory.metafactory mit Lookup, Methodenname (apply), Signaturen und dem MethodHandle auf.
  3. Hidden Class: Die Fabrik erzeugt Bytecode für eine kleine Klasse und lädt sie als Hidden Class. Ihr Name endet auf $$Lambda$1/0x….
  4. CallSite: Das Ergebnis ist eine CallSite. Die JVM verlinkt sie fest. Weitere Aufrufe überspringen Schritte 2 und 3.
  5. Capture: Ohne gefangene Variablen gibt die CallSite immer dieselbe Instanz zurück. Mit gefangenen Variablen entsteht pro Ausführung ein neues Objekt mit den Werten als Felder.
  6. JIT: Im Dauerbetrieb inlined der JIT den Rumpf. Ein Lambda ist dann so schnell wie ein direkter Aufruf.

2. Aufbau

  1. Quellcode: Das Lambda braucht einen Zieltyp, ein Functional Interface wie Function.
  2. Lambda-Rumpf: javac legt ihn als private static Methode lambda$main$3 in dieselbe Klasse. Nutzt das Lambda this, ist die Methode nicht static.
  3. Aufrufstelle: Statt new steht dort invokedynamic. Das ist ein Platzhalter, den die JVM beim ersten Ausführen auflöst.
  4. Bootstrap-Methode: LambdaMetafactory.metafactory bekommt die Interface-Signatur und einen MethodHandle auf den Rumpf.
  5. Laufzeit: Die Fabrik erzeugt eine Hidden Class (Java 15, JEP 371), die das Interface implementiert. Keine Datei auf der Platte.
  6. Anonyme Klasse: zum Vergleich: javac schreibt eine eigene .class-Datei.

3. Details, die Interviewer fragen

  1. Syntax: Es gibt (a, b) -> a + b. Ein Parameter geht ohne Klammern. Ein Block-Rumpf nutzt { return …; }. Parametertypen sind optional. var geht seit Java 11.
  2. Zieltyp (Target Typing): Ein Lambda hat keinen eigenen Typ. Der Kontext bestimmt das Functional Interface. Dasselbe Lambda passt zu Callable oder Supplier.
  3. Functional Interface: Es hat genau eine abstrakte Methode. Details stehen auf der Seite „Interface vs abstrakte Klasse".
  4. Wichtige Interfaces: Dazu gehören Function<T,R> (apply), Consumer<T> (accept), Supplier<T> (get) und Predicate<T> (test). Dazu kommen UnaryOperator, BinaryOperator, BiFunction, Runnable und Callable.
  5. Primitive Spezialisierungen: IntPredicate, ToIntFunction und IntUnaryOperator vermeiden Boxing.
  6. Effectively final (JLS §4.12.4): Das ist eine lokale Variable ohne final, die nach der Initialisierung nie geändert wird. Lambdas dürfen nur solche lokalen Variablen lesen. Das Lambda kopiert den Wert. Änderungen wären unsichtbar und in Threads unsicher.
  7. Felder sind frei: Ein Lambda darf Instanz- und static-Felder lesen und ändern. Dann gelten die normalen Regeln für Thread-Sicherheit.
  8. this und Scope: Ein Lambda öffnet keinen neuen Scope. this ist das umgebende Objekt. Ein Parameter darf nicht wie eine lokale Variable heissen.
  9. Method References (JLS §15.13): Sie sind die Kurzform, wenn das Lambda nur eine Methode aufruft. Es gibt vier Arten. Das sind static, bound, unbound und Konstruktor.
  10. Bound vs unbound: obj::m wertet obj sofort aus. Ist obj null, kommt die NPE beim Erzeugen. Klasse::m nimmt den Empfänger als ersten Parameter.
  11. invokedynamic: Das ist ein Bytecode-Befehl seit Java 7. Eine Bootstrap-Methode entscheidet zur Laufzeit über die Verlinkung. Java nutzt ihn für Lambdas, für String-Verkettung (seit 9) und für Records (ObjectMethods).
  12. Warum invokedynamic statt anonymer Klassen: Es gibt keine Datei pro Lambda. Der Metaspace wird beim Start weniger belastet. Die JVM kann die Strategie später ändern, ohne alten Bytecode zu brechen.
  13. Serialisierung: Lambdas sind nur serialisierbar, wenn der Zieltyp Serializable ist. Davon wird abgeraten.
  14. Checked Exceptions: Standard-Interfaces deklarieren keine. Siehe Seite „Exceptions".
  15. Komposition: Dafür gibt es Function.andThen, compose, Predicate.and/or/negate und Comparator.comparing(...).thenComparing(...).
  16. Unbenannte Parameter (Java 22, JEP 456): Mit (_, wert) -> wert markiert man ungenutzte Parameter. In Java 25 sind sie verfügbar.

4. Fallen

  • „Ein Lambda ist eine anonyme Klasse.“ → Falsch. Kein .class beim Kompilieren, invokedynamic und Hidden Class zur Laufzeit, anderes this.
  • „Lambdas dürfen keine Variablen ändern.“ → Ungenau. Nur lokale Variablen müssen effectively final sein. Felder darf man ändern.
  • „Effectively final heisst unveränderlich.“ → Falsch. Nur die Referenz bleibt gleich. Eine gefangene Liste kann man verändern.
  • „Jeder Lambda-Aufruf erzeugt ein Objekt.“ → Falsch. Ohne Capture gibt HotSpot dieselbe Instanz zurück.
  • „Lambdas sind langsam wegen invokedynamic.“ → Falsch. Nur die erste Verlinkung kostet. Danach inlined der JIT.
  • „this im Lambda ist das Lambda.“ → Falsch. Es ist das umgebende Objekt.

5. Selbsttest

Warum?

Was ist ein Lambda-Ausdruck?

Eine anonyme Funktion, die man als Wert übergibt. Ihr Typ ist ein Functional Interface, das der Kontext bestimmt.

Warum müssen gefangene lokale Variablen effectively final sein?

Das Lambda bekommt eine Kopie des Werts. Änderungen wären nicht sichtbar und bei Threads unsicher.

Warum nutzt Java invokedynamic statt anonymer Klassen?

Keine Class-Datei pro Lambda und Freiheit, die Strategie später in der JVM zu ändern, ohne Bytecode neu zu kompilieren.

Warum ist submit(() -> foo()) manchmal mehrdeutig?

Es passt zu Runnable und Callable. Gibt foo einen Wert zurück, wählt javac Callable. Explizite Typen oder Casts lösen Zweifel.

Warum wirft eine bound Method Reference schon beim Erzeugen eine NPE?

obj::m wertet obj sofort aus. Ist obj null, scheitert das beim Erzeugen. Das Lambda x -> obj.m(x) scheitert erst beim Aufruf.

Wie innen?

Was heisst effectively final?

Eine lokale Variable, die nach der Initialisierung nie geändert wird, auch ohne final. Nur solche darf ein Lambda lesen.

Was bedeutet this in einem Lambda?

Das umgebende Objekt. Ein Lambda öffnet keinen neuen Scope, anders als eine anonyme Klasse.

Wie kompiliert javac ein Lambda?

Der Rumpf wird eine private Methode lambda$…. An der Aufrufstelle steht invokedynamic mit LambdaMetafactory als Bootstrap.

Was ist invokedynamic?

Ein Bytecode-Befehl, dessen Ziel eine Bootstrap-Methode beim ersten Aufruf festlegt. Danach ist die CallSite verlinkt.

Was macht LambdaMetafactory?

Sie erzeugt zur Laufzeit eine Hidden Class, die das Functional Interface implementiert und den Rumpf aufruft, und liefert eine CallSite.

Erzeugt jeder Lambda-Aufruf ein neues Objekt?

Nein. Ohne Capture liefert HotSpot dieselbe Instanz. Mit Capture entsteht pro Auswertung ein neues Objekt.

Wie sieht man, was javac aus einem Lambda gemacht hat?

Mit javap -c -p für invokedynamic und lambda$-Methoden, mit javap -v für die BootstrapMethods.

Zahlen

Was ist der Unterschied zwischen andThen und compose?

f.andThen(g) führt erst f, dann g aus. f.compose(g) führt erst g, dann f aus.

Was ist eine Hidden Class?

Eine Klasse, die nur per Lookup.defineHiddenClass entsteht, nicht per Name auffindbar ist und entladen werden kann. Seit Java 15 nutzen Lambdas sie.

Seit welcher Java-Version darf man var in Lambda-Parametern nutzen?

Seit Java 11. Parametertypen sind sonst optional.

Seit wann gibt es unbenannte Parameter im Lambda?

Seit Java 22 (JEP 456), mit (_, wert) -> wert. In Java 25 sind sie verfügbar.

Vergleich

Welche Arten von Method References gibt es?

Static (Math::max), bound (obj::m), unbound (String::length) und Konstruktor (ArrayList::new).

Was ist der Unterschied zwischen bound und unbound Method Reference?

Bound hat den Empfänger schon festgelegt und wertet ihn sofort aus. Unbound bekommt den Empfänger als ersten Parameter.

Lambda vs anonyme Klasse?

Lambda: kein eigener Scope, keine Datei, nur Functional Interfaces. Anonyme Klasse: eigenes this, Zustand möglich, auch für abstrakte Klassen.

Lambda oder Method Reference?

Die Method Reference ist lesbarer, wenn das Lambda nur eine Methode aufruft. Oft braucht sie keine synthetische Methode.

Lambda oder Schleife?

Lambda für Callbacks und Streams. Schleife für Kontrollfluss mit break und checked Exceptions.

Produktion

Darf ein Lambda ein Feld ändern?

Ja. Die Regel gilt nur für lokale Variablen. Bei Threads braucht das Feld dann Synchronisation.

Szenario: Ein Stack Trace zeigt nur lambda$process$7 und ist kaum lesbar. Was ändern Sie?

Lange Lambdas in benannte private Methoden auslagern und per Method Reference übergeben. Dann steht der Methodenname im Trace.

Szenario: Nach Stunden ist der Heap voll mit Objekten, die eigentlich weg sein sollten. Ein Heap Dump zeigt $$Lambda-Instanzen als Halter. Ursache?

Ein registrierter Listener-Lambda fängt this oder ein grosses Objekt und wird nie abgemeldet. Listener abmelden oder nur kleine Werte fangen.

Szenario: Ein Kollege zählt mit int[] counter in einem parallelen forEach und bekommt falsche Zahlen. Lösung?

Der Array-Trick ist nicht thread-sicher. Stattdessen count(), sum() oder reduce nutzen, also Reduktion statt Seiteneffekt.

Design

Was ist ein Functional Interface?

Ein Interface mit genau einer abstrakten Methode, z. B. Function, Predicate oder Runnable.

Nennen Sie die wichtigsten Interfaces aus java.util.function.

Function (apply), Consumer (accept), Supplier (get), Predicate (test), BiFunction, UnaryOperator, BinaryOperator, plus primitive Varianten wie IntPredicate.

Können Lambdas checked Exceptions werfen?

Nur wenn die Methode des Functional Interface sie deklariert, z. B. Callable. Standard-Interfaces wie Function tun das nicht.

Wie macht man ein Lambda serialisierbar?

Der Zieltyp muss Serializable sein, z. B. per Intersection-Cast. Davon wird abgeraten, weil die Form vom Compiler abhängt.

Echte Ausgabe, Oracle JDK 17.0.3 (java, javac, javap). Die Hex-Adresse der Hidden Class ist gekürzt. Der Mechanismus ist in Java 21 und 25 gleich; Klassennamen und Zähler sind Implementierungsdetails.

  1. Vier Arten Method References: unbound (String::length), bound (praefix::concat), Konstruktor (ArrayList::new), static (Math::max).
  2. Die Lambda-Klasse ist synthetisch und hidden. Auf der Platte gibt es nur LamDemo$1.class für die anonyme Klasse.
  3. this im Lambda ist das umgebende Objekt. In der anonymen Klasse ist this die anonyme Klasse selbst.
  4. Ohne Capture: dieselbe Instanz bei jedem Aufruf. Mit Capture: neue Objekte. Das ist aber ein Implementierungsdetail, keine Garantie der JLS.
  5. andThen: erst plus1, dann mal2: (5+1)·2 = 12. compose: erst mal2, dann plus1: 5·2+1 = 11.
  6. Der Array-Trick umgeht „effectively final": die Referenz bleibt gleich, der Inhalt ändert sich. Er ist nicht thread-sicher; besser sum() oder reduce.
  7. javac hat für jedes Lambda eine private Methode erzeugt. lambdaThis nutzt this und ist darum nicht static.
  8. String::length braucht keine eigene Methode. Der MethodHandle zeigt direkt auf String.length.
  9. Eine lokale Variable, die verändert wird (summe++, s = "b"), darf nicht im Lambda stehen.

Vergleich

  • Lambda: keine eigene Datei, this = umgebendes Objekt, nur Functional Interfaces, ohne eigenen Zustand.
  • Anonyme Klasse: eigene .class-Datei, eigenes this, kann Felder haben, kann abstrakte Klassen und Interfaces mit mehreren Methoden implementieren.
  • Method Reference: lesbarer, wenn nur eine Methode aufgerufen wird. Oft keine synthetische Methode nötig.
  • Benannte Klasse: besser bei viel Logik, Wiederverwendung oder Tests.
  • Lambda vs Schleife: Lambda für Callbacks und Streams; Schleife für Kontrollfluss mit break und checked Exceptions.

In der Produktion

  1. Unlesbare Stack Traces: Frames wie lambda$main$3 und $$Lambda$. Lösung: lange Lambdas in benannte Methoden auslagern und per Method Reference übergeben.
  2. Speicherleck durch gefangenes this: Ein Lambda, das ein Feld nutzt, hält das ganze Objekt. Als Listener registriert und nie entfernt, bleibt alles im Speicher. Lösung: Listener abmelden, nur nötige Werte in lokale Variablen kopieren.
  3. Race Conditions durch Array- oder Atomic-Trick: Zähler in Lambdas über mehrere Threads. Lösung: Reduktion statt Seiteneffekt.
  4. NPE an überraschender Stelle: bound Method Reference obj::m mit obj == null wirft schon beim Erzeugen. Ein Lambda x -> obj.m(x) erst beim Aufruf.
  5. Startzeit: Tausende Lambdas beim Start erzeugen viele Hidden Classes. Für schnellen Start helfen CDS und AOT-Caches; das zeigt die Seite „JIT-Compiler".
  6. Overload-Mehrdeutigkeit: submit(() -> x) passt zu Callable und Runnable. Bei void-Rumpf wählt javac Runnable, sonst Callable. Explizite Typen helfen.

Diagnose: Werkzeuge und Befehle

  • javap -c -p Klasse: zeigt invokedynamic und die lambda$…-Methoden.
  • javap -v Klasse: zeigt BootstrapMethods mit LambdaMetafactory und Ziel-Handle.
  • -Djdk.internal.lambda.dumpProxyClasses=<dir>: schreibt die erzeugten Lambda-Klassen als Datei (internes, nicht unterstütztes Property).
  • -Xlog:class+load: zeigt, wann Lambda-Klassen geladen werden.
  • Heap Dump: Lambda-Instanzen erscheinen als $$Lambda-Klassen; ihr Feld arg$1 zeigt gefangene Objekte.
  • IntelliJ: Debugger kann in Lambdas Breakpoints setzen („Lambda" im Breakpoint-Menü).

Senior-Punkte

  1. Kurze Lambdas, eine Zeile wenn möglich. Mehr Logik gehört in eine benannte Methode mit Method Reference.
  2. Keine Seiteneffekte in Lambdas für Streams. Das macht Code testbar und parallelisierbar.
  3. Standard-Interfaces bevorzugen. Ein eigenes Functional Interface nur, wenn der Name fachlich etwas sagt oder checked Exceptions nötig sind.
  4. Lambdas sind billig im Dauerbetrieb. Die Kosten liegen beim ersten Aufruf und beim Start.
  5. Gefangene Referenzen bewusst halten. Lange lebende Callbacks dürfen keine grossen Objekte festhalten.
