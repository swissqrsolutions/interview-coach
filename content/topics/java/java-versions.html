Java-Versionen 8 bis 25

Java · Tier 1 · Quellen: OpenJDK-Projektseiten JDK 8 bis 27 (Feature-Listen und GA-Daten), JEP 322 (Time-Based Release Versioning), einzelne JEPs wie genannt, Oracle Java SE Support Roadmap (Stand November 2026), Spring Boot System Requirements

Kern: Java erscheint seit Java 10 alle sechs Monate als Feature Release, im März und im September. Einige davon sind LTS-Releases (Long-Term Support) mit jahrelangen Updates: 8, 11, 17, 21, 25. Seit 17 kommt alle zwei Jahre ein LTS. Stand November 2026 ist Java 27 das neueste Release und Java 25 das aktuelle LTS.

1. Wo stehen die Versionen?

  1. LTS-Release: ein Release mit langen Updates von Oracle und anderen Anbietern. Beispiel: Java 25 hat bei Oracle Premier Support bis mindestens September 2030.
  2. Feature Release ohne LTS: erhält nur bis zum nächsten Release Updates. Beispiel: Java 26 bis September 2026.
  3. Preview-Feature: fertig spezifiziert, aber noch nicht final. Man braucht --enable-preview. Es kann sich noch ändern oder verschwinden.
  4. Incubator: eine frühe API in einem jdk.incubator.*-Modul. Beispiel: die Vector API, in Java 27 im zwölften Incubator.

2. Die Reise einer Anwendung von 8 nach 25 (die Geschichte zum Merken)

  1. Start Java 8: Die Anwendung nutzt Lambdas und Streams. Die PermGen ist durch Metaspace ersetzt (JEP 122).
  2. Sprung auf 11: Java 9 bringt das Modulsystem (JPMS) und macht G1 zum Standard-GC (JEP 248). Java 11 entfernt die Java-EE- und CORBA-Module (JEP 320). JAXB und JAX-WS muss man jetzt als Maven-Abhängigkeit holen.
  3. Sprung auf 17: JDK-Interna sind jetzt stark gekapselt (JEP 403). Reflection auf interne Klassen scheitert ohne --add-opens. Dafür gibt es Records, Sealed Classes, Text Blocks und Switch Expressions.
  4. Sprung auf 21: Virtual Threads, Pattern Matching für switch, Record Patterns und Sequenced Collections sind final. Bibliotheken mit Bytecode-Magie brauchen neue Versionen.
  5. Sprung auf 25: Seit 24 pinnt synchronized keine Virtual Threads mehr (JEP 491). Der Security Manager ist seit 24 dauerhaft aus (JEP 486). Java 25 bringt Scoped Values und AOT-Verbesserungen.

4. Details, die Interviewer fragen

  1. Java 8 (LTS): Lambdas und Streams (JEP 126, 107), java.time (JEP 150), Default-Methoden in Interfaces, Optional, CompletableFuture, Metaspace statt PermGen (JEP 122).
  2. Java 9: Modulsystem JPMS (JEP 261), JShell (JEP 222), List.of und Map.of (JEP 269), G1 als Standard (JEP 248), jlink (JEP 282).
  3. Java 10: var für lokale Variablen (JEP 286). Ab hier der 6-Monats-Rhythmus (JEP 322).
  4. Java 11 (LTS): HTTP Client (JEP 321), java Datei.java ohne javac (JEP 330), JFR Open Source (JEP 328), ZGC experimentell (JEP 333), var in Lambdas (JEP 323), neue String-Methoden (isBlank, strip, lines, repeat). Java EE und CORBA entfernt (JEP 320).
  5. Java 12–16: Switch Expressions (14), Helpful NPEs (14), CMS entfernt (14), Text Blocks (15), ZGC und Shenandoah produktiv (15), Biased Locking deaktiviert (15), Records (16), Pattern Matching für instanceof (16), Stream.toList() (16).
  6. Java 17 (LTS): Sealed Classes (JEP 409), starke Kapselung der JDK-Interna (JEP 403), Security Manager zur Entfernung markiert (JEP 411). Spring Boot 4.2 braucht mindestens Java 17.
  7. Java 18–20: UTF-8 als Standard-Zeichensatz (18, JEP 400), Simple Web Server jwebserver (18, JEP 408), Virtual Threads als Preview (19, 20).
  8. Java 21 (LTS): Virtual Threads (JEP 444), Sequenced Collections mit getFirst() und reversed() (JEP 431), Record Patterns (JEP 440), Pattern Matching für switch (JEP 441), Generational ZGC (JEP 439).
  9. Java 22–24: Foreign Function & Memory API final (22, JEP 454), unbenannte Variablen _ (22, JEP 456), Generational ZGC als Standard-Modus (23), Stream Gatherers (24, JEP 485), kein Pinning in synchronized (24, JEP 491), AOT Class Loading (24, JEP 483).
  10. Java 25 (LTS): Scoped Values (JEP 506), Module Import Declarations (JEP 511), Compact Source Files und Instance Main Methods (JEP 512), Flexible Constructor Bodies mit Code vor super(...) (JEP 513), Compact Object Headers als Produkt-Feature (JEP 519), AOT Method Profiling (JEP 515), Generational Shenandoah (JEP 521), drei JFR-Erweiterungen (JEP 509, 518, 520).
  11. Was in 25 noch Preview ist: Structured Concurrency (fünfte Preview), Primitive Types in Patterns, Stable Values. Die Vector API ist noch Incubator.
  12. Nach 25: Java 26 (März 2026) bringt HTTP/3 im HTTP Client (JEP 517) und entfernt die Applet API. Java 27 (September 2026) macht G1 überall zum Standard (JEP 523) und Compact Object Headers zum Standard (JEP 534).
  13. String Templates: Preview in Java 21 und 22. Ab Java 23 nicht mehr enthalten. Ein gutes Beispiel dafür, dass Preview-Features wieder verschwinden können.
  14. Lizenz: Oracle JDK 25 ist unter einer kostenlosen Lizenz (NFTC) für alle nutzbar. Updates für Oracle JDK 17 und 21 laufen inzwischen unter der OTN-Lizenz, also kostenlos nur für Entwicklung und Privates. Freie OpenJDK-Builds gibt es von mehreren Anbietern.

5. Vergleich

  • Java 8: funktionale Grundlagen. Noch in alten Systemen. Oracle Premier Support endete im März 2022.
  • Java 11: erste LTS nach dem Modulsystem. Wichtig: Java EE ist nicht mehr dabei.
  • Java 17: moderne Sprache (Records, Sealed, Text Blocks). Mindestversion für Spring Boot 4.2. Oracle Premier Support bis September 2026.
  • Java 21: Virtual Threads und Pattern Matching. Oracle Premier Support bis September 2028.
  • Java 25: aktuelles LTS. Virtual Threads ohne synchronized-Pinning, Scoped Values, AOT-Cache. Oracle Premier Support bis September 2030.
  • Java 26 und 27: Feature Releases ohne LTS. Gut für frühe Tests, in Produktion nur mit schnellem Upgrade-Prozess.

6. In der Produktion

  1. 8 → 11, ClassNotFoundException: javax.xml.bind…: JAXB ist nicht mehr im JDK. Lösung: Jakarta-XML-Binding als Abhängigkeit hinzufügen.
  2. 11 → 17, InaccessibleObjectException: Eine Bibliothek greift per Reflection auf JDK-Interna zu. Lösung: Bibliothek aktualisieren, notfalls gezielt --add-opens.
  3. Build bricht nach JDK-Wechsel: Alte Maven-Plugins, Lombok, Mockito oder ByteBuddy kennen das neue Klassenformat nicht. Lösung: zuerst Werkzeuge aktualisieren.
  4. Andere Lock-Leistung: Java 15 hat Biased Locking deaktiviert (JEP 374). Code mit vielen unbestrittenen synchronized-Aufrufen kann sich anders verhalten. Lösung: vor dem Wechsel Lasttest (Seite Synchronisation und Locks).
  5. Andere Standardwerte: Neuer Standard-GC (G1 seit 9), UTF-8 als Standard-Zeichensatz (18). Das ändert Verhalten ohne Code-Änderung. Lösung: Release Notes lesen, Last- und Regressionstests.
  6. Kein Support mehr: Ein Service läuft auf einem Release ohne Sicherheits-Updates. Lösung: geplanter LTS-Rhythmus, z. B. Upgrade innerhalb eines Jahres nach jedem LTS.

7. Diagnose: Werkzeuge und Befehle

  • java -version und java -XshowSettings:properties -version: Version und Einstellungen.
  • jdeps --jdk-internals app.jar: findet Zugriffe auf JDK-Interna vor der Migration.
  • jdeprscan: findet Nutzung veralteter APIs.
  • javac --release 17: kompiliert gegen die API von Java 17, auch mit neuerem JDK.
  • OpenRewrite-Rezepte: automatische Migration, z. B. javax → jakarta und Java-Upgrades.
  • jcmd <pid> VM.version und VM.flags: was in Produktion wirklich läuft.

8. Senior-Punkte

  1. Upgrades sind Routine, kein Projekt. Wer alle zwei Jahre auf das nächste LTS geht, hat kleine Schritte. Wer bei 8 bleibt, hat einen grossen, riskanten Sprung.
  2. Die Reihenfolge zählt: Erst Build-Werkzeuge und Bibliotheken, dann JDK, dann neue Sprach-Features. --release hält die Zielversion stabil.
  3. Java 25 lohnt sich konkret: Virtual Threads ohne synchronized-Pinning, Scoped Values final, schnellerer Start mit AOT-Cache.
  4. Preview nur mit Bedacht. String Templates zeigen: Previews können verschwinden. In Produktionscode nur, wenn das Team jedes Release mitgeht.
  5. Lizenz ist Architektur. Welche JDK-Distribution, welcher Support-Vertrag, wie lange Updates? Das gehört in die Plattform-Entscheidung.
  6. Framework gibt den Takt vor: Spring Boot und Jakarta EE setzen Mindest-Versionen. Ein JDK-Upgrade ist oft an ein Framework-Upgrade gekoppelt.

10. Fallen

  • „Jedes Java-Release ist LTS." → Falsch. Nur 8, 11, 17, 21, 25. Das nächste geplante ist 29 im September 2027.
  • „Java 21 ist das aktuelle LTS." → Veraltet. Seit September 2025 ist es Java 25.
  • „Records gibt es seit Java 17." → Ungenau. Final seit Java 16. Java 17 ist das erste LTS mit Records.
  • „Virtual Threads kamen mit Java 19." → Nur als Preview. Final seit Java 21.
  • „Structured Concurrency ist in Java 25 final." → Falsch. Fünfte Preview in 25. Final ist es erst für JDK 28 geplant.
  • „Oracle JDK ist immer kostenpflichtig." → Falsch. Oracle JDK 25 ist unter NFTC kostenlos nutzbar. Es kommt auf Version und Lizenz an.
  • „Ein Preview-Feature ist sicher für Produktion." → Falsch. Es kann sich ändern oder entfernt werden, wie String Templates.

11. Fragen

Wie oft erscheint ein neues Java-Release?

Alle sechs Monate, im März und im September. Das gilt seit Java 10.

Welche Versionen sind LTS?

8, 11, 17, 21 und 25. Seit 17 alle zwei Jahre, das nächste geplante ist 29 im September 2027.

Welche Java-Version ist heute aktuell?

Stand November 2026: Java 27 ist das neueste Release, Java 25 das aktuelle LTS.

Was ist ein Preview-Feature?

Ein fertig spezifiziertes, aber noch nicht finales Feature. Man aktiviert es mit --enable-preview. Es kann sich noch ändern.

Was waren die grossen Neuerungen in Java 8?

Lambdas, Streams, Default-Methoden, Optional, java.time, CompletableFuture und Metaspace statt PermGen.

Was brachte Java 9?

Das Modulsystem JPMS, JShell, List.of und Map.of, und G1 als Standard-GC.

Was ist neu in Java 11?

HTTP Client, Start von .java-Dateien ohne javac, JFR als Open Source, neue String-Methoden. Java EE und CORBA wurden entfernt.

Was bricht typischerweise beim Wechsel von 8 auf 11?

Fehlende Java-EE-APIs wie JAXB und JAX-WS sowie Zugriffe auf JDK-Interna. Dazu alte Build-Plugins.

Welche Sprach-Features kamen zwischen 11 und 17?

Switch Expressions, Text Blocks, Records, Pattern Matching für instanceof und Sealed Classes.

Was ist ein Record?

Eine unveränderliche Datenklasse. Konstruktor, Getter, equals, hashCode und toString entstehen automatisch. Final seit Java 16.

Was sind Sealed Classes?

Klassen oder Interfaces, die mit permits festlegen, wer sie erweitern darf. Final seit Java 17. Mit switch prüft der Compiler Vollständigkeit.

Was bricht beim Wechsel von 11 auf 17?

Starke Kapselung: Reflection auf JDK-Interna scheitert ohne --add-opens. Alte Bibliotheken müssen aktualisiert werden.

Was sind die wichtigsten Neuerungen in Java 21?

Virtual Threads, Pattern Matching für switch, Record Patterns, Sequenced Collections und Generational ZGC.

Was sind Sequenced Collections?

Neue Interfaces für Collections mit fester Reihenfolge. Sie bieten getFirst, getLast, addFirst und reversed. Seit Java 21.

Was ist neu in Java 25?

Scoped Values, Module Import Declarations, Compact Source Files mit void main(), Flexible Constructor Bodies, Compact Object Headers als Produkt-Feature und JFR-Erweiterungen.

Was kam zwischen 21 und 25, das für Produktion zählt?

Kein Pinning in synchronized (24), Stream Gatherers (24), FFM API final (22), AOT Class Loading (24), Security Manager dauerhaft aus (24).

Ist Structured Concurrency in Java 25 final?

Nein, fünfte Preview. Auch Java 26 und 27 haben es als Preview. Final ist es für JDK 28 geplant.

Was ist mit String Templates passiert?

Sie waren Preview in Java 21 und 22. Ab Java 23 sind sie nicht mehr enthalten.

Was macht javac --release?

Es kompiliert gegen die API und das Klassenformat einer älteren Version. So nutzt man ein neues JDK, ohne aus Versehen neue APIs zu verwenden.

Ist Oracle JDK kostenlos?

Oracle JDK 25 ja, unter der NFTC-Lizenz. Neue Updates für 17 und 21 laufen unter OTN, kostenlos nur für Entwicklung und Privatnutzung. OpenJDK-Builds sind frei.

Welche Java-Version braucht Spring Boot heute?

Spring Boot 4.2 braucht mindestens Java 17 und unterstützt bis Java 27.

Welche Java-Versionen haben Sie eingesetzt?

Java 11 bei CARIAD, Java 21 bei DAZiT. Vorbereitet bin ich auf die Neuerungen bis Java 25.

Szenario: Ein Service läuft noch auf Java 8. Wie planen Sie das Upgrade?

Erst jdeps und jdeprscan, dann Build-Werkzeuge und Bibliotheken aktualisieren. Dann direkt auf 21 oder 25, mit --release, Regressions- und Lasttests und einem Rollback-Plan.

Szenario: Nach dem Upgrade von 11 auf 17 startet die App mit InaccessibleObjectException. Was tun Sie?

Die Bibliothek finden, die per Reflection auf JDK-Interna zugreift, und aktualisieren. Nur als Übergang gezielt --add-opens setzen.

Szenario: Das Team will von 21 auf 25. Was ist Ihr Argument, und was prüfen Sie?

Argument: Virtual Threads ohne synchronized-Pinning, Scoped Values, AOT-Cache, Support bis 2030. Prüfen: Framework-Version, Agenten, Security-Manager-Nutzung, Lasttest mit JFR.
