Objekte und Gleichheit

Was ist der Unterschied zwischen == und equals()?

== vergleicht Referenzen, also ob es dasselbe Objekt im Speicher ist. equals() vergleicht Inhalte, wenn die Klasse es überschreibt. Für Objekte wie String immer equals() benutzen.

Warum muss man hashCode() überschreiben, wenn man equals() überschreibt?

Der Vertrag sagt: gleiche Objekte müssen den gleichen hashCode haben. Sonst findet eine HashMap das Objekt nicht wieder, weil sie zuerst über den hashCode den Bucket sucht.

Was steht im equals-Contract?

equals muss reflexiv, symmetrisch, transitiv und konsistent sein, und equals(null) gibt immer false. Verletzt man zum Beispiel die Symmetrie, verhalten sich Collections unvorhersehbar.

Warum ist String in Java immutable?

Strings sind unveränderlich, damit sie sicher geteilt, gecacht und als Map-Key benutzt werden können. Außerdem kann der hashCode einmal berechnet und gespeichert werden. Jede "Änderung" erzeugt ein neues Objekt.

Was ist der String Pool?

Der String Pool ist ein Cache im Heap für String-Literale: gleiche Literale zeigen auf dasselbe Objekt. Darum kann "a" == "a" true sein, aber new String("a") == "a" ist false.

Wie baut man eine immutable Klasse?

Klasse final, alle Felder private final, keine Setter, alles im Konstruktor setzen. Veränderliche Felder wie Listen beim Rein- und Rausgeben defensiv kopieren.

Was ist der Unterschied zwischen Interface und abstrakter Klasse?

Ein Interface beschreibt nur Fähigkeiten, eine Klasse kann viele implementieren. Eine abstrakte Klasse kann Zustand (Felder) und Konstruktoren haben, aber man kann nur von einer erben. Faustregel: Interface zuerst, abstrakte Klasse nur für gemeinsamen Zustand.

Was ist der Unterschied zwischen final, finally und finalize?

final macht Variablen unveränderbar und verbietet Vererbung oder Überschreiben. finally ist der Block, der nach try/catch immer läuft. finalize() war ein Hook vor der Garbage Collection und ist veraltet, stattdessen try-with-resources benutzen.

Collections

ArrayList oder LinkedList, was nimmst du und warum?

Fast immer ArrayList: Zugriff per Index ist O(1) und sie ist cache-freundlich. LinkedList hat O(n)-Zugriff und pro Element Overhead, sie lohnt sich fast nie.

Wie funktioniert eine HashMap intern?

Sie hat ein Array von Buckets; aus dem hashCode des Keys wird der Bucket-Index berechnet. Bei Kollisionen hängen mehrere Einträge als Liste im selben Bucket, und im Bucket entscheidet equals().

Was passiert bei vielen Kollisionen in einer HashMap?

Die Liste im Bucket wird länger und die Suche wird O(n). Wird eine Kette zu lang, wandelt die HashMap sie in einen Baum um, dann ist es O(log n).

Was passiert, wenn die HashMap voll wird?

Beim Überschreiten des Füllfaktors (Standard 0.75) verdoppelt sie das Bucket-Array und verteilt alle Einträge neu. Das kostet kurz Zeit, darum bei bekannter Größe die Kapazität im Konstruktor angeben.

Warum darf ein Map-Key nicht veränderbar sein?

Ändert sich der Key nach dem Einfügen, ändert sich sein hashCode, und die Map sucht im falschen Bucket. Der Eintrag ist dann praktisch verloren. Darum immutable Keys wie String benutzen.

Wann nimmst du TreeMap oder LinkedHashMap statt HashMap?

TreeMap, wenn die Keys sortiert sein müssen, dafür O(log n) statt O(1). LinkedHashMap, wenn die Einfüge-Reihenfolge beim Iterieren erhalten bleiben soll.

Exceptions, Generics, Autoboxing

Was ist der Unterschied zwischen Checked und Unchecked Exceptions?

Checked Exceptions muss der Compiler sehen: fangen oder mit throws deklarieren, zum Beispiel IOException. Unchecked (RuntimeException) muss man nicht deklarieren, sie stehen meist für Programmierfehler wie NullPointerException.

Wann würdest du eine eigene Checked Exception nicht benutzen?

Wenn der Aufrufer sowieso nichts Sinnvolles tun kann, zum Beispiel bei Konfigurations- oder Programmierfehlern. Dann ist eine RuntimeException besser, sonst zwingt man alle Schichten zu leeren catch-Blöcken.

Was macht try-with-resources?

Es schließt Ressourcen wie Streams oder Connections automatisch am Blockende, auch bei Exceptions. Die Ressource muss AutoCloseable implementieren. Das ersetzt das alte manuelle Schließen im finally.

Was ist Type Erasure bei Generics?

Generics existieren nur zur Compile-Zeit; zur Laufzeit ist aus List<String> nur noch List. Darum geht new T() nicht und List<String> und List<Integer> haben dieselbe Klasse.

Welche Falle gibt es beim Autoboxing von Integer?

Kleine Integer-Werte von -128 bis 127 werden gecacht, darum kann == dort zufällig true sein und bei 1000 false. Immer equals() vergleichen. Außerdem kann Unboxing von null eine NullPointerException werfen.

Streams, Optional, Lambdas

Was ist der Unterschied zwischen map und flatMap?

map wandelt jedes Element 1:1 um. flatMap wandelt jedes Element in einen Stream um und hängt alle aneinander, zum Beispiel aus List<List<String>> wird ein flacher Stream von Strings.

Sind Streams lazy? Was heißt das?

Ja: Zwischenoperationen wie filter oder map laufen erst, wenn eine Terminaloperation wie collect oder count kommt. Ohne Terminaloperation passiert gar nichts.

Wie benutzt man Optional richtig?

Optional ist für Rückgabewerte, die fehlen können, statt null. Auswerten mit map, orElse oder orElseThrow, nicht mit get() ohne Prüfung.

Wo sollte man Optional nicht benutzen?

Nicht als Feld, nicht als Methodenparameter und nicht in Collections. Dafür ist es nicht gedacht, es macht den Code nur umständlicher und ist nicht serialisierbar.

Was ist der Unterschied zwischen Lambda und anonymer Klasse?

Ein Lambda ist nur für Interfaces mit genau einer abstrakten Methode und erzeugt keine eigene Klasse pro Aufrufstelle. In einem Lambda zeigt this auf die umgebende Klasse, in der anonymen Klasse auf sich selbst.

Threads und Nebenläufigkeit

Was ist der Unterschied zwischen synchronized und volatile?

synchronized gibt gegenseitigen Ausschluss plus Sichtbarkeit: nur ein Thread im Block. volatile gibt nur Sichtbarkeit: alle Threads sehen den aktuellen Wert, aber x++ bleibt trotzdem unsicher, weil es aus drei Schritten besteht.

Wofür ist AtomicInteger gut?

Für atomare Zähler ohne Lock: incrementAndGet() ist ein einziger atomarer Schritt per Compare-and-Swap. Das ist bei einfachen Zählern schneller und einfacher als synchronized.

Warum benutzt man einen ExecutorService statt new Thread()?

Ein Thread-Pool wiederverwendet Threads und begrenzt ihre Anzahl, denn Threads sind teuer. Außerdem bekommt man Futures, geordnetes Herunterfahren und Warteschlangen geschenkt.

Was ist eine Race Condition, und wie vermeidest du sie?

Zwei Threads lesen und schreiben dieselben Daten gleichzeitig, und das Ergebnis hängt vom Timing ab, klassisch bei lesen-prüfen-schreiben. Lösung: atomare Operationen, Locks oder gleich unveränderliche Objekte.

Was sind Virtual Threads?

Sehr leichte Threads, die die JVM selbst verwaltet, fest im Standard seit Java 21: Tausende blockierende Aufrufe sind damit billig. Sie helfen bei wartendem I/O, nicht bei CPU-Arbeit. In frühen Versionen konnte synchronized den Träger-Thread festhalten (Pinning), das wurde in neueren Versionen verbessert.

JVM und modernes Java

Wie funktioniert Garbage Collection, ganz grob?

Der GC findet Objekte, die von keiner lebenden Referenz mehr erreichbar sind, und gibt ihren Speicher frei. Der Heap ist in Generationen geteilt, weil die meisten Objekte jung sterben: die Young Generation wird oft und billig geräumt, die Old Generation selten.

Was macht der JIT-Compiler?

Die JVM startet interpretiert und übersetzt heiß gelaufene Methoden zur Laufzeit in Maschinencode. Darum ist Java nach dem Warmup schnell, obwohl es mit Bytecode startet.

Was ist ein Record?

Ein Record ist eine kompakte, unveränderliche Datenklasse: record Point(int x, int y) erzeugt Konstruktor, Zugriffsmethoden, equals, hashCode und toString automatisch. Ideal für DTOs und Wertobjekte.

Wo liegen Objekte, wo lokale Variablen?

Objekte liegen im Heap, der von allen Threads geteilt wird. Lokale Variablen und Referenzen liegen im Stack des jeweiligen Threads. Klassen-Metadaten liegen im Metaspace.

Die 5 häufigsten Fangfragen

  • „Ist Java call-by-reference?" Nein, immer call-by-value: bei Objekten wird die Referenz als Wert kopiert. Man kann das Objekt ändern, aber nicht die Variable des Aufrufers umbiegen.
  • „Integer a=127, b=127; a==b? Und bei 128?" Bei 127 true (Integer-Cache von -128 bis 127), bei 128 false. Darum nie == bei Wrappern.
  • „Macht volatile ein count++ thread-sicher?" Nein: ++ ist lesen, rechnen, schreiben, also drei Schritte. Es braucht AtomicInteger oder synchronized.
  • „Garantiert finally, dass der Code immer läuft?" Fast: nicht bei System.exit(), JVM-Absturz oder Stromausfall. Und ein return im finally verschluckt Exceptions, nie machen.
  • „Kann man eine laufende ArrayList in einer for-each-Schleife verändern?" Nein, das wirft ConcurrentModificationException. Entweder über den Iterator entfernen oder removeIf() benutzen.
