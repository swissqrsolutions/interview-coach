HashSet, TreeSet, LinkedHashSet, Queue, Deque, PriorityQueue

Java · Tier 2 · Quellen: Java SE 25 API-Doku (Set, HashSet, LinkedHashSet, TreeSet, Queue, Deque, ArrayDeque, PriorityQueue, BlockingQueue, Stack, SequencedCollection), JEP 431 (Sequenced Collections, Java 21)

Kern: Ein Set ist eine Sammlung ohne Duplikate; es beantwortet schnell „Ist X schon drin?“. Eine Queue ist eine Warteschlange, die Elemente in einer festen Ordnung herausgibt: FIFO, LIFO oder nach Priorität. HashSet, LinkedHashSet und TreeSet sind intern Maps; ArrayDeque und PriorityQueue sind Arrays.

1. Wo sitzen Sets und Queues?

  1. HashSet: intern eine HashMap. Das Element ist der Schlüssel, der Wert ein festes Dummy-Objekt. Beispiel: Duplikate aus einer Liste entfernen.
  2. LinkedHashSet: intern eine LinkedHashMap. Ohne Duplikate, aber in Einfüge-Reihenfolge.
  3. TreeSet: intern eine TreeMap. Sortiert, mit Suchen wie floor und ceiling.
  4. Deque (double-ended queue): Einfügen und Entfernen an beiden Enden. ArrayDeque ist ein Ring-Array. Beispiel: Stack oder FIFO-Queue.
  5. PriorityQueue: ein Binary Heap in einem Array. Gibt immer das kleinste Element zuerst heraus.
  6. BlockingQueue: eine thread-sichere Queue, die bei leer oder voll warten kann. Beispiel: Producer-Consumer.

2. Die Reise eines Elements durch eine PriorityQueue (die Geschichte zum Merken)

  1. Das Array als Baum: Eine PriorityQueue speichert einen Binary Heap in einem Array. Das Element an Stelle i hat seine Kinder an 2i+1 und 2i+2.
  2. Heap-Regel: Jeder Eltern-Knoten ist kleiner oder gleich seinen Kindern. Darum steht das kleinste Element immer an Stelle 0.
  3. offer(0): Das neue Element kommt ans Ende des Arrays. Dann tauscht es nach oben, solange es kleiner als sein Eltern-Knoten ist (sift up). Kosten: O(log n).
  4. poll(): Die Wurzel geht raus. Das letzte Element springt an die Wurzel und tauscht nach unten (sift down). Kosten: O(log n).
  5. Nur die Spitze ist sortiert. Der Rest des Arrays ist nur „heap-geordnet“. Darum zeigt toString() keine sortierte Liste.

Echte Ausgabe, Oracle JDK 17.0.3. Zeiten bei 10) ändern sich pro Lauf. Die HashSet-Reihenfolge ist nicht garantiert.

  1. Das doppelte „Bern“ ist in allen drei Sets nur einmal da. Die Reihenfolge unterscheidet sich: keine, Einfügung, sortiert.
  2. add liefert false, wenn das Element schon drin ist. So erkennt man Duplikate ohne extra contains.
  3. TreeSet hat die gleichen Navigations-Methoden wie TreeMap. subSet(15, 35) ist unten inklusiv, oben exklusiv.
  4. Dieselbe ArrayDeque ist Stack (LIFO: zuletzt rein, zuerst raus) oder Queue (FIFO: zuerst rein, zuerst raus).
  5. ArrayDeque verbietet null. null ist dort das Signal für „leer“.
  6. Das Array der PriorityQueue ist nicht sortiert. Nur poll() liefert die sortierte Folge. Mit Comparator.reverseOrder() wird sie ein Max-Heap.
  7. Zwei Methoden-Familien: add/remove/element werfen Exceptions. offer/poll/peek liefern false oder null.
  8. Set.of wirft bei Duplikaten sofort eine IllegalArgumentException.
  9. Entfernen in einer for-each-Schleife wirft eine ConcurrentModificationException. removeIf ist sicher.
  10. contains auf einer Liste ist O(n), auf einem HashSet O(1). Hier: 1778 ms gegen 12 ms, inklusive Aufbau des Sets.

4. Details, die Interviewer fragen

  1. Wie erkennt ein Set Duplikate? HashSet und LinkedHashSet nutzen hashCode und equals. TreeSet nutzt nur compareTo oder den Comparator.
  2. Kosten: HashSet und LinkedHashSet: add, remove, contains im Mittel O(1). TreeSet: O(log n). LinkedHashSet braucht etwas mehr Speicher.
  3. null: HashSet und LinkedHashSet erlauben ein null. TreeSet mit natürlicher Ordnung nicht. ArrayDeque und PriorityQueue verbieten null.
  4. Queue-Methoden:
    • Einfügen: add (wirft) oder offer (liefert false).
    • Entfernen: remove (wirft) oder poll (liefert null).
    • Ansehen: element (wirft) oder peek (liefert null).
  5. Deque-Methoden: offerFirst/offerLast, pollFirst/pollLast, dazu push/pop für den Stack-Betrieb.
  6. ArrayDeque statt Stack und LinkedList: Die Klasse Stack ist alt, erbt von Vector und ist synchronisiert. Die API-Doku empfiehlt Deque. ArrayDeque ist als Queue meist schneller als LinkedList, weil sie keine Knoten-Objekte anlegt.
  7. PriorityQueue-Kosten: offer, poll: O(log n). peek: O(1). remove(Object) und contains: O(n). Der Iterator hat keine sortierte Reihenfolge.
  8. Gleiche Priorität: PriorityQueue ist nicht stabil. Gleich grosse Elemente kommen in beliebiger Reihenfolge. Lösung: Sequenznummer im Comparator.
  9. BlockingQueue: put wartet, wenn voll. take wartet, wenn leer. offer/poll mit Timeout warten begrenzt. Implementierungen: ArrayBlockingQueue (fest begrenzt), LinkedBlockingQueue (optional begrenzt, Standard Integer.MAX_VALUE), PriorityBlockingQueue, DelayQueue, SynchronousQueue (Kapazität 0).
  10. Unveränderliche Sets: Set.of und Set.copyOf verbieten null und haben keine feste Reihenfolge. Set.of wirft bei Duplikaten.
  11. SequencedCollection (Java 21): LinkedHashSet, TreeSet und Deque haben getFirst, getLast, reversed. Vorher brauchte man dafür Iteratoren.
  12. Vorgrösse: HashSet.newHashSet(n) (Java 19) reserviert Platz für n Elemente ohne Resize. new HashSet<>(n) setzt nur die Kapazität.

5. Vergleich

  • HashSet: schnellstes Set, keine Ordnung.
  • LinkedHashSet: Einfüge-Reihenfolge, fast so schnell. Gut für „Duplikate weg, Reihenfolge behalten“.
  • TreeSet: sortiert, O(log n), Bereichs-Suchen.
  • EnumSet: für Enums, intern ein Bit-Vektor. Sehr schnell und klein.
  • ArrayDeque: Stack und FIFO-Queue, nicht thread-sicher.
  • LinkedList als Queue: erlaubt null, braucht ein Objekt pro Element. Meist schlechter als ArrayDeque.
  • PriorityQueue: „gib mir immer das Kleinste“, z. B. Top-K, Scheduler, Dijkstra.
  • ConcurrentLinkedQueue / BlockingQueue: für mehrere Threads. Blocking, wenn Producer und Consumer aufeinander warten sollen.

6. In der Produktion

  1. contains() auf einer Liste in einer Schleife: O(n²) bei grossen Daten. Lösung: vorher ein HashSet bauen.
  2. Unbegrenzte Queue: Eine LinkedBlockingQueue ohne Grenze (auch in Executors.newFixedThreadPool) wächst bei Last bis zum OOM. Lösung: begrenzte Queue und eine klare Reaktion, wenn sie voll ist (Backpressure).
  3. Veränderte Elemente im Set: Ändert sich ein Feld, das hashCode oder compareTo nutzt, findet das Set das Element nicht mehr. Lösung: unveränderliche Elemente, z. B. Records.
  4. TreeSet verliert Elemente: Der Comparator liefert 0 für verschiedene Objekte. Lösung: eindeutiger Comparator mit thenComparing.
  5. PriorityQueue für Top-K: Alle Millionen Elemente einfügen ist unnötig. Lösung: Min-Heap der Grösse K, bei Überlauf poll(). Speicher O(K).
  6. Remove in Schleife: ConcurrentModificationException in der Produktion. Lösung: removeIf oder Iterator.remove().

7. Diagnose: Werkzeuge und Befehle

  • Profiler (async-profiler, JFR): viel Zeit in ArrayList.indexOf zeigt contains auf Listen.
  • jcmd <pid> GC.class_histogram: viele LinkedBlockingQueue$Node zeigen eine volle, unbegrenzte Queue.
  • Thread Dump: Consumer in LinkedBlockingQueue.take (WAITING) sind normal. Producer in put zeigen eine volle Queue.
  • Metriken: Queue-Grösse als Gauge exportieren (Micrometer), Alarm bei Wachstum.
  • EqualsVerifier im Unit-Test: prüft equals/hashCode der Set-Elemente.

8. Senior-Punkte

  1. Die Frage bestimmt die Struktur. „Ist X drin?“ → Set. „Was kommt als Nächstes?“ → Queue. „Was ist das Kleinste?“ → PriorityQueue.
  2. Jede Queue zwischen Threads braucht eine Grenze. Eine unbegrenzte Queue verschiebt das Problem nur bis zum OOM.
  3. ArrayDeque ist der Standard für Stack und Queue in einem Thread. Stack und LinkedList sind Altlasten.
  4. Set-Elemente müssen unveränderlich sein, mindestens in den Feldern für equals, hashCode und compareTo.
  5. In-Memory-Queues sind nicht dauerhaft. Bei einem Neustart sind die Elemente weg. Für wichtige Arbeit: Kafka, eine DB-Tabelle oder ein Message Broker.

„Bei MATCH ist die Arbeits-Queue bewusst keine In-Memory-Queue: Nachrichten stehen als Pending in MSSQL und werden atomar beansprucht. So geht bei einem Neustart nichts verloren.“ (Prüfen und durch dein echtes Beispiel ersetzen.)

10. Fallen

  • „Die PriorityQueue ist sortiert.“ → Falsch. Nur das erste Element ist das kleinste. Iterator und toString sind nicht sortiert.
  • „TreeSet nutzt equals für Duplikate.“ → Falsch. Es nutzt nur compareTo oder den Comparator.
  • „Für einen Stack nimmt man Stack.“ → Veraltet. ArrayDeque mit push/pop.
  • „poll() wirft bei leerer Queue.“ → Falsch. Es liefert null. remove() wirft.
  • „HashSet hat eine eigene Hash-Tabelle.“ → Falsch. Es ist eine HashMap mit Dummy-Werten.
  • „LinkedBlockingQueue ist begrenzt.“ → Nur, wenn man eine Kapazität angibt. Standard ist Integer.MAX_VALUE.

11. Fragen

Wie ist HashSet aufgebaut?

Intern eine HashMap. Das Element ist der Schlüssel, der Wert ein festes Dummy-Objekt.

HashSet vs LinkedHashSet vs TreeSet?

HashSet: keine Ordnung, O(1). LinkedHashSet: Einfüge-Reihenfolge, O(1). TreeSet: sortiert, O(log n).

Wie erkennt ein HashSet Duplikate?

Über hashCode für den Bucket und equals für den Vergleich. Fehlt ein korrektes hashCode, entstehen Duplikate.

Wie erkennt ein TreeSet Duplikate?

compareTo oder Comparator liefert 0. equals spielt keine Rolle.

Was liefert Set.add() zurück?

true, wenn das Element neu war. false, wenn es schon drin war.

Wie entfernen Sie Duplikate aus einer Liste und behalten die Reihenfolge?

new ArrayList<>(new LinkedHashSet<>(list)) oder stream().distinct().

Queue vs Deque?

Queue fügt hinten ein und nimmt vorne weg. Deque kann an beiden Enden einfügen und entfernen, also auch Stack sein.

offer vs add, poll vs remove?

offer und poll liefern false oder null. add und remove werfen eine Exception.

Warum ArrayDeque statt Stack?

Stack erbt von Vector und ist unnötig synchronisiert. ArrayDeque ist schneller, und die API-Doku empfiehlt Deque.

Warum ArrayDeque statt LinkedList als Queue?

ArrayDeque nutzt ein Ring-Array ohne Knoten-Objekte. Weniger Speicher, besserer Cache, weniger GC.

Warum verbietet ArrayDeque null?

poll und peek liefern null für „leer“. Ein null-Element wäre davon nicht unterscheidbar.

Wie funktioniert PriorityQueue?

Ein Binary Heap in einem Array. Das kleinste Element steht vorne. offer und poll kosten O(log n).

Wie bauen Sie einen Max-Heap?

new PriorityQueue<>(Comparator.reverseOrder()) oder ein eigener Comparator.

Ist die PriorityQueue bei gleicher Priorität FIFO?

Nein, sie ist nicht stabil. Für FIFO bei Gleichstand eine Sequenznummer in den Comparator nehmen.

Wie finden Sie die Top 10 aus einer Million Werte?

Min-Heap der Grösse 10. Jeden Wert einfügen, bei Grösse 11 das Kleinste entfernen. O(n log 10), Speicher O(10).

Was ist eine BlockingQueue?

Eine thread-sichere Queue. put wartet, wenn sie voll ist. take wartet, wenn sie leer ist. Basis für Producer-Consumer.

ArrayBlockingQueue vs LinkedBlockingQueue?

ArrayBlockingQueue ist fest begrenzt mit einem Lock. LinkedBlockingQueue ist optional begrenzt, Standard Integer.MAX_VALUE, mit getrennten Locks für put und take.

Was ist eine SynchronousQueue?

Eine Queue ohne Kapazität. Jedes put wartet auf ein take. CachedThreadPool nutzt sie.

Was ist EnumSet?

Ein Set für Enum-Werte als Bit-Vektor. Sehr schnell und kompakt, in Enum-Reihenfolge.

Was bringt SequencedCollection in Java 21?

getFirst, getLast, addFirst, addLast und reversed für geordnete Sammlungen wie LinkedHashSet, TreeSet, Deque und List.

Wie entfernen Sie Elemente sicher beim Iterieren?

Mit removeIf oder Iterator.remove(). Set.remove in einer for-each-Schleife wirft ConcurrentModificationException.

Szenario: Ein Import prüft für jede Zeile list.contains(id) und braucht Stunden. Was tun Sie?

contains auf einer Liste ist O(n), zusammen O(n²). Lösung: IDs vorher in ein HashSet laden. Dann O(1) pro Zeile.

Szenario: Ein Service mit Producer-Consumer-Queue stirbt nach Stunden mit OutOfMemoryError. Was prüfen Sie?

Ob die Queue unbegrenzt ist und der Consumer zu langsam. Heap-Histogramm zeigt viele Queue-Nodes. Lösung: Grenze setzen, Backpressure, Consumer skalieren, Queue-Grösse als Metrik.

Szenario: Ein Job-Scheduler mit PriorityQueue führt Jobs gleicher Priorität in falscher Reihenfolge aus. Warum?

PriorityQueue ist nicht stabil. Lösung: Comparator erst nach Priorität, dann nach Einfüge-Sequenz oder Zeitstempel.
