Apache Arrow und Arrow Flight SQL

Dremio · Tier 2 · Quellen: Apache Arrow Columnar Format Spec, Arrow Flight RPC Docs, Arrow Flight SQL Spec, ADBC Docs (arrow.apache.org; Arrow 26.0.1), Dremio 26.x Docs (Arrow Flight), Apache Spark 4.3 Docs (Arrow in PySpark)

Kern: Apache Arrow ist ein sprachunabhängiges Spaltenformat im Arbeitsspeicher. Es löst das Problem, dass jedes Tool Daten beim Austausch umwandeln (serialisieren) muss. Arrow Flight ist ein RPC-Protokoll auf gRPC, das Arrow-Batches direkt über das Netz streamt; Flight SQL legt darauf ein Protokoll für SQL-Abfragen, ähnlich wie JDBC, aber spaltenweise.

1. Wo sitzen Arrow und Flight?

  1. Parquet: das Format auf Disk, komprimiert und kodiert. Arrow ist das Format im Speicher.
  2. Engine: Dremio liest Parquet und rechnet intern auf Arrow-Puffern, spaltenweise und vektorisiert.
  3. Flight SQL Server: Er nimmt SQL per gRPC an und streamt das Ergebnis als Arrow-Batches.
  4. Client: Er bekommt Spalten im gleichen Layout. Es gibt keine Umwandlung Zeile für Zeile.
  5. DataFrame: pandas (mit Arrow-Typen) oder Polars können die Puffer oft ohne Kopie (zero-copy) nutzen.
  6. PySpark: nutzt Arrow beim Austausch JVM ↔ Python, z. B. bei toPandas() und Pandas UDFs.

2. Die Reise einer Flight-SQL-Abfrage

  1. Handshake: Der Client meldet sich an, z. B. mit Benutzer und Passwort oder Token. Er bekommt ein Bearer-Token für die nächsten Aufrufe.
  2. GetFlightInfo: Der Client schickt das SQL in einer CommandStatementQuery. Sie ist eine Protobuf-Nachricht im cmd-Feld des FlightDescriptor.
  3. FlightInfo: Der Server plant die Abfrage. Er antwortet mit dem Schema und einer Liste von Endpoints.
  4. Tickets: Jeder Endpoint hat ein Ticket und evtl. eine Adresse. Mehrere Endpoints erlauben paralleles Laden.
  5. DoGet: Der Client ruft für jedes Ticket DoGet auf.
  6. Stream: Der Server streamt RecordBatches, also Blöcke von Spalten.
  7. Tabelle: Der Client setzt die Batches zu einer Tabelle zusammen und zeigt sie an.

3. Beispiel: das Arrow-Layout von innen

# Modell des Arrow-Layouts mit der Standardbibliothek (pyarrow ist hier nicht installiert)
import struct, json
rows = [{"trade_id": "T-1", "volume": 50}, {"trade_id": "T-22", "volume": None},
        {"trade_id": "T-333", "volume": 40}]
# Spalte volume: int64 + Validity-Bitmap (1 Bit pro Zeile, LSB zuerst)
validity = sum(1 << i for i, r in enumerate(rows) if r["volume"] is not None)
values = struct.pack("<3q", *[r["volume"] or 0 for r in rows])
# Spalte trade_id: utf8 = Offsets (int32) + ein Datenpuffer
data = "".join(r["trade_id"] for r in rows).encode()
offsets, pos = [0], 0
for r in rows:
    pos += len(r["trade_id"].encode()); offsets.append(pos)
print("volume.validity =", format(validity, "08b"), "(Bit i = Zeile i gültig)")
print("volume.values   =", values.hex(" ", 8))
print("trade_id.offsets=", offsets)
print("trade_id.data   =", data)
print("trade_id Zeile 2 =", data[offsets[2]:offsets[3]].decode())
print("volume Zeile 1 gültig =", bool((validity >> 1) & 1))
print("Bytes Arrow-Puffer:", 1 + len(values) + 4*len(offsets) + len(data),
      "| Bytes als JSON:", len(json.dumps(rows).encode()))
volume.validity = 00000101 (Bit i = Zeile i gültig)
volume.values   = 3200000000000000 0000000000000000 2800000000000000
trade_id.offsets= [0, 3, 7, 12]
trade_id.data   = b'T-1T-22T-333'
trade_id Zeile 2 = T-333
volume Zeile 1 gültig = False
Bytes Arrow-Puffer: 53 | Bytes als JSON: 110

Echte Ausgabe, Python 3.12 (nur Standardbibliothek). Ein Modell des Layouts aus der Arrow-Spec, nicht pyarrow. Echtes Arrow richtet Puffer zusätzlich auf 8 bzw. 64 Bytes aus.

  1. Validity-Bitmap: Ein Bit pro Zeile sagt, ob der Wert gültig ist. Bit 1 ist 0: Zeile 1 ist null.
  2. Fester Typ: int64-Werte liegen dicht hintereinander, je 8 Bytes, Little Endian (32 hex = 50). Der Null-Platz ist trotzdem belegt.
  3. Strings: Ein Offsets-Puffer und ein Datenpuffer. Zeile 2 liegt zwischen Byte 7 und 12.
  4. Zugriff in O(1): Jede Zeile findet man direkt über Offset oder Index, ohne Parsen.
  5. Schon hier ist das Format halb so gross wie JSON, und es braucht beim Lesen keine Umwandlung.

Flight SQL aus Python (ADBC):

import adbc_driver_flightsql.dbapi as flightsql
with flightsql.connect("grpc+tls://dremio:32010",
        db_kwargs={"username": "reader", "password": "…"}) as conn:
    with conn.cursor() as cur:
        cur.execute("SELECT trade_date, SUM(volume_mwh) v FROM gold.daily GROUP BY trade_date")
        table = cur.fetch_arrow_table()     # pyarrow.Table, spaltenweise
print(table.schema, table.num_rows)

4. Details, die Interviewer fragen

  1. RecordBatch: ein Block mit gleich vielen Zeilen pro Spalte und einem Schema. Ströme bestehen aus vielen Batches.
  2. Arrow IPC: das Format, um Batches zu senden oder zu speichern (Stream- oder File-Format). Flight nutzt es im Netz.
  3. Flight-RPCs: GetFlightInfo, DoGet (lesen), DoPut (schreiben), DoExchange (beides), DoAction (Befehle), ListFlights, GetSchema.
  4. Flight SQL-Commands: CommandStatementQuery (SELECT), CommandStatementUpdate (DML), Prepared Statements per DoAction, Metadaten wie CommandGetTables, Bulk-Ingest per CommandStatementIngest.
  5. Paralleles Lesen: Mehrere Endpoints in FlightInfo erlauben, dass der Client Teile von mehreren Knoten gleichzeitig holt.
  6. Zero-Copy: Gleiche Puffer im Speicher können von mehreren Bibliotheken genutzt werden, ohne Kopie. Über das Netz gibt es eine Übertragung, aber kein Umwandeln.
  7. JDBC über Flight SQL: Es gibt einen Arrow-Flight-SQL-JDBC-Treiber. Er wandelt am Ende doch in Zeilen um; der Vorteil ist kleiner als mit nativen Arrow-Clients.
  8. ADBC (Arrow Database Connectivity): eine Client-API wie JDBC/ODBC, aber mit Arrow-Ergebnissen. Für Flight SQL, PostgreSQL, SQLite u. a.
  9. Arrow in PySpark: spark.sql.execution.arrow.pyspark.enabled beschleunigt toPandas() und createDataFrame(pandas_df). Pandas UDFs nutzen Arrow immer.
  10. Sicherheit: TLS (grpc+tls://), Auth per Basic oder Token, Header pro Aufruf. Ohne TLS gehen Passwörter im Klartext.

5. Vergleich

  • JDBC/ODBC: zeilenweise APIs, überall unterstützt. Bei grossen Ergebnissen viel Umwandlung und CPU.
  • Flight SQL: spaltenweise, streamend, parallel. Weniger Tool-Unterstützung als JDBC, aber stark für Python und Analyse-Apps.
  • REST + JSON: einfach zu nutzen und zu debuggen. Für grosse Daten langsam und gross.
  • Arrow vs Parquet: Arrow für Speicher und Transport, unkomprimiert und direkt adressierbar. Parquet für Disk, kompakt mit Kodierung und Kompression.

6. In der Produktion

  1. Verbindung scheitert mit TLS-Fehler: Ein Firmen-Proxy signiert TLS neu, das CA-Zertifikat fehlt. Lösung: Firmen-CA in den Client oder das Image einbauen.
  2. Client läuft in OOM: Er lädt das ganze Ergebnis mit fetch_arrow_table(). Lösung: Batches streamen, LIMIT und Paging, Aggregation auf dem Server.
  3. Load Balancer bricht gRPC-Streams ab: Er spricht nur HTTP/1.1 oder hat kurze Timeouts. Lösung: HTTP/2-fähiger Balancer, Timeouts erhöhen.
  4. Typ-Probleme: Decimal mit hoher Präzision oder Zeitzonen kommen im Client anders an. Lösung: Schema prüfen, Typen explizit casten.
  5. Token läuft ab: lange Sessions scheitern. Lösung: Token erneuern, Fehler behandeln.

7. Diagnose

  • gRPC-Logs: GRPC_VERBOSITY=DEBUG und GRPC_TRACE für Verbindungsprobleme.
  • Schema prüfen: GetSchema bzw. table.schema vor der Weiterverarbeitung.
  • Server-Seite: Job-Profil in Dremio: Planungszeit gegen Übertragungszeit.
  • Netz: openssl s_client -connect host:32010 zeigt die Zertifikatskette.

8. Senior-Punkte

  1. Arrow lohnt sich bei grossen Ergebnissen und spaltenweiser Weiterverarbeitung. Für zehn Zeilen ist JDBC genauso gut.
  2. Ein Format über Grenzen hinweg spart CPU in jedem Schritt: Engine, Netz, Client.
  3. Aggregieren auf dem Server. Flight macht Transport schnell, aber Millionen Zeilen im Browser bleiben falsch.
  4. ADBC statt JDBC in Python-Apps, wenn die Daten sowieso in DataFrames landen.
  5. gRPC braucht passende Infrastruktur: HTTP/2, Timeouts, TLS-Zertifikate.

10. Fallen

  • „Arrow ist ein Dateiformat wie Parquet.“ → Falsch. Arrow ist primär ein Format im Speicher. Parquet ist für Disk.
  • „Flight SQL ist ein Treiber von Dremio.“ → Falsch. Es ist ein offenes Protokoll des Arrow-Projekts.
  • „Zero-Copy heisst, über das Netz wird nichts kopiert.“ → Falsch. Bytes werden übertragen, aber nicht umgewandelt.
  • „Mit dem Flight-JDBC-Treiber bekomme ich den vollen Vorteil.“ → Nur teilweise, JDBC wandelt in Zeilen um.

11. Fragen

Was ist Apache Arrow?

Ein sprachunabhängiges Spaltenformat im Speicher. Tools können Daten austauschen, ohne sie umzuwandeln.

Wie ist eine Arrow-Spalte aufgebaut?

Eine Validity-Bitmap für null-Werte und Datenpuffer. Strings haben zusätzlich einen Offsets-Puffer.

Was ist ein RecordBatch?

Ein Block von Spalten mit gleicher Zeilenzahl und einem Schema. Streams bestehen aus vielen Batches.

Arrow vs Parquet?

Arrow ist für Speicher und Transport, unkomprimiert und direkt adressierbar. Parquet ist für Disk, kodiert und komprimiert.

Was ist Arrow Flight?

Ein RPC-Framework auf gRPC, das Arrow-Batches streamt. Methoden sind z. B. GetFlightInfo, DoGet, DoPut und DoAction.

Was ist Flight SQL?

Ein Protokoll auf Flight für SQL-Datenbanken. Es definiert Protobuf-Commands für Abfragen, Prepared Statements und Metadaten.

Wie läuft eine Abfrage mit Flight SQL?

GetFlightInfo mit CommandStatementQuery liefert Schema und Endpoints mit Tickets. Dann holt der Client die Daten mit DoGet pro Ticket.

Warum zwei Schritte?

So kann der Server das Ergebnis auf mehrere Endpoints verteilen. Der Client lädt dann parallel.

Was ist ADBC?

Eine Datenbank-API wie JDBC, aber mit Arrow-Ergebnissen. Sie spart die Umwandlung in Zeilen.

Warum ist Flight schneller als JDBC?

Keine Umwandlung Zeile für Zeile, spaltenweises Streaming und paralleles Laden über mehrere Endpoints.

Wie nutzt PySpark Arrow?

Beim Austausch zwischen JVM und Python, z. B. bei toPandas() und Pandas UDFs. Ohne Arrow werden Zeilen einzeln serialisiert.

Was heisst zero-copy?

Mehrere Bibliotheken nutzen dieselben Puffer im Speicher, ohne sie zu kopieren oder umzuwandeln.

Wie sichern Sie Flight ab?

TLS mit grpc+tls, Authentifizierung per Basic oder Token und Rechte in der Engine.

Wie schreibt man Daten per Flight SQL?

Mit DoPut: CommandStatementUpdate für DML oder CommandStatementIngest für Bulk-Ingest von Arrow-Batches.

Wann lohnt sich Flight nicht?

Bei kleinen Ergebnissen oder Tools, die nur JDBC/ODBC können. Dann bringt es wenig.

Szenario: Die WebUI wird bei grossen Charts langsam und frisst Speicher. Was tun Sie?

Auf dem Server aggregieren statt Rohdaten zu holen. Batches streamen statt alles in eine Tabelle zu laden.

Szenario: Die Flight-Verbindung scheitert nur im Firmennetz mit einem Zertifikatsfehler. Ursache?

Ein Proxy signiert TLS neu. Die Firmen-CA muss in den Trust Store des Clients oder des Images.

Szenario: Lange Abfragen brechen nach 60 Sekunden ab, kurze klappen. Woran denken Sie?

An einen Timeout im Load Balancer oder Ingress für gRPC-Streams. Timeouts und HTTP/2-Unterstützung prüfen.
