Listen, Dicts, Sets, Tuples: intern und Komplexität

Python · Tier 2 · Quellen: docs.python.org 3.15 (Tutorial: Data Structures; Library: Built-in Types, collections, sys.getsizeof; Glossary: hashable), What's New in Python 3.7 (dict-Reihenfolge), What's New in Python 3.15 (PEP 814 frozendict, PEP 798), CPython-Quellcode Objects/listobject.c, Objects/dictobject.c

Kern: Python hat vier eingebaute Sammlungen: list (dynamisches Array), tuple (unveränderliches Array), dict (Hash-Tabelle für Schlüssel-Wert) und set (Hash-Tabelle nur für Schlüssel). Die Wahl entscheidet über die Komplexität: x in list ist O(n), x in set im Durchschnitt O(1). Wer die interne Struktur kennt, kann jede Komplexitätsfrage selbst herleiten.

1. Wo sitzen die vier Strukturen?

  1. list: ein dynamisches Array von Zeigern auf Objekte. Index-Zugriff ist O(1). Beispiel: zeilen[42].
  2. tuple: ein Array fester Länge. Es ist unveränderlich und darum als Dict-Schlüssel nutzbar. Beispiel: (jahr, monat).
  3. dict: eine Hash-Tabelle mit open addressing, also ohne verkettete Listen. Seit Python 3.7 behält sie garantiert die Einfügereihenfolge.
  4. set: eine eigene Hash-Tabelle nur mit Schlüsseln. Sie hat keine garantierte Reihenfolge.
  5. Referenzen: Alle vier speichern nur Zeiger. Das Objekt [2, 3] in einem Tuple bleibt veränderbar.
  6. collections: ergänzt Spezialfälle, z. B. deque (Queue mit O(1) an beiden Enden).

2. Die Reise eines d["Bern"] = 1

  1. Hash berechnen: Python ruft hash("Bern") auf. Strings speichern ihren Hash nach dem ersten Aufruf.
  2. Slot finden: Die unteren Bits des Hash wählen einen Slot im Index-Array. Die Grösse ist immer eine Zweierpotenz.
  3. Kollision: Ist der Slot belegt, sucht Python nach einer festen Formel weiter (probing). Es gibt keine Ketten wie bei Java-HashMap.
  4. Vergleich: Gleicher Hash allein reicht nicht. Python prüft zuerst Identität (is), dann ==.
  5. Speichern: Der Eintrag kommt ans Ende des entries-Arrays. Der Slot im Index zeigt darauf. So bleibt die Einfügereihenfolge erhalten.
  6. Wachsen: Ist die Tabelle zu etwa zwei Dritteln voll, baut Python sie grösser neu auf. Das kostet einmal O(n), im Mittel bleibt put O(1).

3. Beispiel: die Strukturen messen

print(f"  x in list: {timeit.timeit(lambda: (n-1) in L, number=1000):.3f} s")
print(f"  x in set:  {timeit.timeit(lambda: (n-1) in S, number=1000):.6f} s")

print("6) list.pop(0) vs deque.popleft() (100000x)")
def drain_list():
    q = list(range(n))
    while q: q.pop(0)
def drain_deque():
    q = deque(range(n))
    while q: q.popleft()
print(f"  list.pop(0):     {timeit.timeit(drain_list, number=1):.3f} s")
print(f"  deque.popleft(): {timeit.timeit(drain_deque, number=1):.3f} s")

print("  ", grid)
grid = [[0] * 3 for _ in range(3)]
grid[0][0] = 9
print("  ", grid)

  1. Überallokation: Die Liste wächst nicht bei jedem append. Sie reserviert Platz für 4, dann 8, dann 16 Zeiger. Darum ist append amortisiert O(1).
  2. Reihenfolge: Das Dict gibt die Schlüssel in Einfügereihenfolge zurück. Das ist seit 3.7 eine Sprachgarantie.
  3. Gleiche Schlüssel: 1, 1.0 und True haben den gleichen Hash und sind gleich (==). Darum bleibt ein Eintrag: der erste Schlüssel 1 mit dem letzten Wert 'c'.
  4. Unhashable: Eine Liste kann nicht in ein Set. Sie ist veränderbar und hat keinen __hash__.
  5. Tuple-Falle: t[1] += [4] ändert zuerst die Liste (in place) und scheitert dann bei der Zuweisung ins Tuple. Fehler und Änderung passieren beide.
  6. Lookup: in auf einer Liste prüft jedes Element. Das Set springt direkt zum Slot. Hier über 6000× schneller.
  7. Queue: list.pop(0) verschiebt alle übrigen Zeiger, also O(n). deque.popleft() ist O(1). Hier über 100× schneller.
  8. Liste von Listen: [[0]*3]*3 kopiert drei Referenzen auf dieselbe innere Liste. Die Comprehension baut drei eigene Listen.

4. Details, die Interviewer fragen

  1. Komplexität list: Index, append, pop() am Ende: O(1) (append amortisiert). insert(0, x), pop(0), x in list, remove: O(n). sort: O(n log n).
  2. Komplexität dict/set: get, set, in, del: im Durchschnitt O(1). Schlimmster Fall O(n), wenn viele Schlüssel kollidieren.
  3. Hashable: Ein Objekt ist hashable, wenn sein Hash sich nie ändert und es __eq__ hat. Gleiche Objekte müssen den gleichen Hash haben. Eingebaute unveränderliche Typen sind hashable.
  4. __eq__ ohne __hash__: Wer nur __eq__ definiert, setzt __hash__ auf None. Das Objekt passt dann nicht mehr in Set oder Dict-Schlüssel.
  5. Kompaktes Dict: CPython trennt seit 3.6 Index-Array und entries-Array. Das spart Speicher und hält die Reihenfolge. Ab 3.7 ist die Reihenfolge Teil der Sprache.
  6. Set ist nicht geordnet: Die Ausgabe-Reihenfolge eines Sets kann sich zwischen Läufen ändern. Für Strings ist der Hash pro Prozess zufällig (Hash Randomization, PYTHONHASHSEED).
  7. Ändern beim Iterieren: Ein Dict oder Set beim Iterieren zu vergrössern wirft RuntimeError: dictionary changed size during iteration. Lösung: über list(d) iterieren.
  8. Kopien: a[:], list(a), copy.copy machen eine flache Kopie: neue äussere Liste, gleiche innere Objekte. copy.deepcopy kopiert alles rekursiv.
  9. tuple vs list Speicher: Ein Tuple hat keine Reserve und ist kleiner. Es ist auch etwas schneller zu erzeugen.
  10. Dict-Operatoren: d1 | d2 verbindet zwei Dicts (seit 3.9). Bei gleichen Schlüsseln gewinnt der rechte Wert.
  11. Neu in 3.15: frozendict (PEP 814) ist ein unveränderliches, hashbares Dict. Es ist keine Unterklasse von dict. Comprehensions erlauben jetzt * und ** (PEP 798), z. B. [*L for L in listen].
  12. Sortieren: list.sort() sortiert in place, sorted() liefert eine neue Liste. Beide sind stabil: Gleiche Elemente behalten ihre Reihenfolge.

5. Vergleich

  • list: geordnet, veränderbar, Duplikate erlaubt, Suche O(n). Für Folgen mit Index.
  • tuple: geordnet, unveränderlich, hashbar (wenn der Inhalt es ist). Für feste Datensätze und Dict-Schlüssel.
  • dict: Schlüssel eindeutig, Einfügereihenfolge, Suche O(1). Für Lookups über einen Schlüssel.
  • set / frozenset: eindeutig, ungeordnet, Suche O(1), Mengenoperationen (|, &, -). frozenset ist hashbar.
  • deque: O(1) an beiden Enden, Index in der Mitte O(n). Für Queues und Sliding Windows (maxlen).
  • Counter / defaultdict: Dict-Unterklassen zum Zählen und Gruppieren ohne if key not in d.
  • namedtuple / dataclass: namedtuple ist ein Tuple mit Feldnamen. @dataclass ist eine normale Klasse; mit frozen=True wird sie hashbar.
  • Python list vs Java ArrayList: beide dynamische Arrays mit amortisiertem O(1)-append. Python speichert immer Zeiger, auch für Zahlen.

6. In der Produktion

  1. Langsame Schleife durch in list: Ein Abgleich „ist ID schon bekannt?“ gegen eine Liste wird bei Millionen Zeilen O(n²). Lösung: einmal set(ids), dann O(1).
  2. Queue mit pop(0): Eine Arbeitsliste wird mit wachsender Länge immer langsamer. Lösung: collections.deque.
  3. Speicher: Eine Liste von Millionen Python-ints braucht pro Zahl ein Objekt plus einen Zeiger. Lösung: array-Modul, NumPy oder gleich Spark/pandas mit Spalten.
  4. Veränderbarer Default: def f(x, acc=[]) teilt eine Liste über alle Aufrufe. Lösung: acc=None und in der Funktion neu anlegen.
  5. Unerwartete Duplikate entfernt: 1 und True oder 1 und 1.0 landen im gleichen Schlüssel. Lösung: Typen vor dem Gruppieren normalisieren.
  6. Nicht reproduzierbare Ausgabe: Code, der über ein Set iteriert, liefert je Lauf eine andere Reihenfolge. Tests werden flaky. Lösung: sorted(s) vor der Ausgabe.

7. Diagnose

  • sys.getsizeof(x): flache Grösse eines Containers in Bytes, ohne die Elemente.
  • tracemalloc: findet, welche Zeile den meisten Speicher alloziert.
  • timeit / python -m timeit: misst kleine Code-Stücke, z. B. in list gegen in set.
  • cProfile (ab 3.15 auch profiling.tracing) und der neue Sampling-Profiler profiling.sampling in 3.15: zeigen, wo die Zeit hingeht.
  • id(a) == id(b) oder a is b: prüft, ob zwei Namen dasselbe Objekt meinen, z. B. bei der [[0]*3]*3-Falle.

8. Senior-Punkte

  1. Die Struktur folgt der Hauptoperation: viel Suche → set/dict, viel Index → list, beide Enden → deque.
  2. O(1) bei dict und set ist ein Durchschnitt. Er hängt von einem guten __hash__ ab.
  3. Unveränderlich ist sicherer: tuple, frozenset, frozendict und frozen-Dataclasses können nicht versehentlich geteilt verändert werden.
  4. Grosse Daten gehören nicht in Python-Listen. Spaltenformate (NumPy, pandas, Arrow, Spark) sparen Speicher und Zeit.
  5. Reihenfolge nur garantieren, wo sie dokumentiert ist: dict ja, set nein. Tests dürfen sich nicht auf Set-Reihenfolge verlassen.

10. Fallen

  • „Ein Set behält die Einfügereihenfolge wie ein Dict.“ → Falsch. Nur dict garantiert die Reihenfolge.
  • „Ein Tuple ist komplett unveränderlich.“ → Falsch. Nur die Zeiger sind fest. Eine Liste darin bleibt veränderbar.
  • „Jedes Tuple ist hashable.“ → Falsch. hash((1, [2])) wirft TypeError.
  • „list.pop(0) ist O(1).“ → Falsch. O(n); dafür deque.popleft().
  • „[[0]*3]*3 erzeugt drei Zeilen.“ → Falsch. Drei Referenzen auf dieselbe Zeile.
  • „{1: 'a', True: 'b'} hat zwei Einträge.“ → Falsch. 1 == True und gleicher Hash, also ein Eintrag.
  • „frozendict ist ein dict.“ → Falsch. Es erbt nicht von dict; isinstance(x, dict) ist False.

11. Fragen

Wie ist eine Python-Liste intern aufgebaut?

Als dynamisches Array von Zeigern auf Objekte. Sie reserviert Platz am Ende, darum ist append amortisiert O(1).

Warum ist append amortisiert O(1)?

Die Liste wächst in Stufen mit Reserve. Das teure Umkopieren passiert selten und verteilt sich auf viele append.

Welche Listen-Operationen sind O(n)?

insert(0, x), pop(0), remove, x in list, index und Slicing-Kopien.

Wie ist ein dict intern aufgebaut?

Eine Hash-Tabelle mit open addressing. CPython trennt ein kleines Index-Array von einem dichten entries-Array.

Seit wann ist die dict-Reihenfolge garantiert?

Seit Python 3.7 als Sprachgarantie. In CPython 3.6 war sie ein Implementierungsdetail.

Hat ein set eine Reihenfolge?

Nein. Die Reihenfolge ist nicht garantiert und kann sich zwischen Läufen ändern.

Was heisst hashable?

Der Hash ändert sich nie, und das Objekt ist mit == vergleichbar. Gleiche Objekte haben den gleichen Hash.

Warum kann eine Liste kein Dict-Schlüssel sein?

Sie ist veränderbar. Ihr Hash würde sich ändern, und der Eintrag wäre nicht mehr auffindbar.

Was passiert, wenn ich nur __eq__ definiere?

Python setzt __hash__ auf None. Die Objekte passen nicht mehr in set oder als dict-Schlüssel.

Wie löst dict Kollisionen?

Mit open addressing: Python probiert nach einer festen Formel andere Slots. Es gibt keine Ketten.

Wann wächst ein dict?

Wenn es etwa zu zwei Dritteln voll ist. Dann baut CPython eine grössere Tabelle und trägt alles neu ein.

Was ist der Unterschied zwischen list und tuple?

tuple ist unveränderlich, hat feste Grösse, braucht weniger Speicher und ist hashbar, wenn der Inhalt es ist.

Ist ein Tuple immer hashbar?

Nein. Nur wenn alle Elemente hashbar sind. (1, [2]) wirft TypeError.

Warum gibt {1: 'a', True: 'b'} nur einen Eintrag?

1 == True und hash(1) == hash(True). Der Schlüssel 1 bleibt, der Wert wird 'b'.

Wann nehmen Sie deque statt list?

Für Queues und Arbeit an beiden Enden. append und popleft sind O(1), pop(0) auf list ist O(n).

Was machen Counter und defaultdict?

Counter zählt Elemente und hat most_common. defaultdict erzeugt fehlende Werte über eine Factory, z. B. list.

Flache vs tiefe Kopie?

Die flache Kopie teilt die inneren Objekte. copy.deepcopy kopiert alles rekursiv.

Warum ist [[0]*3]*3 gefährlich?

Alle drei Zeilen sind dieselbe Liste. Eine Änderung erscheint in jeder Zeile. Besser: eine Comprehension.

Was passiert, wenn ich ein dict beim Iterieren vergrössere?

RuntimeError: dictionary changed size during iteration. Lösung: über list(d) iterieren oder ein neues dict bauen.

Was ist frozendict?

Ein unveränderliches, hashbares Mapping, neu in Python 3.15 (PEP 814). Es ist keine Unterklasse von dict.

sort() vs sorted()?

sort() sortiert die Liste in place und gibt None zurück. sorted() nimmt jedes Iterable und liefert eine neue Liste. Beide sind stabil.

Wie verbinden Sie zwei Dicts?

Mit d1 | d2 seit Python 3.9 oder {**d1, **d2}. Bei gleichen Schlüsseln gewinnt rechts.

Warum ist die Set-Reihenfolge von Strings je Lauf anders?

Hash Randomization: Der String-Hash nutzt einen zufälligen Seed pro Prozess. Steuerbar über PYTHONHASHSEED.

Szenario: Ein Abgleich von 2 Mio. IDs dauert Stunden. Was prüfen Sie?

Ob in der Schleife x in list steht. Das ist O(n) pro Prüfung, gesamt O(n²). Ein set macht es O(n) gesamt.

Szenario: Ein Unit-Test schlägt nur manchmal fehl, weil die Reihenfolge der Ausgabe wechselt. Warum?

Der Code iteriert über ein set. Die Reihenfolge ist nicht garantiert. Lösung: sorted() vor der Ausgabe oder im Test Mengen vergleichen.

Szenario: Eine Funktion liefert beim zweiten Aufruf alte Werte mit. Woran denken Sie?

An einen veränderbaren Default wie acc=[]. Er wird nur einmal erzeugt und über Aufrufe geteilt. Lösung: acc=None.
