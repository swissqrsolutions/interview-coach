Heap und PriorityQueue

DSA · Tier 1 · Quellen: Java SE 25 API-Doku java.util.PriorityQueue, java.util.Collections.reverseOrder, java.util.Comparator, CLRS 4. Auflage (2022): Kap. 6 „Heapsort“ (Binary Heap, Priority Queues)

Kern: Ein Heap ist ein Binärbaum, in dem jeder Elternknoten kleiner oder gleich seinen Kindern ist (Min-Heap). So liegt das kleinste Element immer oben: peek in O(1), offer und poll in O(log n). In Java ist das die PriorityQueue, standardmässig ein Min-Heap.

1. Wo sitzt der Heap?

  1. Heap-Eigenschaft: Jeder Elternknoten ist ≤ seinen Kindern. Mehr Ordnung gibt es nicht. Geschwister sind ungeordnet.
  2. Vollständiger Baum: Der Baum ist Ebene für Ebene von links gefüllt. Darum passt er lückenlos in ein Array.
  3. Array-Indizes: Kinder von i liegen bei 2i + 1 und 2i + 2. Kein Zeiger nötig.
  4. offer: hinten anhängen, dann nach oben tauschen (sift up). O(log n).
  5. poll: Wurzel nehmen, letztes Element nach oben, dann nach unten tauschen (sift down). O(log n).
  6. PriorityQueue: Java-Klasse dafür. Kopf ist das kleinste Element laut Comparator. Bei Gleichstand ist offen, welches kommt.

2. Die Reise eines Median-Streams (die Geschichte zum Merken)

  1. Zwei Hälften: low hält die kleinere Hälfte als Max-Heap, high die grössere als Min-Heap.
  2. Einfügen: Jede Zahl geht zuerst in low. Dann wandert das grösste Element von low nach high. So ist jedes Element in low ≤ jedes in high.
  3. Ausgleichen: Hat high mehr Elemente als low, wandert das kleinste von high zurück.
  4. Median lesen: Bei ungerader Anzahl ist es die Spitze von low. Bei gerader das Mittel der beiden Spitzen.
  5. Kosten: Pro Zahl höchstens drei Heap-Operationen: O(log n). Der Median selbst O(1).

3. Beispiel: vier Klassiker in Java

Erkennen: „k grösste / kleinste / häufigste“, „k-tes Element“, „merge k sortierte …“, „Median eines Streams“, „immer das nächste nach Priorität“, „Scheduler“, Dijkstra.

Template (Top-k mit Min-Heap der Grösse k):

PriorityQueue<Integer> minHeap = new PriorityQueue<>();          // Min-Heap
PriorityQueue<Integer> maxHeap = new PriorityQueue<>(Collections.reverseOrder());
for (int x : nums) {
    minHeap.offer(x);
    if (minHeap.size() > k) minHeap.poll();       // kleinstes fliegt raus
}
// minHeap enthält jetzt die k grössten, peek() ist das k-grösste

1. Kth Largest Element – O(n log k) Zeit, O(k) Speicher:

static int findKthLargest(int[] nums, int k) {
    PriorityQueue<Integer> minHeap = new PriorityQueue<>();
    for (int x : nums) {
        minHeap.offer(x);
        if (minHeap.size() > k) minHeap.poll();
    }
    return minHeap.peek();
}

2. Top K Frequent Elements – O(n log k):

static List<Integer> topKFrequent(int[] nums, int k) {
    Map<Integer, Integer> freq = new HashMap<>();
    for (int x : nums) freq.merge(x, 1, Integer::sum);
    PriorityQueue<Map.Entry<Integer, Integer>> heap =
        new PriorityQueue<>((a, b) -> Integer.compare(a.getValue(), b.getValue()));
    for (Map.Entry<Integer, Integer> e : freq.entrySet()) {
        heap.offer(e);
        if (heap.size() > k) heap.poll();
    }
    List<Integer> res = new ArrayList<>();
    while (!heap.isEmpty()) res.add(heap.poll().getKey());
    Collections.reverse(res);                     // häufigstes zuerst
    return res;
}

3. Merge k Sorted Lists – O(N log k), N = alle Knoten:

static class ListNode { int val; ListNode next; ListNode(int v) { val = v; } }

static ListNode mergeKLists(ListNode[] lists) {
    PriorityQueue<ListNode> heap = new PriorityQueue<>(Comparator.comparingInt(n -> n.val));
    for (ListNode n : lists) if (n != null) heap.offer(n);   // null-Listen überspringen
    ListNode dummy = new ListNode(0), tail = dummy;
    while (!heap.isEmpty()) {
        ListNode n = heap.poll();
        tail.next = n; tail = n;
        if (n.next != null) heap.offer(n.next);              // Nachfolger nachschieben
    }
    return dummy.next;
}

4. Find Median from Data Stream – addNum O(log n), findMedian O(1):

static class MedianFinder {
    private final PriorityQueue<Integer> low = new PriorityQueue<>(Collections.reverseOrder()); // Max-Heap
    private final PriorityQueue<Integer> high = new PriorityQueue<>();                          // Min-Heap
    void addNum(int x) {
        low.offer(x);
        high.offer(low.poll());                               // grösstes der unteren Hälfte nach oben
        if (high.size() > low.size()) low.offer(high.poll()); // low darf 1 mehr haben
    }
    double findMedian() {
        return low.size() > high.size() ? low.peek() : (low.peek() + (long) high.peek()) / 2.0;
    }
}

Echte Ausgabe, Oracle JDK 17.0.3.

  1. Kth Largest mit Duplikaten: Das 4-grösste in [3,2,3,1,2,4,5,5,6] ist 4. Duplikate zählen einzeln.
  2. Merge k: Eine leere Liste (null) wird übersprungen. Ohne die null-Prüfung käme eine NullPointerException.
  3. Median: Nach 5 und 15 ist es 10.0. Die long-Addition schützt vor Overflow bei grossen Werten.
  4. toString zeigt [1, 2, 8, 3, 5, 9]: die Array-Reihenfolge des Heaps. Nur poll() liefert sortiert.
  5. Der Comparator (a, b) -> b - a läuft über: 1 - Integer.MIN_VALUE wird negativ. Der „Max-Heap“ zeigt dann das Minimum. Collections.reverseOrder() ist korrekt.

4. Details, die Interviewer fragen

  1. Min-Heap für die k grössten: Klingt verkehrt, ist richtig. Der Min-Heap der Grösse k wirft immer das kleinste raus. Übrig bleiben die k grössten. Speicher O(k) statt O(n).
  2. Max-Heap in Java: new PriorityQueue<>(Collections.reverseOrder()) oder Comparator.reverseOrder(). Nie (a, b) -> b - a bei beliebigen int.
  3. Kosten laut Doku: offer, poll, remove(), add O(log n). peek, element, size O(1). remove(Object) und contains O(n).
  4. Heap bauen: Den Heap aus n Elementen auf einmal bauen geht in O(n) (CLRS Kap. 6, BUILD-MAX-HEAP). n-mal offer ist O(n log n).
  5. Iteration ist unsortiert: Laut Doku garantiert der Iterator keine Reihenfolge. Für sortierte Ausgabe: poll in einer Schleife.
  6. Alternative für Kth Largest: Quickselect mit O(n) im Durchschnitt, O(n²) im schlechtesten Fall. Der Heap ist stabiler und streamfähig.
  7. Alternative für Top-K Frequent: Bucket Sort nach Häufigkeit in O(n), weil eine Häufigkeit höchstens n ist.
  8. Comparator für Objekte: Comparator.comparingInt(n -> n.val). Bei Gleichstand einen zweiten Schlüssel mit thenComparing, falls die Reihenfolge zählt.
  9. Randfälle: k = n, k = 1, Duplikate, leere Listen, null-Listen, negative Zahlen, Overflow bei Summen.
  10. So sprichst du beim Coden: „Ich brauche immer das kleinste der aktuellen Köpfe. Das ist eine PriorityQueue mit k Einträgen. Jeder der N Knoten geht einmal rein und raus: O(N log k). Speicher O(k).“

5. Vergleich

  • PriorityQueue (Binary Heap): Minimum in O(1), Einfügen und Entfernen O(log n), keine Suche.
  • TreeSet / TreeMap: sortiert, Min und Max je O(log n), auch Suche und Löschen beliebiger Elemente O(log n). Keine Duplikate im TreeSet.
  • Sortieren: O(n log n) einmalig. Gut, wenn alle Daten vorher da sind und sich nicht ändern.
  • Quickselect: k-tes Element in O(n) im Durchschnitt, verändert das Array.
  • PriorityBlockingQueue: thread-sichere Variante für mehrere Threads.

6. In der Produktion

  1. Scheduler und Timer: Aufgaben nach Ausführungszeit sortiert halten. ScheduledThreadPoolExecutor nutzt intern eine Warteschlange nach Zeit.
  2. Top-k in Streams: „die 10 langsamsten Requests“ mit einem Min-Heap der Grösse 10. Speicher O(k), egal wie viele Requests.
  3. Merge sortierter Dateien: Externes Sortieren grosser Daten: viele sortierte Teile, ein Heap über die Köpfe.
  4. Falscher Comparator: Subtraktion im Comparator liefert bei grossen Werten falsche Reihenfolge, ohne Fehler. Immer Integer.compare.

7. Diagnose

  • Nicht toString vertrauen: Zum Prüfen die Queue kopieren und per poll ausgeben.
  • Grössen-Invariante prüfen: Beim Median gilt immer low.size() == high.size() oder low.size() == high.size() + 1.
  • Testfälle: Duplikate, negative Zahlen, Integer.MIN_VALUE/MAX_VALUE, k = 1, k = n.

8. Senior-Punkte

  1. O(n log k) statt O(n log n): Der Heap der Grösse k ist besser als Sortieren, wenn k klein ist, und funktioniert auf Streams.
  2. Comparator sicher schreiben: Integer.compare, Comparator.comparingInt, reverseOrder. Subtraktion ist ein klassischer Bug.
  3. Die Grenzen der PriorityQueue kennen: keine schnelle Suche, kein schnelles Ändern einer Priorität. Bei Dijkstra fügt man darum neu ein und ignoriert veraltete Einträge.
  4. Alternativen nennen: Quickselect, Bucket Sort, TreeMap. Das zeigt Überblick.

10. Fallen

  • „PriorityQueue ist ein Max-Heap.“ → Falsch. Standard ist Min-Heap: Kopf ist das kleinste Element.
  • „Für die k grössten nehme ich einen Max-Heap mit allen Elementen.“ → Geht, aber O(n) Speicher. Min-Heap der Grösse k ist O(k).
  • „System.out.println(pq) zeigt die sortierte Reihenfolge.“ → Falsch. Es zeigt die Array-Reihenfolge.
  • „(a, b) -> b - a ist ein sicherer Max-Heap.“ → Falsch. Overflow bei grossen Werten.
  • „pq.contains(x) ist O(log n).“ → Falsch. O(n), der Heap ist nicht durchsuchbar.
  • „Einen Heap zu bauen kostet immer O(n log n).“ → Nicht ganz. Bottom-up-Aufbau ist O(n).

11. Fragen

Was ist ein Heap?

Ein vollständiger Binärbaum, in dem jeder Elternknoten ≤ seinen Kindern ist (Min-Heap). Er liegt als Array im Speicher.

Ist Javas PriorityQueue ein Min- oder Max-Heap?

Ein Min-Heap. Der Kopf ist das kleinste Element laut natürlicher Ordnung oder Comparator.

Wie baust du einen Max-Heap in Java?

new PriorityQueue<>(Collections.reverseOrder()) oder mit Comparator.reverseOrder().

Welche Komplexität haben offer, poll und peek?

offer und poll O(log n), peek O(1).

Was kostet contains auf einer PriorityQueue?

O(n). Der Heap ist nur teilweise geordnet und nicht durchsuchbar.

Wo liegen die Kinder von Index i im Array?

Bei 2i + 1 und 2i + 2. Der Elternknoten liegt bei (i − 1) / 2.

Wie findest du das k-grösste Element?

Min-Heap der Grösse k. Bei Überlauf das kleinste entfernen. Am Ende ist peek das k-grösste. O(n log k).

Warum ein Min-Heap für die k grössten?

Er wirft immer das kleinste der aktuellen Kandidaten raus. So bleiben die k grössten bei nur O(k) Speicher.

Wie findest du die k häufigsten Elemente?

Erst eine Frequenz-Map, dann ein Min-Heap der Grösse k nach Häufigkeit. Oder Bucket Sort in O(n).

Wie mergst du k sortierte Listen?

Die Köpfe aller Listen in einen Min-Heap. Immer das kleinste nehmen und seinen Nachfolger einfügen. O(N log k).

Wie findest du den Median eines Streams?

Max-Heap für die untere, Min-Heap für die obere Hälfte, Grössen ausgeglichen. Median aus den Spitzen.

Warum zeigt toString die Elemente unsortiert?

Es gibt das interne Array aus. Der Iterator garantiert laut Doku keine Reihenfolge.

Warum ist (a, b) -> b - a gefährlich?

Die Subtraktion kann überlaufen und das Vorzeichen drehen. Dann stimmt die Ordnung nicht mehr.

Was kostet es, einen Heap aus n Elementen zu bauen?

Bottom-up O(n). n-mal einzeln einfügen O(n log n).

Heap oder TreeMap?

Heap für „immer das kleinste“, schnell und einfach. TreeMap, wenn man auch suchen, löschen oder Min und Max zugleich braucht.

Was ist Quickselect?

Partitionieren wie Quicksort, aber nur in einer Hälfte weiter. k-tes Element in O(n) im Durchschnitt, O(n²) im schlechtesten Fall.

Szenario: Du sollst aus einem endlosen Log-Stream die 10 langsamsten Requests halten. Wie?

Ein Min-Heap der Grösse 10 nach Dauer. Neuer Request rein, bei Grösse 11 das kleinste raus. O(log 10) pro Request, O(10) Speicher.

Szenario: Dein Max-Heap liefert bei grossen Werten das Minimum zuerst. Was ist falsch?

Der Comparator rechnet b − a und läuft über. Fix: Collections.reverseOrder() oder Integer.compare(b, a).

Szenario: Der Interviewer fragt, ob Merge k Sorted Lists auch ohne Heap geht. Was sagst du?

Ja, mit Divide and Conquer: Listen paarweise mergen, auch O(N log k). Nacheinander mergen wäre O(N · k).
