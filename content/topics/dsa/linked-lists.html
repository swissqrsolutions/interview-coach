Linked Lists

Kern: Eine Linked List ist eine Kette von Nodes. Jeder Node hält einen Wert und einen Zeiger auf den nächsten. Einfügen und Löschen an einer bekannten Stelle kostet O(1), der Zugriff per Index kostet O(n). Die meisten Aufgaben löst man mit zwei Zeigern und einem Dummy-Node.

Antwort-Muster

Frage: Wie dreht man eine Linked List um?

  1. Mechanismus: Ich laufe mit prev und cur durch die Liste und drehe bei jedem Node den next-Zeiger um.
  2. Zahl: Ein Durchlauf, O(n) Zeit und O(1) Platz. Vorher muss ich next in einer Variable merken.
  3. Trade-off: Rekursiv ist es kürzer, braucht aber O(n) Stack. Iterativ ist sicherer bei langen Listen.
  4. Produktion: In Java ist ArrayList fast immer besser als LinkedList, wegen der Cache-Lokalität.

1. Umdrehen in 5 Schritten

  1. Start: prev = null, cur = head.
  2. next merken: next = cur.next. Sonst geht der Rest der Liste verloren.
  3. Umdrehen: cur.next = prev. Der Node zeigt jetzt zurück.
  4. Vorrücken: prev = cur, dann cur = next.
  5. Ende: Ist cur null, ist prev der neue Kopf. Bei einer leeren Liste ist das null.

2. Aufbau

  1. Ein Node hat val und next. Das letzte next ist null.
  2. Die Liste ist über den Kopf (head) erreichbar. Es gibt keinen Zugriff per Index.
  3. Ein Dummy-Node vor dem Kopf vermeidet Sonderfälle beim Löschen und Einfügen am Anfang.
  4. Slow und Fast: Zwei Zeiger mit verschiedenem Tempo finden die Mitte und Zyklen.
  5. Die doppelt verkettete Liste hat zusätzlich prev. Java LinkedList ist so gebaut.
  6. Zyklus: Zeigt ein next zurück, endet die Liste nie. Eine Schleife ohne Abbruch läuft endlos.

3. Details

  1. Kosten: Einfügen und Löschen an einem bekannten Node kostet O(1). Suchen und Zugriff per Index kostet O(n). Am Anfang einfügen ist O(1).
  2. Dummy-Node: Ein Node vor dem Kopf. Er macht „Kopf löschen“ und „in leere Liste einfügen“ zu normalen Fällen. Das Ergebnis ist dummy.next.
  3. Umdrehen: next merken, umdrehen, prev und cur vorrücken. O(n) Zeit, O(1) Platz. Rekursiv braucht es O(n) Stack.
  4. Mitte finden: fast geht zwei Schritte, slow einen. Ist fast am Ende, steht slow in der Mitte. Bei gerader Länge ist es die zweite Mitte.
  5. Zyklus erkennen (Floyd): Gibt es einen Zyklus, holt fast slow ein. Gibt es keinen, erreicht fast null. O(n) Zeit, O(1) Platz. Ein HashSet geht auch, braucht aber O(n) Platz.
  6. Zyklus-Start finden: Nach dem Treffen setzt man einen Zeiger auf den Kopf. Beide gehen einen Schritt pro Runde. Wo sie sich treffen, beginnt der Zyklus. Der Abstand Kopf bis Start ist gleich dem Abstand Treffpunkt bis Start (modulo Zyklus-Länge).
  7. Zwei sortierte Listen mischen: Dummy-Node und ein Zeiger t. Immer den kleineren Kopf anhängen. Am Ende den Rest anhängen. O(n + m), ohne neue Nodes.
  8. N-ter Knoten von hinten: fast geht n Schritte voraus. Dann laufen beide, bis fast am Ende ist. slow steht vor dem Node, der weg muss. Ein Durchlauf.
  9. Palindrom prüfen: Mitte finden, zweite Hälfte umdrehen, beide Hälften vergleichen. O(n) Zeit, O(1) Platz. Die Liste ist danach verändert, wenn man die Hälfte nicht zurückdreht.
  10. Java LinkedList: Sie ist doppelt verkettet und implementiert List und Deque. Index-Zugriff läuft vom näheren Ende aus. Sie ist nicht synchronisiert.
  11. ArrayList: get und set sind O(1). add ist amortisiert O(1). Einfügen in der Mitte ist O(n), weil Elemente verschoben werden.
  12. Cache-Lokalität: Ein Array liegt im Speicher am Stück. Nodes einer Liste liegen verstreut. Darum ist ArrayList in der Praxis meist schneller, auch beim Einfügen in der Mitte.

4. Fallen

  • „Einfügen in einer Linked List ist immer O(1).“ → Falsch. Nur an einem bekannten Node. Den Node zu finden kostet O(n).
  • „LinkedList ist in Java schneller als ArrayList beim Einfügen.“ → Falsch. Nur am Anfang. Für get ist sie viel langsamer (Beispiel: 344 ms gegen 0.5 ms).
  • „Umdrehen geht ohne next zu merken.“ → Falsch. Nach cur.next = prev ist der Rest der Liste nicht mehr erreichbar.
  • „Bei einem Zyklus findet die Schleife while (n != null) das Ende.“ → Falsch. Sie läuft endlos. Man braucht Floyd oder ein Set.
  • „Den Kopf löschen ist wie jeden anderen Node.“ → Falsch. Es gibt keinen Vorgänger. Ein Dummy-Node löst das.
  • „Der Palindrom-Test hinterlässt die Liste unverändert.“ → Falsch. Die zweite Hälfte ist umgedreht. Man muss zurückdrehen, wenn die Liste weiter gebraucht wird.

5. Selbsttest

Warum?

Warum nimmt man einen Dummy-Node?

Er steht vor dem Kopf. So braucht man keinen Sonderfall, wenn der Kopf gelöscht wird oder die Liste leer ist.

Warum nutzt man zwei Zeiger?

Mit einem Durchlauf und O(1) Platz findet man Mitte, Zyklus und den n-ten Node von hinten. Man spart einen zweiten Durchlauf oder ein Set.

Warum ist ArrayList meist schneller als LinkedList?

Ein Array liegt am Stück im Speicher und nutzt den CPU-Cache. Listen-Nodes sind verstreut. get ist bei LinkedList O(n).

Wie innen?

Wie dreht man eine Liste um?

Mit prev und cur: next merken, cur.next = prev, prev = cur, cur = next. Am Ende ist prev der neue Kopf.

Wie findet man die Mitte?

slow geht einen Schritt, fast zwei. Ist fast am Ende, steht slow in der Mitte. Bei gerader Länge ist es die zweite Mitte.

Wie erkennt man einen Zyklus?

Mit Floyd: slow einen Schritt, fast zwei. Treffen sie sich, gibt es einen Zyklus. Erreicht fast null, gibt es keinen.

Wie findet man den Start des Zyklus?

Nach dem Treffen einen Zeiger auf den Kopf setzen. Beide gehen einen Schritt pro Runde. Wo sie sich treffen, beginnt der Zyklus.

Wie löscht man den n-ten Node von hinten?

fast geht n Schritte voraus. Dann laufen fast und slow, bis fast.next null ist. slow steht vor dem Node, der weg muss: slow.next = slow.next.next.

Wie mischt man zwei sortierte Listen?

Dummy-Node und Zeiger t. Immer den kleineren Kopf an t hängen und vorrücken. Am Ende den Rest anhängen.

Zahlen

Was kostet get(i) bei LinkedList?

O(n). Java läuft vom näheren Ende aus, also höchstens etwa n/2 Schritte.

Was kosten Einfügen und Löschen an bekanntem Node?

O(1). Bei doppelt verketteten Listen auch das Löschen, weil prev bekannt ist.

Wie viel Platz braucht Floyd?

O(1). Es sind nur zwei Zeiger. Ein HashSet bräuchte O(n).

Was kostet das Umdrehen?

O(n) Zeit und O(1) Platz iterativ. Rekursiv O(n) Stack.

Vergleich

LinkedList vs ArrayList?

ArrayList: get O(1), add amortisiert O(1), Einfügen vorne O(n). LinkedList: get O(n), Einfügen an bekannter Stelle O(1). In der Praxis gewinnt ArrayList meist wegen Cache.

Einfach vs doppelt verkettet?

Doppelt hat zusätzlich prev. Rückwärts laufen und Löschen eines bekannten Nodes gehen in O(1). Dafür braucht jeder Node mehr Speicher.

Linked List vs Array?

Array: Zugriff O(1), Einfügen in der Mitte O(n). Liste: Zugriff O(n), Einfügen an bekannter Stelle O(1).

Floyd vs HashSet bei Zyklen?

Floyd braucht O(1) Platz. Das Set braucht O(n) Platz, ist aber einfacher und findet den Start direkt.

Produktion

Was tun, wenn ein Dienst viele LinkedList-Objekte hält und viel Speicher braucht?

Jeder Eintrag ist ein eigener Node mit zwei Zeigern. Das kostet Speicher und Garbage-Collection. Lösung: ArrayList oder ArrayDeque.

Was tun bei einer Endlosschleife beim Durchlaufen einer eigenen Liste?

Vermutlich ein Zyklus durch einen falschen next-Zeiger. Ich prüfe mit Floyd. Beim Debuggen gebe ich nur die ersten N Nodes aus.

Szenario: Eine Warteschlange wird mit list.remove(0) auf einer ArrayList gebaut und ist bei grossen Mengen langsam. Was tun Sie?

remove(0) verschiebt alle Elemente, O(n). Lösung: ArrayDeque als Queue. Es hat O(1) am Anfang und am Ende.

Szenario: Beim Löschen von Elementen in einer for-each-Schleife über eine Liste gibt es Fehler. Was tun Sie?

Strukturelle Änderungen ausserhalb des Iterators sind verboten, die Iteratoren sind fail-fast. Lösung: iterator.remove() oder removeIf().

Design

Wann nutzen Sie eine eigene Linked List?

Fast nie. In Java nehme ich ArrayList, ArrayDeque oder LinkedHashMap. Linked Lists stecken in LRU-Caches und im Interview.

Wie baut man einen LRU-Cache?

Mit einer HashMap und einer doppelt verketteten Liste. Die Map findet den Node in O(1). Die Liste verschiebt ihn nach vorne oder entfernt ihn hinten in O(1). In Java macht das LinkedHashMap.

Wie testen Sie eine Listen-Funktion?

Leere Liste, ein Node, zwei Nodes, gerade und ungerade Länge, Zyklus, Kopf löschen, Ende löschen. Dazu prüfen, dass kein Node verloren geht.

Wie vermeiden Sie einen Stack Overflow bei langen Listen?

Iterativ arbeiten statt rekursiv. Jede Rekursionstiefe kostet Stack, bei einer langen Liste geht er aus.

Mehr

Gerüst

  • Warum? Einfügen und Löschen an bekannter Stelle in O(1), kein Verschieben, keine feste Grösse.
  • Wie innen? Nodes mit val und next. Zwei Zeiger und ein Dummy-Node lösen fast alle Aufgaben.
  • Zahlen Zugriff O(n), Einfügen bekannt O(1). Floyd: O(n) Zeit, O(1) Platz. Umdrehen: O(n), O(1).
  • Vergleich ArrayList: get O(1). LinkedList: get O(n), doppelt verkettet. ArrayDeque als Queue.
  • Produktion LinkedList frisst Speicher und Cache. Zyklus gibt eine Endlosschleife.
  • Design Dummy-Node. Iterativ statt rekursiv. LRU: Map plus doppelt verkettete Liste.

Beispiel: Umdrehen, Mitte, Zyklus, Mischen und Löschen in Java

static class Node { int val; Node next; Node(int v) { val = v; } }

static Node reverse(Node head) {
    Node prev = null, cur = head;
    while (cur != null) {
        Node next = cur.next;      // merken
        cur.next = prev;           // umdrehen
        prev = cur;                // vorrücken
        cur = next;
    }
    return prev;
}
static Node middle(Node head) {
    Node slow = head, fast = head;
    while (fast != null && fast.next != null) { slow = slow.next; fast = fast.next.next; }
    return slow;
}
static Node cycleStart(Node head) {
    Node slow = head, fast = head;
    while (fast != null && fast.next != null) {
        slow = slow.next; fast = fast.next.next;
        if (slow == fast) {
            Node p = head;
            while (p != slow) { p = p.next; slow = slow.next; }
            return p;
        }
    }
    return null;
}
static Node mergeSorted(Node a, Node b) {
    Node dummy = new Node(0), t = dummy;
    while (a != null && b != null) {
        if (a.val <= b.val) { t.next = a; a = a.next; } else { t.next = b; b = b.next; }
        t = t.next;
    }
    t.next = a != null ? a : b;
    return dummy.next;
}
static Node removeNthFromEnd(Node head, int n) {
    Node dummy = new Node(0); dummy.next = head;
    Node fast = dummy, slow = dummy;
    for (int i = 0; i < n; i++) fast = fast.next;
    while (fast.next != null) { fast = fast.next; slow = slow.next; }
    slow.next = slow.next.next;
    return dummy.next;
}

list with cycle        = 1 -> 2 -> 3 -> 4 -> 5 -> 3 -> 4 -> 5 -> 3 -> 4 -> 5 -> 3 ->  ...
mergeSorted            = 1 -> 2 -> 3 -> 3 -> 5 -> 6 -> 8
removeNthFromEnd(2)    = 1 -> 2 -> 3 -> 5, n=5 (Kopf) = 2 -> 3 -> 4 -> 5
palindrome 1,2,2,1 = true, 1,2,3 = false
get(n/2) x 2000, n=100,000: ArrayList 0.50 ms, LinkedList 343.95 ms (sum=200000000)

iterator.remove even   = [1, 3, 5]

Echte Ausgabe, Oracle JDK 17.0.3.1. Die Zeiten sind Einzelmessungen ohne Warm-up und zeigen nur die Grössenordnung.

  1. reverse dreht alle Zeiger. Die leere Liste gibt null zurück, also eine leere Ausgabe.
  2. Bei Länge 6 liefert middle den Wert 4, die zweite Mitte. Bei Länge 5 den Wert 3.
  3. Der Zyklus beginnt bei 3. Ohne Zyklus gibt es null. Die Ausgabe der Liste mit Zyklus ist auf 12 Nodes gekürzt, sonst liefe sie endlos.
  4. mergeSorted erzeugt eine sortierte Liste mit beiden Dreien, ohne neue Nodes.
  5. removeNthFromEnd löscht auch den Kopf (n = 5) ohne Sonderfall, weil der Dummy-Node davor steht.
  6. get in der Mitte: 0.50 ms gegen 343.95 ms bei 2000 Aufrufen. Das ist der Preis von O(n) pro Zugriff.
  7. Einfügen vorne: LinkedList ist mit 8.4 ms viel schneller als ArrayList mit 218.9 ms. Das ist der einzige Fall, in dem sie gewinnt. Dafür gibt es ArrayDeque.

Vergleich

  • ArrayList: Array, get O(1), add amortisiert O(1), Einfügen vorne O(n).
  • LinkedList (Java): doppelt verkettet, List und Deque, get O(n), nicht synchronisiert.
  • ArrayDeque: Queue und Stack mit O(1) an beiden Enden, ohne Node-Objekte.
  • LinkedHashMap: Map mit doppelt verketteter Liste. Basis für LRU-Caches.
  • Einfach verkettet: wenig Speicher, nur vorwärts. Doppelt: rückwärts und Löschen in O(1).
  • Floyd: O(1) Platz. HashSet: O(n) Platz, einfach.

Produktion

  1. Speicher: Jeder Eintrag einer LinkedList ist ein Node mit zwei Zeigern. Bei Millionen Einträgen belastet das den Heap und den Garbage Collector. Lösung: ArrayList oder ArrayDeque.
  2. Langsame Zugriffe: get(i) in einer Schleife auf einer LinkedList ist O(n²). Lösung: Iterator oder ArrayList.
  3. Langsame Queue: remove(0) auf einer ArrayList verschiebt alles. Lösung: ArrayDeque.
  4. Endlosschleife: Ein Zyklus durch einen falschen next-Zeiger. Lösung: Floyd zum Prüfen, Nodes beim Debuggen begrenzt ausgeben.
  5. ConcurrentModificationException: Löschen in einer for-each-Schleife. Lösung: iterator.remove() oder removeIf().
  6. Stack Overflow: Rekursion über lange Listen. Lösung: iterativ arbeiten.

Diagnose: Werkzeuge und Befehle

  • Nodes ausgeben: Eine Hilfsfunktion, die höchstens N Nodes druckt, damit ein Zyklus nicht hängt.
  • Kleine Fälle: leer, ein Node, zwei Nodes, gerade und ungerade Länge.
  • Zeiger-Invariante: Sagen, was prev, cur und next vor jedem Schritt bedeuten.
  • jcmd <pid> GC.class_histogram: zeigt viele java.util.LinkedList$Node-Objekte.
  • Profiler: zeigt Zeit in LinkedList.get oder node(int).
  • Stack Trace: Tiefe Rekursion zeigt sich als lange, gleiche Frames.

Senior-Punkte

  1. In Java fast nie LinkedList. ArrayList und ArrayDeque sind schneller und kleiner.
  2. Zeiger-Aufgaben haben drei Werkzeuge: Dummy-Node, Slow und Fast, Umdrehen. Wer sie kennt, löst fast alles.
  3. O(1) heisst „bei bekanntem Node“. Das Finden kostet O(n). Darum paart man Listen mit einer Map, wie beim LRU-Cache.
  4. Iterativ vor rekursiv bei langen Listen. Der Stack ist begrenzt.
  5. Randfälle zuerst: leer, ein Node, Kopf löschen, Zyklus. Dort gehen Fehler hin.
  6. Verändern oder kopieren: Das Umdrehen der zweiten Hälfte verändert die Liste. Sagen, ob man sie zurückdreht.
