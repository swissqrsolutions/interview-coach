Stack und Queue

Kern: Ein Stack ist LIFO (Last In, First Out), das zuletzt Eingefügte kommt zuerst raus. Eine Queue ist FIFO (First In, First Out), das zuerst Eingefügte kommt zuerst raus. In Java nimmt man für beides ArrayDeque über das Interface Deque.

Antwort-Muster

Frage: Welche Klasse nimmst du in Java für Stack und Queue?

  1. Mechanismus: ArrayDeque über das Interface Deque. Als Stack nutze ich push/pop/peek, als Queue offer/poll.
  2. Zahl: Die Operationen sind amortisiert O(1), weil das Ring-Array wächst.
  3. Trade-off: Die Klasse Stack erbt von Vector und ist synchronized. Die Java-Doku empfiehlt Deque. ArrayDeque erlaubt kein null.
  4. Produktion: Für mehrere Threads brauche ich eine BlockingQueue mit Grenze, sonst droht ein OutOfMemoryError.

1. Die Reise eines monotonen Stacks

  1. Der Stack hält wartende Tage: Er speichert Indizes von Tagen, die noch keinen wärmeren Tag gefunden haben.
  2. Monoton fallend: Von unten nach oben fallen die Temperaturen. Das ist die Invariante.
  3. Ein neuer Tag kommt: Ist er wärmer als der oberste wartende Tag, ist er dessen Antwort. Pop und Abstand eintragen.
  4. Wiederholen: Solange der neue Tag wärmer ist, weiter poppen. Dann den neuen Tag pushen.
  5. Am Ende: Tage, die noch im Stack liegen, haben keinen wärmeren Tag. Ihr Wert bleibt 0.

2. Aufbau

  1. Deque: Das Interface Deque („double-ended queue“) erlaubt Einfügen und Entfernen an beiden Enden.
  2. Als Stack: push, pop, peek arbeiten alle am Kopf (First).
  3. Als Queue: offer hängt hinten an, poll nimmt vorne weg.
  4. ArrayDeque: ein wachsendes Ring-Array. Die meisten Operationen sind amortisiert O(1). null ist verboten.
  5. Stack-Klasse: erbt von Vector. Die Java-Doku empfiehlt stattdessen Deque<Integer> stack = new ArrayDeque<>().

3. Details, die Interviewer fragen

  1. Warum nicht java.util.Stack? Stack erbt von Vector. Die Methoden von Vector sind synchronized. Die Java-Doku empfiehlt Deque. ArrayDeque ist laut Doku als Stack wahrscheinlich schneller als Stack.
  2. ArrayDeque oder LinkedList als Queue? ArrayDeque ist laut Doku als Queue wahrscheinlich schneller als LinkedList. LinkedList erlaubt null. ArrayDeque erlaubt es nicht.
  3. Werfen oder nicht werfen: add/remove/element werfen bei Fehler eine Exception. offer/poll/peek geben false oder null zurück. push/pop verhalten sich wie addFirst/removeFirst.
  4. Monotoner Stack: Ein monotoner Stack hält Elemente sortiert, steigend oder fallend. Er findet für jedes Element das nächste grössere oder kleinere in O(n).
  5. Fallend oder steigend? Für „nächstes grösseres“ nimmst du einen fallenden Stack. Für „nächstes kleineres“ nimmst du einen steigenden Stack. Faustregel: Der Stack hält, was noch auf seine Antwort wartet.
  6. Indizes statt Werte: Man speichert meist Indizes. So kann man Abstände berechnen. Den Wert hat man trotzdem über a[i].
  7. Monotones Deque: Es liefert das Maximum in jedem Fenster der Grösse k. Entferne hinten kleinere Werte. Entferne vorne veraltete Indizes.
  8. Rekursion = Stack: Jede Rekursion lässt sich mit einem eigenen Stack iterativ schreiben. Das vermeidet StackOverflowError.
  9. Randfälle: Teste leere Eingabe, nur öffnende Klammern und nur schliessende Klammern. Teste ein Element und alle gleich. Bei Gleichheit entscheidest du zwischen > und >=.
  10. So sprichst du beim Coden: Sage, dass jede schliessende Klammer zur letzten offenen passen muss. Das ist LIFO, also ein Stack. Du nimmst ArrayDeque, nicht Stack. Am Ende muss der Stack leer sein. Es ist O(n) Zeit und O(n) Speicher.

4. Fallen

  • „Für einen Stack nehme ich java.util.Stack.“ → Veraltet. Deque<E> stack = new ArrayDeque<>().
  • „Valid Parentheses ist fertig, wenn kein pop scheitert.“ → Falsch. Am Ende muss der Stack leer sein.
  • „Queue mit zwei Stacks ist O(n) pro pop.“ → Nur einzeln. Amortisiert O(1), jedes Element wird einmal umgefüllt.
  • „Ein while im for beim monotonen Stack ist O(n²).“ → Falsch. Jedes Element wird höchstens einmal gepoppt: O(n).
  • „ArrayDeque erlaubt null wie LinkedList.“ → Falsch. null wirft NullPointerException.
  • „PriorityQueue ist eine FIFO-Queue.“ → Falsch. Sie liefert das kleinste Element, nicht das älteste.

5. Selbsttest

Warum?

Warum nicht java.util.Stack?

Stack erbt von Vector und ist synchronized. Das kostet Zeit und erlaubt Zugriff per Index, was nicht zu einem Stack passt.

Was ist der Unterschied zwischen poll und remove?

poll gibt bei leerer Queue null zurück. remove wirft NoSuchElementException.

Darf ArrayDeque null enthalten?

Nein. null würde mit dem „leer“-Signal von poll kollidieren. Es wirft NullPointerException.

Warum ist der monotone Stack O(n)?

Jeder Index wird genau einmal gepusht und höchstens einmal gepoppt.

Wie innen?

Was ist der Unterschied zwischen Stack und Queue?

Stack ist LIFO: das Letzte kommt zuerst raus. Queue ist FIFO: das Erste kommt zuerst raus.

Welche Methoden nutzt du für Stack und Queue auf ArrayDeque?

Stack: push, pop, peek. Queue: offer, poll, peek.

Was ist ein monotoner Stack?

Ein Stack, dessen Elemente immer steigend oder fallend sortiert sind. Er findet das nächste grössere oder kleinere Element in O(n).

Wie baust du eine Queue aus zwei Stacks?

push in den in-Stack. pop aus dem out-Stack; ist er leer, alles aus in umfüllen. Amortisiert O(1).

Wie funktioniert ein Min Stack?

Jeder Eintrag speichert seinen Wert und das Minimum bis dahin. getMin liest das oberste Minimum, O(1).

Zahlen

Wie baust du einen Stack aus Queues?

Bei push das neue Element hinten anhängen und alle anderen dahinter rotieren. push O(n), pop O(1).

Wie teuer sind push und pop auf ArrayDeque?

Amortisiert O(1). Nur beim Wachsen des Ring-Arrays wird kopiert.

Wie viele Umfüll-Schritte macht eine Queue aus zwei Stacks bei 6 Elementen?

6 Schritte. Jedes Element wandert genau einmal von in nach out. Darum amortisiert O(1).

Vergleich

Welche Klasse nimmst du in Java für einen Stack?

ArrayDeque über das Interface Deque. Die Java-Doku empfiehlt Deque statt der Klasse Stack.

Welche Queue nimmst du für mehrere Threads?

Eine BlockingQueue wie ArrayBlockingQueue für Producer-Consumer mit Grenze, oder ConcurrentLinkedQueue ohne Blockieren.

Ist PriorityQueue eine FIFO-Queue?

Nein. Sie gibt immer das kleinste Element zuerst heraus, nicht das älteste.

Produktion

Szenario: Ein Service mit In-Memory-Queue stirbt unter Last mit OutOfMemoryError. Was vermutest du?

Die Queue ist unbegrenzt und der Consumer zu langsam. Lösung: begrenzte BlockingQueue, Backpressure oder ein externer Broker. Queue-Länge als Metrik überwachen.

Was geht kaputt, wenn man null in eine ArrayDeque legt?

offer(null) wirft eine NullPointerException. Das fällt oft erst in Produktion auf.

Woran erkennst du eine volllaufende Queue?

Die Queue-Länge als Metrik wächst ständig. Im Heap-Histogramm erscheinen viele Queue-Knoten oder Object[]. Ein Thread Dump zeigt Threads, die in take() warten.

Design

Wie prüfst du gültige Klammern?

Öffnende Klammern (oder die erwartete schliessende) pushen. Bei schliessender poppen und vergleichen. Am Ende muss der Stack leer sein.

Wo nutzt man eine Queue in Algorithmen?

BFS auf Bäumen und Graphen, Ebenen-Reihenfolge, kürzester Weg ohne Gewichte.

Wo nutzt man einen Stack in Algorithmen?

DFS ohne Rekursion, Klammern, Ausdrücke auswerten, Undo, monotone Probleme.

Wie findest du das Maximum in jedem Fenster der Grösse k?

Mit einem monotonen Deque von Indizes, Werte fallend. Vorne steht das Maximum. O(n).

Szenario: Deine Klammer-Lösung sagt für "((" true. Was fehlt?

Am Ende prüfe ich nicht, ob der Stack leer ist. Fix: return stack.isEmpty().

Szenario: Der Interviewer fragt, ob dein while im for nicht O(n²) ist. Was sagst du?

Jedes Element kommt einmal in den Stack und geht höchstens einmal raus. Alle while-Durchläufe zusammen sind höchstens n. Also O(n) gesamt.

Mehr

Gerüst

  • Warum? Verschachtelung ist LIFO: Die letzte offene Klammer schliesst zuerst. Aufgaben der Reihe nach sind FIFO.
  • Wie innen? Deque mit ArrayDeque, ein wachsendes Ring-Array. push/pop/peek am Kopf, offer/poll als Queue.
  • Zahlen Operationen sind amortisiert O(1). Monotoner Stack: jeder Index einmal push, höchstens einmal pop, also O(n).
  • Vergleich ArrayDeque statt Stack (Vector, synchronized) und statt LinkedList. PriorityQueue ist keine FIFO-Queue.
  • Produktion Unbegrenzte Queue → OutOfMemoryError. Rekursion → StackOverflowError. ArrayDeque ist nicht thread-sicher und erlaubt kein null.
  • Design Monotoner Stack für „nächstes grösseres Element“. Min Stack speichert das Minimum pro Eintrag. Queue aus zwei Stacks.

Beispiel: vier Klassiker in Java

Erkennen Stack: Klammern und Verschachtelung, „nächstes grösseres/kleineres Element“, Rückgängig, Ausdrücke auswerten, DFS ohne Rekursion. Erkennen Queue: „der Reihe nach“, BFS, Ebenen, kürzester Weg ohne Gewichte.

Template (monotoner Stack):

Deque<Integer> stack = new ArrayDeque<>();          // Indizes
for (int i = 0; i < a.length; i++) {
    while (!stack.isEmpty() && a[i] > a[stack.peek()]) {
        int j = stack.pop();                         // a[i] ist die Antwort für j
        // Ergebnis für j eintragen
    }
    stack.push(i);
}

1. Valid Parentheses – O(n) Zeit, O(n) Speicher:

static boolean isValid(String s) {
    Deque<Character> stack = new ArrayDeque<>();
    for (char c : s.toCharArray()) {
        if (c == '(') stack.push(')');                // Trick: erwartete schliessende Klammer pushen
        else if (c == '[') stack.push(']');
        else if (c == '{') stack.push('}');
        else if (stack.isEmpty() || stack.pop() != c) return false;
    }
    return stack.isEmpty();                           // offene Reste -> ungültig
}

2. Daily Temperatures und Next Greater Element (monotoner Stack) – O(n):

static int[] dailyTemperatures(int[] t) {
    int[] ans = new int[t.length];
    Deque<Integer> stack = new ArrayDeque<>();        // Indizes, Temperaturen fallend
    for (int i = 0; i < t.length; i++) {
        while (!stack.isEmpty() && t[i] > t[stack.peek()]) {
            int j = stack.pop();                      // i ist der "nächste wärmere Tag" für j
            ans[j] = i - j;
        }
        stack.push(i);
    }
    return ans;
}

static int[] nextGreater(int[] a) {
    int[] ans = new int[a.length];
    Arrays.fill(ans, -1);
    Deque<Integer> stack = new ArrayDeque<>();
    for (int i = 0; i < a.length; i++) {
        while (!stack.isEmpty() && a[i] > a[stack.peek()]) ans[stack.pop()] = a[i];
        stack.push(i);
    }
    return ans;
}

3. Queue mit zwei Stacks – amortisiert O(1) pro Operation:

static class MyQueue {
    private final Deque<Integer> in = new ArrayDeque<>(), out = new ArrayDeque<>();
    int moves = 0;                                    // nur zum Zeigen der Kosten
    void push(int x) { in.push(x); }
    int pop()  { shift(); return out.pop(); }
    int peek() { shift(); return out.peek(); }
    boolean empty() { return in.isEmpty() && out.isEmpty(); }
    private void shift() {
        if (out.isEmpty())                            // nur umfüllen, wenn out leer ist
            while (!in.isEmpty()) { out.push(in.pop()); moves++; }
    }
}

4. Min Stack – alle Operationen O(1):

static class MinStack {
    private final Deque<int[]> st = new ArrayDeque<>();   // {wert, minimum bis hier}
    void push(int x) { st.push(new int[]{x, st.isEmpty() ? x : Math.min(x, st.peek()[1])}); }
    void pop()    { st.pop(); }
    int top()     { return st.peek()[0]; }
    int getMin()  { return st.peek()[1]; }
}

Echte Ausgabe, Oracle JDK 17.0.3.

  1. "((" ist ungültig, weil am Ende noch etwas im Stack liegt. Viele vergessen das return stack.isEmpty().
  2. "([)]" scheitert, weil ) kommt, aber oben ] erwartet wird.
  3. MyQueue: 6 Elemente, insgesamt 6 Umfüll-Schritte. Jedes Element wird genau einmal von in nach out bewegt. Darum amortisiert O(1).
  4. MinStack: Nach pop von −3 ist das Minimum wieder −2. Jeder Eintrag merkt sich sein eigenes Minimum.
  5. push legt vorne ab, offerLast hinten: [2, 1, 3]. poll auf leerem Deque gibt null, pop wirft eine Exception.

Vergleich

  • ArrayDeque: Stack und Queue, amortisiert O(1), kein null, nicht thread-sicher. Standardwahl.
  • LinkedList: Deque und List, O(1) an den Enden, erlaubt null, mehr Speicher pro Element.
  • Stack: Legacy, synchronized über Vector. Nicht mehr nutzen.
  • PriorityQueue: keine FIFO-Queue. Sie gibt immer das kleinste Element zuerst.
  • ArrayBlockingQueue / LinkedBlockingQueue: thread-sicher, blockierend, für Producer-Consumer.
  • ConcurrentLinkedDeque: thread-sicher, nicht blockierend.

In der Produktion

  1. Unbegrenzte Queue: Eine Queue ohne Grenze wächst, wenn der Consumer langsamer ist. Ergebnis: OutOfMemoryError. Lösung: begrenzte BlockingQueue mit Backpressure.
  2. Tiefe Rekursion: Rekursiver Parser oder DFS auf tiefen Daten wirft StackOverflowError. Lösung: eigener Stack auf dem Heap.
  3. null in ArrayDeque: offer(null) wirft NullPointerException. Das fällt oft erst in Produktion auf.
  4. Threads: ArrayDeque ist nicht thread-sicher. Für mehrere Threads: java.util.concurrent-Queues.

Diagnose

  • Stack-Zustand von Hand: Nach jedem Schritt aufschreiben, was oben liegt.
  • Thread Dump (jcmd <pid> Thread.print): zeigt Threads, die in take() einer BlockingQueue warten.
  • Heap-Histogramm: viele Object[] oder Queue-Knoten deuten auf eine volllaufende Queue.
  • Metrik: Queue-Länge überwachen. Wächst sie ständig, ist der Consumer zu langsam.

Senior-Punkte

  1. Deque statt Stack ist ein Signal: Du kennst die aktuelle Java-API.
  2. Monotoner Stack ist ein Muster, keine Einzellösung. Next Greater, Daily Temperatures, Largest Rectangle in Histogram nutzen dasselbe Gerüst.
  3. Amortisiert begründen: „Jedes Element wird einmal gepusht und einmal gepoppt.“ Das ist das ganze Argument.
  4. Queues brauchen Grenzen. In echten Systemen ist eine unbegrenzte Queue ein verstecktes Speicherleck.
