Graphen: BFS, DFS, Topo-Sort

DSA · Tier 1 · Quellen: Java SE 25 API-Doku java.util (ArrayDeque, ArrayList), CLRS 4. Auflage (2022): Kap. 20 „Elementary Graph Algorithms“ (BFS, DFS, topologische Sortierung), Kap. 19 „Data Structures for Disjoint Sets“ (Union-Find)

Kern: Ein Graph ist eine Menge von Knoten (V) und Kanten (E) zwischen ihnen. Fast jede Graph-Aufgabe ist BFS oder DFS mit einer visited-Markierung, in O(V + E). Darauf bauen topologische Sortierung, Zykluserkennung und Union-Find für Zusammenhang.

1. Wo sitzt das Muster?

  1. Grid als Graph: Jede Zelle ist ein Knoten. Nachbarn sind die vier Zellen oben, unten, links, rechts. Keine Liste nötig, nur ein Richtungs-Array.
  2. Adjazenzliste: Für jeden Knoten eine Liste seiner Nachbarn. Speicher O(V + E). Standard im Interview.
  3. Gerichtet oder ungerichtet: Bei ungerichteten Kanten trägt man beide Richtungen ein. Bei gerichteten nur u → v.
  4. visited: Ein Graph kann Zyklen haben. Ohne Markierung läuft die Suche endlos.
  5. Kosten: BFS und DFS besuchen jeden Knoten einmal und jede Kante ein- bis zweimal: O(V + E). Im Grid: O(Zeilen · Spalten).

2. Die Reise einer topologischen Sortierung (die Geschichte zum Merken)

  1. Indegree zählen: Der Indegree ist die Anzahl eingehender Kanten. Ein Kurs mit Indegree 0 hat keine offenen Voraussetzungen.
  2. Start: Alle Knoten mit Indegree 0 kommen in eine Queue. Hier nur Kurs 0.
  3. Abarbeiten: Ein Knoten wird ausgegeben. Für jeden Nachfolger sinkt der Indegree um 1.
  4. Neu frei: Fällt ein Indegree auf 0, kommt dieser Knoten in die Queue. Kurs 3 wird erst frei, wenn 1 und 2 fertig sind.
  5. Zyklus-Test: Bei einem Zyklus fällt kein Knoten im Kreis je auf 0. Dann ist die Ausgabe kürzer als V. Das ist der Algorithmus von Kahn.

3. Beispiel: vier Klassiker in Java

Erkennen: Grid mit „Inseln“, „Regionen“, „kürzester Weg“; Beziehungen „hängt ab von“, „ist verbunden mit“; Kantenliste als Eingabe; „Reihenfolge mit Voraussetzungen“; „gibt es einen Zyklus?“; „wie viele Gruppen?“.

Template (BFS mit visited): beim Einfügen markieren, nicht beim Herausnehmen.

static List<List<Integer>> buildGraph(int n, int[][] edges, boolean directed) {
    List<List<Integer>> adj = new ArrayList<>();
    for (int i = 0; i < n; i++) adj.add(new ArrayList<>());
    for (int[] e : edges) { adj.get(e[0]).add(e[1]); if (!directed) adj.get(e[1]).add(e[0]); }
    return adj;
}

static List<Integer> bfs(List<List<Integer>> adj, int start) {   // O(V + E)
    List<Integer> order = new ArrayList<>();
    boolean[] seen = new boolean[adj.size()];
    Deque<Integer> q = new ArrayDeque<>();
    q.offer(start); seen[start] = true;
    while (!q.isEmpty()) {
        int u = q.poll(); order.add(u);
        for (int v : adj.get(u)) if (!seen[v]) { seen[v] = true; q.offer(v); }
    }
    return order;
}

1. Number of Islands (DFS auf dem Grid) – O(R · C) Zeit, O(R · C) Stack im schlechtesten Fall:

static final int[][] DIRS = {{1, 0}, {-1, 0}, {0, 1}, {0, -1}};

static int numIslands(char[][] g) {
    int count = 0;
    for (int r = 0; r < g.length; r++)
        for (int c = 0; c < g[0].length; c++)
            if (g[r][c] == '1') { count++; sink(g, r, c); }
    return count;
}
static void sink(char[][] g, int r, int c) {
    if (r < 0 || c < 0 || r >= g.length || c >= g[0].length || g[r][c] != '1') return;
    g[r][c] = '0';                                        // als besucht markieren
    for (int[] d : DIRS) sink(g, r + d[0], c + d[1]);
}

2. Kürzester Weg im Grid (BFS, ungewichtet) – O(R · C):

static int shortestPath(int[][] g, int sr, int sc, int tr, int tc) {   // 0 = frei, 1 = Wand
    int R = g.length, C = g[0].length;
    boolean[][] seen = new boolean[R][C];
    Deque<int[]> q = new ArrayDeque<>();
    q.offer(new int[]{sr, sc}); seen[sr][sc] = true;      // beim Einfügen markieren
    for (int dist = 0; !q.isEmpty(); dist++) {
        for (int i = q.size(); i > 0; i--) {              // eine Ebene = ein Schritt
            int[] cur = q.poll();
            if (cur[0] == tr && cur[1] == tc) return dist;
            for (int[] d : DIRS) {
                int nr = cur[0] + d[0], nc = cur[1] + d[1];
                if (nr >= 0 && nc >= 0 && nr < R && nc < C && g[nr][nc] == 0 && !seen[nr][nc]) {
                    seen[nr][nc] = true;
                    q.offer(new int[]{nr, nc});
                }
            }
        }
    }
    return -1;
}

3. Course Schedule II (topologische Sortierung, Kahn) und Zykluserkennung (DFS, drei Farben) – O(V + E):

static int[] topoSort(int n, int[][] prereq) {            // prereq[i] = {kurs, voraussetzung}
    List<List<Integer>> adj = new ArrayList<>();
    for (int i = 0; i < n; i++) adj.add(new ArrayList<>());
    int[] indeg = new int[n];
    for (int[] p : prereq) { adj.get(p[1]).add(p[0]); indeg[p[0]]++; }
    Deque<Integer> q = new ArrayDeque<>();
    for (int i = 0; i < n; i++) if (indeg[i] == 0) q.offer(i);
    int[] order = new int[n]; int k = 0;
    while (!q.isEmpty()) {
        int u = q.poll(); order[k++] = u;
        for (int v : adj.get(u)) if (--indeg[v] == 0) q.offer(v);
    }
    return k == n ? order : new int[0];                   // k < n -> Zyklus
}

// 0 = weiss (neu), 1 = grau (auf dem aktuellen Pfad), 2 = schwarz (fertig)
static boolean hasCycle(List<List<Integer>> adj) {
    int[] color = new int[adj.size()];
    for (int u = 0; u < adj.size(); u++) if (color[u] == 0 && dfsCycle(adj, u, color)) return true;
    return false;
}
static boolean dfsCycle(List<List<Integer>> adj, int u, int[] color) {
    color[u] = 1;
    for (int v : adj.get(u)) {
        if (color[v] == 1) return true;                   // Rückwärtskante -> Zyklus
        if (color[v] == 0 && dfsCycle(adj, v, color)) return true;
    }
    color[u] = 2;
    return false;
}

4. Union-Find (kurz) – fast O(1) pro Operation, amortisiert:

static class UnionFind {
    final int[] parent, size; int components;
    UnionFind(int n) {
        parent = new int[n]; size = new int[n]; components = n;
        for (int i = 0; i < n; i++) { parent[i] = i; size[i] = 1; }
    }
    int find(int x) {
        while (parent[x] != x) { parent[x] = parent[parent[x]]; x = parent[x]; }  // Pfad halbieren
        return x;
    }
    boolean union(int a, int b) {
        int ra = find(a), rb = find(b);
        if (ra == rb) return false;                       // schon verbunden -> Kante schliesst Zyklus
        if (size[ra] < size[rb]) { int t = ra; ra = rb; rb = t; }
        parent[rb] = ra; size[ra] += size[rb]; components--;
        return true;
    }
}

  1. Drei Inseln: der 2×2-Block oben links, die einzelne Zelle in der Mitte, zwei Zellen unten rechts.
  2. Zum Ziel (3,0) sind es 7 Schritte, weil die Wand in Zeile 1 einen Umweg über Spalte 2 erzwingt. BFS findet den kürzesten Weg, weil sie Ebene für Ebene geht.
  3. Die zwei Kurse mit gegenseitiger Voraussetzung liefern ein leeres Array: Zyklus.
  4. 0→1, 0→2, 1→2 hat keinen Zyklus, obwohl 2 zweimal erreicht wird. Darum braucht man drei Farben: Schwarz (fertig) ist kein Zyklus, nur Grau (auf dem Pfad).
  5. Union-Find erkennt beim Hinzufügen der Kante (0,2), dass 0 und 2 schon verbunden sind. Das ist „Redundant Connection“.

4. Details, die Interviewer fragen

  1. BFS oder DFS? Kürzester Weg ohne Gewichte → BFS. Alles erreichen, Zusammenhang, Zyklus, Pfade aufzählen → DFS (oder BFS).
  2. Beim Einfügen markieren: Markiert man erst beim Herausnehmen, kommt ein Knoten mehrfach in die Queue. Das kostet Zeit und Speicher.
  3. Gewichtete Kanten: BFS findet dann nicht den kürzesten Weg. Dafür Dijkstra mit PriorityQueue (nicht-negative Gewichte).
  4. Zyklus ungerichtet: DFS mit Eltern-Knoten: Ein besuchter Nachbar, der nicht der Elternknoten ist, ist ein Zyklus. Oder Union-Find.
  5. Zyklus gerichtet: drei Farben (DFS) oder Kahn (Ausgabe kürzer als V).
  6. Topologische Sortierung: nur für DAGs (gerichtete azyklische Graphen). Es gibt oft mehrere gültige Reihenfolgen. DFS-Variante: Postorder umgedreht.
  7. Union-Find: find mit Pfadkompression und union nach Grösse oder Rang. Zusammen fast O(1) amortisiert (inverse Ackermann-Funktion, CLRS Kap. 19).
  8. Grid-Tricks: Richtungs-Array DIRS, Grenzen zuerst prüfen, Grid selbst als visited nutzen (wenn Ändern erlaubt ist).
  9. Randfälle: leeres Grid, ein Knoten, isolierte Knoten, Selbstschleifen, doppelte Kanten, Start = Ziel, Ziel unerreichbar.
  10. So sprichst du beim Coden: „Das ist ein Graph: Zellen sind Knoten, Nachbarn die vier Richtungen. Ich zähle Zusammenhangskomponenten mit DFS und markiere besuchte Zellen. Jede Zelle einmal: O(R · C). Rekursionstiefe im schlechtesten Fall R · C, darum könnte ich auf BFS wechseln.“

5. Vergleich

  • BFS: Queue, kürzester Weg ohne Gewichte, Speicher O(V).
  • DFS: Rekursion oder Stack, Zyklen, Topo-Sort, Komponenten. Tiefe kann O(V) sein.
  • Kahn (BFS-Topo-Sort): iterativ, erkennt Zyklen über die Anzahl.
  • Union-Find: nur „sind a und b verbunden?“, auch wenn Kanten nach und nach kommen. Keine Wege.
  • Dijkstra: gewichtete Graphen ohne negative Gewichte, O((V + E) log V) mit PriorityQueue.
  • Adjazenzmatrix: O(V²) Speicher, O(1) „gibt es Kante u-v?“. Nur bei dichten, kleinen Graphen.

6. In der Produktion

  1. Abhängigkeiten: Build-Tools, Paketmanager und Workflow-Systeme sortieren Aufgaben topologisch. Ein Zyklus ist ein Fehler („circular dependency“).
  2. Spark und andere Engines planen Jobs als DAG von Stufen.
  3. Tiefe Rekursion: DFS auf grossen Graphen wirft StackOverflowError. Lösung: iterativ mit eigenem Stack.
  4. Speicher: Riesige Graphen passen nicht in Adjazenzlisten im Speicher. Dann Graph-Datenbank oder verteilte Verarbeitung.

7. Diagnose

  • Graph zeichnen: Kanten als Pfeile, Indegree daneben schreiben.
  • Queue-Zustand pro Ebene ausgeben, um BFS-Fehler zu sehen.
  • Testfälle: Zyklus aus 2 Knoten, isolierter Knoten, Diamant (0→1, 0→2, 1→3, 2→3), unerreichbares Ziel.

8. Senior-Punkte

  1. Erst modellieren, dann coden: Was sind Knoten, was Kanten, gerichtet oder nicht, gewichtet oder nicht? Das sagst du laut.
  2. O(V + E) begründen: Jeder Knoten einmal, jede Kante ein- oder zweimal.
  3. Drei Farben, nicht zwei, für gerichtete Zyklen. Das ist eine häufige Prüffrage.
  4. Union-Find kennen, aber nur einsetzen, wenn nur Zusammenhang gefragt ist.

10. Fallen

  • „BFS findet immer den kürzesten Weg.“ → Nur ohne Gewichte (oder alle gleich). Sonst Dijkstra.
  • „visited beim Herausnehmen setzen reicht.“ → Korrekt, aber teuer. Knoten landen mehrfach in der Queue. Beim Einfügen markieren.
  • „Ein schon besuchter Knoten heisst Zyklus.“ → Falsch im gerichteten Graph. Nur ein grauer Knoten (auf dem aktuellen Pfad).
  • „Topologische Sortierung gibt es für jeden Graph.“ → Falsch. Nur für gerichtete azyklische Graphen.
  • „Union-Find findet den Weg zwischen zwei Knoten.“ → Falsch. Es sagt nur, ob sie verbunden sind.

11. Fragen

Wie stellst du einen Graphen in Java dar?

Meist als Adjazenzliste List<List<Integer>>. Speicher O(V + E). Für kleine dichte Graphen eine Matrix.

Welche Komplexität haben BFS und DFS?

O(V + E) Zeit mit Adjazenzliste. Im Grid O(Zeilen · Spalten).

Wann BFS, wann DFS?

BFS für kürzeste Wege ohne Gewichte und Ebenen. DFS für Zyklen, Topo-Sort, Komponenten und Pfade.

Warum markiert man bei BFS beim Einfügen?

Sonst kommt ein Knoten mehrfach in die Queue, bevor er verarbeitet wird.

Wie zählst du Inseln im Grid?

Jede noch unbesuchte Land-Zelle startet eine DFS oder BFS, die die ganze Insel markiert. Anzahl Starts = Anzahl Inseln.

Wie findest du den kürzesten Weg im Grid?

BFS vom Start, Ebene für Ebene. Die Ebene, in der das Ziel auftaucht, ist die Distanz.

Was ist eine topologische Sortierung?

Eine Reihenfolge der Knoten, in der jede Kante von früher nach später zeigt. Nur bei DAGs möglich.

Wie funktioniert Kahns Algorithmus?

Indegree zählen, alle mit 0 in eine Queue. Herausnehmen, ausgeben, Nachfolger-Indegree senken, neue Nullen einfügen.

Wie erkennt Kahn einen Zyklus?

Werden weniger als V Knoten ausgegeben, gibt es einen Zyklus.

Warum drei Farben bei der DFS-Zykluserkennung?

Grau heisst „auf dem aktuellen Pfad“. Nur eine Kante zu Grau ist ein Zyklus. Schwarz ist schon fertig und harmlos.

Wie erkennst du einen Zyklus im ungerichteten Graph?

DFS mit Elternknoten: ein besuchter Nachbar, der nicht der Elternknoten ist. Oder Union-Find: union auf schon verbundene Knoten.

Was ist Union-Find?

Eine Struktur für disjunkte Mengen mit find (Wurzel der Menge) und union (Mengen verbinden).

Was machen Pfadkompression und Union by Size?

Sie halten die Bäume flach. Zusammen ist jede Operation amortisiert fast O(1).

Wann nimmst du Union-Find statt DFS?

Wenn Kanten nach und nach kommen und nur gefragt ist, ob zwei Knoten verbunden sind.

Was tust du bei gewichteten Kanten?

Dijkstra mit PriorityQueue bei nicht-negativen Gewichten. BFS ist dann falsch.

Welche Randfälle testest du?

Leerer Graph, isolierte Knoten, Selbstschleife, doppelte Kanten, Start = Ziel, Ziel unerreichbar.

Szenario: Deine Inseln-DFS wirft bei einem 1000×1000-Grid voller Land StackOverflowError. Was tust du?

Die Rekursion ist bis zu 10⁶ tief. Ich wechsle auf BFS mit ArrayDeque oder iterative DFS mit eigenem Stack.

Szenario: Deine Zykluserkennung meldet einen Zyklus im Diamant 0→1, 0→2, 1→3, 2→3. Was ist falsch?

Ich nutze nur „besucht“ statt drei Farben. Knoten 3 ist schon fertig (schwarz), nicht auf dem Pfad. Fix: nur Kanten zu grauen Knoten zählen.

Szenario: Ein Build-System soll Module in gültiger Reihenfolge bauen und Zyklen melden. Wie?

Module als Knoten, Abhängigkeiten als Kanten. Kahns Algorithmus liefert die Reihenfolge. Bleiben Knoten übrig, meldet man sie als Zyklus.
