Bäume: DFS, BFS, BST

DSA · Tier 1 · Quellen: Java SE 25 API-Doku java.util (ArrayDeque, TreeMap), CLRS 4. Auflage (2022): Kap. 10 „Elementary Data Structures“ (Darstellung von Bäumen), Kap. 12 „Binary Search Trees“ (Inorder, Suche), Kap. 13 „Red-Black Trees“

Kern: Ein Binärbaum ist eine Struktur aus Knoten mit höchstens zwei Kindern. Fast jede Baumaufgabe ist eine Traversierung: DFS (Tiefensuche, rekursiv oder mit Stack) oder BFS (Breitensuche, Ebene für Ebene mit Queue). Beide besuchen jeden Knoten einmal: O(n) Zeit.

1. Wo sitzt das Muster?

  1. Knoten: Ein Knoten (TreeNode) hat einen Wert und Zeiger left und right.
  2. Wurzel und Blätter: Die Wurzel hat keinen Elternknoten. Ein Blatt hat keine Kinder.
  3. Höhe h: Die Höhe ist die längste Kette von der Wurzel zu einem Blatt. Balanciert: h ≈ log n. Entartet (Kette): h = n.
  4. DFS: geht erst in die Tiefe. Drei Reihenfolgen: Pre-, In-, Postorder. Speicher O(h) für den Stack.
  5. BFS: geht Ebene für Ebene mit einer Queue. Speicher O(w), w ist die grösste Ebenenbreite.
  6. BST: Ein binärer Suchbaum hat links nur kleinere, rechts nur grössere Werte, im ganzen Teilbaum. Inorder liefert dann sortierte Werte.

2. Die Reise einer Level-Order-Traversierung (die Geschichte zum Merken)

  1. Start: Die Wurzel kommt in die Queue.
  2. Ebene merken: size = q.size() ist die Anzahl Knoten dieser Ebene. Das ist der wichtigste Schritt.
  3. Genau size-mal pollen: Jeden Knoten in die Ebenenliste schreiben und seine Kinder hinten anhängen.
  4. Nächste Ebene: Die Kinder liegen jetzt allein in der Queue. Die Schleife beginnt von vorn.
  5. Ende: Die Queue ist leer. Jeder Knoten war genau einmal drin: O(n).

3. Beispiel: DFS, BFS und vier Klassiker in Java

Erkennen: Eingabe ist ein TreeNode root. „Tiefe“, „Pfad“, „Teilbaum“ → DFS. „Ebene“, „kürzester Weg zur Wurzel“, „von links nach rechts pro Zeile“ → BFS. „BST“ → Inorder ist sortiert oder Grenzen weitergeben.

Template (rekursive DFS): Basisfall, dann Kinder, dann kombinieren.

static class TreeNode {
    int val; TreeNode left, right;
    TreeNode(int v) { val = v; }
    TreeNode(int v, TreeNode l, TreeNode r) { val = v; left = l; right = r; }
}

static void inorder(TreeNode n, List<Integer> out) {     // O(n) Zeit, O(h) Stack
    if (n == null) return;                                // Basisfall
    inorder(n.left, out);
    out.add(n.val);
    inorder(n.right, out);
}

DFS iterativ (Inorder und Preorder mit eigenem Stack):

static List<Integer> inorderIterative(TreeNode root) {
    List<Integer> out = new ArrayList<>();
    Deque<TreeNode> stack = new ArrayDeque<>();
    TreeNode cur = root;
    while (cur != null || !stack.isEmpty()) {
        while (cur != null) { stack.push(cur); cur = cur.left; }  // ganz nach links
        cur = stack.pop();
        out.add(cur.val);
        cur = cur.right;
    }
    return out;
}

static List<Integer> preorderIterative(TreeNode root) {
    List<Integer> out = new ArrayList<>();
    if (root == null) return out;
    Deque<TreeNode> stack = new ArrayDeque<>();
    stack.push(root);
    while (!stack.isEmpty()) {
        TreeNode n = stack.pop();
        out.add(n.val);
        if (n.right != null) stack.push(n.right);          // rechts zuerst pushen
        if (n.left != null) stack.push(n.left);            // damit links zuerst kommt
    }
    return out;
}

1. Level Order (BFS) – O(n) Zeit, O(w) Speicher:

static List<List<Integer>> levelOrder(TreeNode root) {
    List<List<Integer>> res = new ArrayList<>();
    if (root == null) return res;
    Deque<TreeNode> q = new ArrayDeque<>();
    q.offer(root);
    while (!q.isEmpty()) {
        int size = q.size();                              // so viele Knoten hat diese Ebene
        List<Integer> level = new ArrayList<>();
        for (int i = 0; i < size; i++) {
            TreeNode n = q.poll();
            level.add(n.val);
            if (n.left != null) q.offer(n.left);
            if (n.right != null) q.offer(n.right);
        }
        res.add(level);
    }
    return res;
}

2. Maximum Depth – O(n) Zeit, O(h) Speicher:

static int maxDepth(TreeNode n) {
    if (n == null) return 0;
    return 1 + Math.max(maxDepth(n.left), maxDepth(n.right));
}

3. Validate BST – Grenzen von oben nach unten, O(n):

static boolean isValidBST(TreeNode n) { return valid(n, Long.MIN_VALUE, Long.MAX_VALUE); }
static boolean valid(TreeNode n, long low, long high) {
    if (n == null) return true;
    if (n.val <= low || n.val >= high) return false;
    return valid(n.left, low, n.val) && valid(n.right, n.val, high);
}

// FALSCH: prüft nur die direkten Kinder
static boolean isValidBSTWrong(TreeNode n) {
    if (n == null) return true;
    if (n.left != null && n.left.val >= n.val) return false;
    if (n.right != null && n.right.val <= n.val) return false;
    return isValidBSTWrong(n.left) && isValidBSTWrong(n.right);
}

4. Lowest Common Ancestor – Binärbaum O(n), BST O(h):

static TreeNode lca(TreeNode root, TreeNode p, TreeNode q) {
    if (root == null || root == p || root == q) return root;
    TreeNode l = lca(root.left, p, q), r = lca(root.right, p, q);
    if (l != null && r != null) return root;              // p links, q rechts
    return l != null ? l : r;
}

static TreeNode lcaBST(TreeNode root, int p, int q) {
    TreeNode cur = root;
    while (cur != null) {
        if (p < cur.val && q < cur.val) cur = cur.left;
        else if (p > cur.val && q > cur.val) cur = cur.right;
        else return cur;                                  // Weg trennt sich hier
    }
    return null;
}

  1. Rekursive und iterative Inorder liefern dasselbe. Der eigene Stack ersetzt den Call Stack.
  2. lca(20, 7) ist 20: Ein Knoten kann sein eigener Vorfahre sein.
  3. Im Baum bad liegt 3 rechts von 5. Die falsche Version prüft nur Eltern und Kind (6 und 3) und sagt true. Die richtige sieht die Grenze „grösser als 5“.
  4. Ein Knoten mit Integer.MAX_VALUE ist gültig, weil die Grenzen long sind. Mit int-Grenzen würde er fälschlich abgelehnt.
  5. Eine Kette mit 100 000 Knoten sprengt die rekursive DFS. BFS mit Queue schafft sie problemlos.

4. Details, die Interviewer fragen

  1. Top-down oder bottom-up: Top-down gibt Informationen nach unten (z. B. Grenzen bei Validate BST). Bottom-up gibt Ergebnisse nach oben (z. B. Tiefe, LCA). Frag dich: „Was braucht der Knoten von seinen Kindern?“
  2. Welche Reihenfolge? Preorder: Baum kopieren oder serialisieren. Inorder: BST sortiert ausgeben, k-kleinstes Element. Postorder: erst Kinder fertig, dann Knoten (Höhe, Löschen).
  3. Speicher: DFS O(h), BFS O(w). Balanciert ist h = O(log n). Eine Kette hat h = n. Ein voller Baum hat w ≈ n/2 in der letzten Ebene.
  4. BST-Operationen: Suchen, Einfügen, Löschen O(h). Nur bei balancierten Bäumen O(log n). Java TreeMap ist ein Rot-Schwarz-Baum mit garantiert O(log n).
  5. Validate BST, Alternative: Inorder-Traversierung und prüfen, ob jeder Wert grösser als der vorherige ist.
  6. LCA-Idee: Findet die linke Seite einen Knoten und die rechte Seite den anderen, ist der aktuelle Knoten der LCA.
  7. Durchmesser und Pfadsummen: Gleiches Bottom-up-Muster: Jeder Knoten gibt die Tiefe zurück und aktualisiert nebenbei ein globales Maximum.
  8. Randfälle: root == null, ein Knoten, nur linke Kinder (Kette), doppelte Werte im BST, Integer.MIN_VALUE/MAX_VALUE als Werte.
  9. So sprichst du beim Coden: „Basisfall: null gibt 0. Jeder Knoten fragt beide Kinder nach ihrer Tiefe und nimmt das Maximum plus eins. Jeder Knoten einmal besucht: O(n) Zeit, O(h) Speicher für die Rekursion, schlimmster Fall O(n) bei einer Kette.“

5. Vergleich

  • DFS rekursiv: kürzester Code, O(h) Stack, Risiko StackOverflowError bei tiefen Bäumen.
  • DFS iterativ: eigener ArrayDeque-Stack auf dem Heap, mehr Code, keine Tiefengrenze.
  • BFS: Queue, Ebenen, kürzester Weg in Kanten von der Wurzel. Speicher O(w).
  • BST: sortierte Struktur, O(h) pro Operation. Unbalanciert kann h = n sein.
  • TreeMap/TreeSet: balancierter BST (Rot-Schwarz), O(log n) garantiert, dazu floorKey, ceilingKey.
  • Heap: auch ein Binärbaum, aber nur „Eltern ≤ Kinder“. Kein Suchbaum.

6. In der Produktion

  1. StackOverflowError: Rekursion über tiefe Strukturen (z. B. verschachteltes JSON oder XML, Kategorie-Bäume). Lösung: iterativ oder Tiefe begrenzen.
  2. Unbalancierte Bäume: Sortierte Daten in einen einfachen BST eingefügt ergeben eine Kette. Lösung: balancierte Struktur wie TreeMap.
  3. Hierarchien in Datenbanken: Organigramme oder Kategorien als Eltern-Spalte. Abfragen über alle Ebenen mit rekursiven CTEs (WITH RECURSIVE).
  4. UI-Komponentenbäume: Frameworks wie Angular oder JSF halten die Oberfläche als Baum. Änderungen werden durch Traversierung verteilt.

7. Diagnose

  • Baum zeichnen: Vor dem Coden den Beispielbaum aufzeichnen und die erwartete Reihenfolge notieren.
  • Stack-Tiefe: -Xss ändert die Thread-Stackgrösse. Das ist ein Workaround, kein Fix.
  • Testbäume: leer, ein Knoten, Kette, voller Baum, der „bad“-BST mit tiefem Verstoss.

8. Senior-Punkte

  1. O(h) ehrlich nennen: „O(log n) wenn balanciert, O(n) im schlechtesten Fall.“ Das unterscheidet Senior von Junior.
  2. Rekursion ist im Interview gut, aber du sagst, wann sie in Produktion gefährlich ist.
  3. Validate BST ist ein Test für Invarianten: Die Regel gilt für den ganzen Teilbaum, nicht nur für Kinder.
  4. Fertige Strukturen nutzen: In echtem Code TreeMap statt eigener BST.

10. Fallen

  • „Ein BST ist gültig, wenn jedes Kind auf der richtigen Seite seines Elternknotens liegt.“ → Falsch. Die Regel gilt für den ganzen Teilbaum.
  • „BST-Suche ist O(log n).“ → Nur balanciert. Allgemein O(h), schlimmster Fall O(n).
  • „Rekursion braucht keinen Speicher.“ → Falsch. O(h) auf dem Call Stack.
  • „Grenzen als int mit Integer.MIN_VALUE reichen.“ → Falsch bei Knoten mit genau diesem Wert. long oder null als „keine Grenze“.
  • „BFS braucht weniger Speicher als DFS.“ → Kommt darauf an. BFS O(w), DFS O(h). Bei breiten Bäumen ist BFS teurer.

11. Fragen

Was ist der Unterschied zwischen DFS und BFS?

DFS geht erst in die Tiefe, mit Rekursion oder Stack. BFS geht Ebene für Ebene mit einer Queue.

Was sind Pre-, In- und Postorder?

Preorder: Knoten, links, rechts. Inorder: links, Knoten, rechts. Postorder: links, rechts, Knoten.

Was liefert Inorder auf einem BST?

Die Werte in aufsteigender Reihenfolge.

Wie viel Speicher braucht DFS?

O(h) für den Stack. h ist log n bei balancierten Bäumen und n bei einer Kette.

Wie viel Speicher braucht BFS?

O(w), die breiteste Ebene. Bei einem vollen Baum ist das ca. n/2.

Wie trennst du in BFS die Ebenen?

Vor der inneren Schleife size = q.size() merken und genau so oft pollen.

Wie schreibst du Inorder iterativ?

Ganz nach links und dabei pushen. Dann pop, Wert ausgeben, nach rechts gehen. Wiederholen.

Warum pusht man bei iterativer Preorder zuerst rechts?

Der Stack ist LIFO. Wer zuletzt gepusht wird, kommt zuerst. So kommt links vor rechts.

Wie berechnest du die maximale Tiefe?

null gibt 0, sonst 1 + max(Tiefe links, Tiefe rechts). O(n).

Wie prüfst du einen BST?

Grenzen (low, high) von oben weitergeben. Links wird high = Knotenwert, rechts low = Knotenwert. Oder Inorder streng steigend prüfen.

Warum long statt int für die Grenzen?

Ein Knoten kann Integer.MIN_VALUE oder MAX_VALUE haben. Mit int-Grenzen würde er fälschlich abgelehnt.

Wie findest du den LCA im Binärbaum?

Rekursiv beide Seiten fragen. Finden beide etwas, ist der aktuelle Knoten der LCA. Sonst gibt man weiter, was gefunden wurde.

Wie findest du den LCA im BST?

Sind beide Werte kleiner, nach links. Beide grösser, nach rechts. Sonst ist der aktuelle Knoten der LCA. O(h).

Was ist Top-down vs Bottom-up?

Top-down gibt Information an die Kinder weiter. Bottom-up sammelt Ergebnisse der Kinder und kombiniert sie.

Welche Komplexität haben BST-Operationen?

O(h). Balanciert O(log n), entartet O(n).

Was ist TreeMap intern?

Ein Rot-Schwarz-Baum, also ein balancierter BST. get, put, remove garantiert O(log n).

Wie findest du das k-kleinste Element im BST?

Inorder-Traversierung und beim k-ten besuchten Knoten stoppen. O(h + k).

Szenario: Deine rekursive Lösung wirft bei einem tiefen Baum StackOverflowError. Was tust du?

Ich schreibe sie iterativ mit ArrayDeque als Stack oder nutze BFS. -Xss erhöhen ist nur ein Workaround.

Szenario: Deine isValidBST sagt true für 5 mit rechtem Teilbaum 6(3, 7). Was ist falsch?

Ich prüfe nur direkte Kinder. 3 liegt rechts von 5 und verletzt die Regel. Fix: Grenzen low/high durch den ganzen Teilbaum weitergeben.

Szenario: Der Interviewer fragt „Die rechte Seitenansicht des Baums?“. Wie gehst du vor?

BFS mit Ebenen und pro Ebene das letzte Element nehmen. Oder DFS rechts zuerst und pro Tiefe das erste gesehene. O(n).
