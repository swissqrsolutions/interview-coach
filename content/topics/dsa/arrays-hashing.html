Arrays und Hashing

DSA · Tier 1 · Quellen: Java SE 25 API-Doku java.util (HashMap, HashSet, Map.merge, Map.computeIfAbsent, Arrays), CLRS 4. Auflage (2022): Kap. 11 „Hash Tables“

Kern: Arrays und Hashing ist das Muster „merk dir, was du schon gesehen hast“. Eine HashMap oder ein HashSet macht eine Suche von O(n) zu O(1) im Durchschnitt. So wird aus einer O(n²)-Doppelschleife ein einziger Durchlauf in O(n).

1. Wo sitzt das Muster?

  1. Eingabe: ein Array oder ein String. Die naive Lösung vergleicht jedes Paar: O(n²).
  2. Ein Durchlauf: Du gehst einmal von links nach rechts. Pro Element machst du O(1) Arbeit in einer Map.
  3. Frequenz-Map: Schlüssel = Element, Wert = Anzahl. Beispiel: freq.merge(x, 1, Integer::sum).
  4. Wert → Index: Schlüssel = Wert, Wert = Position. Beispiel: Two Sum findet so den Partner.
  5. Schlüssel → Gruppe: Ein kanonischer Schlüssel ist eine Normalform, die zusammengehörige Elemente teilen. Beispiel: sortierte Buchstaben für Anagramme.
  6. Prefix-Summe: Die Prefix-Summe ist die Summe aller Elemente bis Index i. Damit ist jede Teilsumme eine Differenz zweier Prefixe.

2. Die Reise von Two Sum (die Geschichte zum Merken)

  1. Start: Die Map ist leer. Sie wird „Wert → Index“ für alles, was links von i liegt.
  2. i = 0: Der Partner von 2 wäre 7. Die Map kennt 7 noch nicht. Also speichert sie 2 → 0.
  3. i = 1: Der Partner von 7 wäre 2. Die Map kennt 2 mit Index 0. Antwort: [0, 1].
  4. Der Kern: Statt für jedes Element alle anderen zu prüfen (O(n²)), fragt man die Map (O(1)). Gesamt O(n).
  5. Die Falle: Erst prüfen, dann einfügen. Sonst ist bei [3, 3] und Ziel 6 das Element sein eigener Partner.

3. Beispiel: vier Klassiker in Java

Erkennen: „Finde ein Paar / Duplikat / Gruppe“, „wie oft“, „Teilarray mit Summe k“, und n ist zu gross für O(n²).

Template (Frequenz-Map):

Map<Integer, Integer> freq = new HashMap<>();

1. Two Sum – Zeit O(n), Speicher O(n):

static int[] twoSum(int[] nums, int target) {
    Map<Integer, Integer> indexOf = new HashMap<>();      // Wert -> Index
    for (int i = 0; i < nums.length; i++) {
        int need = target - nums[i];
        Integer j = indexOf.get(need);
        if (j != null) return new int[]{j, i};             // erst prüfen ...
        indexOf.put(nums[i], i);                           // ... dann einfügen
    }
    return new int[0];
}

2. Group Anagrams – Zeit O(n · k log k) mit k = Wortlänge, Speicher O(n · k):

static List<List<String>> groupAnagrams(String[] words) {
    Map<String, List<String>> groups = new HashMap<>();
    for (String w : words) {
        char[] c = w.toCharArray();
        Arrays.sort(c);                                    // kanonischer Schlüssel
        groups.computeIfAbsent(new String(c), k -> new ArrayList<>()).add(w);
    }
    return new ArrayList<>(groups.values());
}

// Variante ohne Sortieren: O(n * k), nur 'a'..'z'
static String countKey(String w) {
    int[] cnt = new int[26];
    for (char ch : w.toCharArray()) cnt[ch - 'a']++;
    return Arrays.toString(cnt);
}

3. Contains Duplicate und Valid Anagram – Zeit O(n):

static boolean containsDuplicate(int[] nums) {
    Set<Integer> seen = new HashSet<>();
    for (int x : nums) if (!seen.add(x)) return true;      // add liefert false bei Duplikat
    return false;
}

static boolean isAnagram(String s, String t) {             // Speicher O(1): 26 Zähler
    if (s.length() != t.length()) return false;
    int[] cnt = new int[26];
    for (int i = 0; i < s.length(); i++) { cnt[s.charAt(i) - 'a']++; cnt[t.charAt(i) - 'a']--; }
    for (int c : cnt) if (c != 0) return false;
    return true;
}

4. Prefix-Summen: Subarray Sum Equals K und Range Sum – Zeit O(n):

static int subarraySum(int[] nums, int k) {
    Map<Integer, Integer> countOfPrefix = new HashMap<>();
    countOfPrefix.put(0, 1);                               // leeres Prefix
    int prefix = 0, result = 0;
    for (int x : nums) {
        prefix += x;
        result += countOfPrefix.getOrDefault(prefix - k, 0);
        countOfPrefix.merge(prefix, 1, Integer::sum);
    }
    return result;
}

static int[] buildPrefix(int[] a) {                        // p[i] = Summe a[0..i-1]
    int[] p = new int[a.length + 1];
    for (int i = 0; i < a.length; i++) p[i + 1] = p[i] + a[i];
    return p;
}
static int rangeSum(int[] p, int l, int r) { return p[r + 1] - p[l]; }   // O(1)

Echte Ausgabe, Oracle JDK 17.0.3. Die Gruppen von groupAnagrams wurden für die Ausgabe sortiert; HashMap hat keine feste Reihenfolge.

  1. [3,3] mit Ziel 6 liefert [0, 1] und nicht [0, 0]. Das beweist „erst prüfen, dann einfügen“.
  2. [3,2,4] liefert [1, 2]. Die 3 an Index 0 darf nicht mit sich selbst rechnen.
  3. Der Zähl-Schlüssel von „eat“ hat eine 1 bei a, e und t. Alle Anagramme haben denselben Schlüssel.
  4. subarraySum([1,-1,0], 0) = 3: [1,-1], [0] und [1,-1,0]. Mit negativen Zahlen funktioniert Sliding Window nicht, Prefix-Summe schon.
  5. countOfPrefix.put(0, 1) zählt Teilarrays ab Index 0. Ohne diese Zeile fehlt bei [1,2,3], k=3 das Teilarray [1,2].

4. Details, die Interviewer fragen

  1. Erkennen: Wörter wie „Paar“, „Duplikat“, „Anagramm“, „Häufigkeit“, „Gruppe“ oder „Teilarray mit Summe k“. Und die Brute Force wäre O(n²).
  2. Map oder Array als Zähler: Bei kleinem, festem Alphabet (z. B. 26 Kleinbuchstaben) ist int[26] schneller und O(1) Speicher. Bei beliebigen Werten nimmt man eine HashMap.
  3. merge und computeIfAbsent: merge(k, 1, Integer::sum) zählt in einer Zeile. computeIfAbsent(k, x -> new ArrayList<>()) legt eine Gruppe nur bei Bedarf an.
  4. Kanonischer Schlüssel: Sortierte Buchstaben kosten O(k log k). Der Zähl-Schlüssel kostet O(k). Für den Interviewer nennst du beide.
  5. Prefix-Summe: Summe von l bis r ist p[r+1] − p[l]. Vorbereitung O(n), jede Abfrage O(1).
  6. Prefix-Summe plus Map: Gesucht sind Paare von Prefixen mit Differenz k. Das ist Two Sum auf Prefixen.
  7. Randfälle: leeres Array, ein Element, alle gleich, negative Zahlen, Null, Overflow bei grossen Summen (long nutzen).
  8. Integer-Vergleich: Integer mit == vergleicht Referenzen. Werte ausserhalb −128…127 sind dann oft „ungleich“. Immer equals oder auf int auspacken.
  9. Sortieren als Alternative: Sortieren und Nachbarn vergleichen ist O(n log n) Zeit und wenig Zusatzspeicher. Das ist ein guter Kompromiss, wenn Speicher knapp ist.
  10. So sprichst du beim Coden: „Brute Force ist O(n²): jedes Paar prüfen. Der Engpass ist die Suche nach dem Partner. Ich merke mir Gesehenes in einer HashMap, dann ist die Suche O(1). Gesamt O(n) Zeit, O(n) Speicher. Ich teste mit [3,3] und Ziel 6.“

5. Vergleich

  • HashMap/HashSet: O(1) im Durchschnitt, keine Reihenfolge, beliebige Schlüssel.
  • int[] als Zähler: O(1) echt, nur für kleine bekannte Wertebereiche, sehr schnell.
  • TreeMap: O(log n), sortiert. Nötig bei „nächster grösserer Schlüssel“ (ceilingKey).
  • Sortieren + Scan: O(n log n), wenig Speicher, verändert die Reihenfolge (Indizes gehen verloren).
  • LinkedHashMap: wie HashMap, aber mit Einfügereihenfolge. Gut für „erstes eindeutiges Zeichen“.

6. In der Produktion

  1. Deduplizieren: Ein HashSet über IDs entfernt Duplikate in O(n). Mit equals/hashCode auf dem richtigen Schlüssel.
  2. Join im Speicher: Zwei Listen über eine ID verbinden: eine Liste in eine Map laden, die andere durchlaufen. O(n + m) statt O(n · m).
  3. Speicher: Jeder Map-Eintrag ist ein Objekt. Bei Millionen Integer-Schlüsseln wird das teuer. Lösung: Arrays, primitive Collections oder in der Datenbank zählen.
  4. Veränderbare Schlüssel: Ändert sich ein Schlüssel nach put, findet die Map ihn nicht mehr. Lösung: unveränderliche Schlüssel (String, Record).

7. Diagnose

  • Von Hand testen: leeres Array, ein Element, Duplikat, negatives Ziel. Laut durchgehen, bevor du „fertig“ sagst.
  • Map ausgeben: System.out.println(map) nach jedem Schritt zeigt, ob der Zustand stimmt.
  • Profiler / Heap-Histogramm: jcmd <pid> GC.class_histogram zeigt viele HashMap$Node bei grossen Maps.

8. Senior-Punkte

  1. Hashing tauscht Speicher gegen Zeit. Du nennst den Preis: O(n) Zusatzspeicher.
  2. Kleines Alphabet → Array. Das ist schneller und zeigt, dass du die Daten ansiehst.
  3. Prefix-Summe ist ein eigenes Werkzeug. Sie löst Teilarray-Fragen auch mit negativen Zahlen, wo Sliding Window scheitert.
  4. O(1) ist ein Durchschnitt. Schlechte hashCode-Methoden machen Maps langsam.
  5. Reihenfolge ist kein Versprechen. Tests, die auf HashMap-Reihenfolge bauen, sind falsch.

10. Fallen

  • „Bei Two Sum erst alles in die Map, dann suchen.“ → Riskant. Dann kann ein Element sich selbst finden. Erst prüfen, dann einfügen.
  • „Teilarray mit Summe k geht immer mit Sliding Window.“ → Falsch. Nur bei nicht-negativen Zahlen. Sonst Prefix-Summe plus Map.
  • „Integer a == Integer b vergleicht Werte.“ → Falsch. Es vergleicht Referenzen. Ausserhalb −128…127 oft false.
  • „Sortierte Buchstaben sind der schnellste Anagramm-Schlüssel.“ → Nicht ganz. Ein Zählarray ist O(k) statt O(k log k).
  • „HashMap behält die Einfügereihenfolge.“ → Falsch. Dafür gibt es LinkedHashMap.

11. Fragen

Wann denkst du an eine HashMap?

Wenn ich wiederholt suche, ob ich etwas schon gesehen habe. Das macht O(n²) oft zu O(n).

Wie löst du Two Sum in O(n)?

Eine Map Wert → Index. Für jedes Element prüfe ich, ob target − x drin ist, dann füge ich x ein.

Warum erst prüfen, dann einfügen?

Sonst kann ein Element sich selbst als Partner finden, z. B. 3 + 3 = 6 mit nur einer 3.

Wie gruppierst du Anagramme?

Mit einem kanonischen Schlüssel: sortierte Buchstaben oder ein Zählarray. Dann computeIfAbsent in eine Map von Listen.

Welche Komplexität hat Group Anagrams?

O(n · k log k) mit Sortieren, O(n · k) mit Zähl-Schlüssel. k ist die Wortlänge.

Wie prüfst du auf Duplikate?

HashSet.add liefert false bei einem Duplikat. O(n) Zeit, O(n) Speicher. Alternative: sortieren, O(n log n).

Wann nimmst du ein int[26] statt einer Map?

Wenn die Werte ein kleines festes Alphabet sind, z. B. nur Kleinbuchstaben. Schneller und O(1) Speicher.

Was ist eine Prefix-Summe?

p[i] ist die Summe der ersten i Elemente. Summe von l bis r ist p[r+1] − p[l], in O(1).

Wie zählst du Teilarrays mit Summe k?

Laufende Prefix-Summe und eine Map Prefix → Anzahl. Für jedes Prefix addiere ich, wie oft prefix − k schon vorkam.

Warum steht put(0, 1) am Anfang?

Es steht für das leere Prefix. So zählen auch Teilarrays, die bei Index 0 beginnen.

Warum funktioniert Sliding Window nicht mit negativen Zahlen?

Das Fenster zu vergrössern kann die Summe senken. Dann weiss man nicht mehr, in welche Richtung man schieben muss.

Was macht Map.merge?

Fehlt der Schlüssel, setzt es den Wert. Sonst kombiniert es alten und neuen Wert mit der Funktion, z. B. Integer::sum.

Was macht computeIfAbsent?

Fehlt der Schlüssel, erzeugt es den Wert mit der Funktion und speichert ihn. Dann gibt es den Wert zurück.

Welche Randfälle testest du?

Leere Eingabe, ein Element, alle gleich, negative Zahlen, Null, keine Lösung, grosse Summen (long).

Hashing oder Sortieren?

Hashing: O(n) Zeit, O(n) Speicher. Sortieren: O(n log n) Zeit, wenig Speicher, aber die Indizes gehen verloren.

Wie findest du das erste eindeutige Zeichen?

Erst zählen (int[26] oder Map), dann den String nochmal durchlaufen und das erste Zeichen mit Anzahl 1 nehmen. O(n).

Szenario: Der Interviewer sagt „Speicher ist knapp“ bei Contains Duplicate. Was tust du?

Ich sortiere in place und vergleiche Nachbarn. O(n log n) Zeit, kaum Zusatzspeicher. Ich sage, dass die Eingabe dabei verändert wird.

Szenario: Deine Two-Sum-Lösung gibt bei [3,3], Ziel 6 das Ergebnis [0,0] zurück. Was ist falsch?

Ich füge vor dem Prüfen ein, oder ich fülle die Map vorher komplett. Fix: im gleichen Durchlauf erst prüfen, dann einfügen.

Szenario: Zwei Listen mit je 1 Mio. Einträgen sollen über eine ID verbunden werden. Wie?

Die kleinere Liste in eine HashMap ID → Objekt laden, die andere durchlaufen. O(n + m) statt O(n · m). Wenn es nicht in den Speicher passt: in der Datenbank joinen.
