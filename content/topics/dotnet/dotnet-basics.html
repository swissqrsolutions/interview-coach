.NET und C# für Java-Entwickler

Kern: .NET ist die Laufzeit und die Bibliothek, C# ist die wichtigste Sprache dazu. Wie die JVM führt die CLR Zwischencode (IL) per JIT aus. Gegenüber Java sind Value Types, Properties, LINQ, async/await und reified Generics die grössten Unterschiede.

Antwort-Muster

Frage: Was ist in C# und .NET anders als in Java?

  1. Mechanismus: Roslyn kompiliert C# zu IL in einer Assembly. Die CLR macht daraus per JIT Maschinencode.
  2. Zahl: Aktuell ist .NET 11 (STS) und .NET 10 ist LTS. .NET 8 und 9 sind seit dem 10. November 2026 ohne Support.
  3. Trade-off: struct spart Heap-Objekte, kopiert aber bei jeder Zuweisung. Nullable-Typen warnen nur beim Kompilieren.
  4. Produktion: Ich schalte Nullable ein, nutze async bis ganz oben und bleibe auf einer unterstützten LTS-Version.

1. Vom Code zum laufenden Programm in 6 Schritten

  1. Quellcode: Du schreibst .cs-Dateien. Die Projektdatei .csproj nennt Zielversion und Pakete. Sie entspricht der pom.xml.
  2. Roslyn: Das ist der C#-Compiler. Er erzeugt IL (Intermediate Language) und Metadaten.
  3. Assembly: Das Ergebnis ist eine .dll. Sie entspricht einer JAR-Datei mit Bytecode.
  4. CLR: Die Common Language Runtime lädt die Assembly. Typen bleiben zur Laufzeit voll bekannt.
  5. JIT: Beim ersten Aufruf übersetzt der JIT die Methode in Maschinencode. Tiered Compilation optimiert heisse Methoden später neu.
  6. GC: Der Garbage Collector räumt den Heap auf. Er nutzt die Generationen 0, 1 und 2.

Der Weg ist fast gleich wie bei Java. Native AOT kann Maschinencode schon beim Build erzeugen. Dann gibt es keinen JIT zur Laufzeit.

2. Aufbau

  1. Die CLR ist die Laufzeit. Sie hat den JIT, den GC und das Typsystem.
  2. Die BCL (Base Class Library) ist die Standardbibliothek im Namespace System.
  3. Das SDK bringt den Compiler und die dotnet CLI mit. Die Runtime allein reicht zum Ausführen.
  4. NuGet ist der Paketmanager. Pakete stehen im .csproj als PackageReference.
  5. Ein Namespace gruppiert Typen wie ein Java-Package. Er muss nicht zum Ordner passen.
  6. Das Target Framework (net10.0) legt fest, gegen welche APIs du baust.

3. Details

  1. Value Types: Ein struct ist ein Value Type. Eine Zuweisung kopiert den Inhalt. Ein class ist ein Referenztyp, die Zuweisung kopiert nur die Referenz. Java hat dafür nur primitive Typen.
  2. Records: Ein record ist ein Typ mit Wertgleichheit. Er bringt Equals, GetHashCode, ToString und with mit. Records gibt es seit C# 9. Sie sind ähnlich wie Java Records, aber mit with-Kopie.
  3. Properties: Ein Property ersetzt Getter und Setter. { get; init; } heisst, der Wert wird nur beim Erzeugen gesetzt. init gibt es seit C# 9.
  4. Nullable Reference Types: Mit <Nullable>enable</Nullable> ist string nicht null und string? darf null sein. Der Compiler warnt. Zur Laufzeit gibt es keine Prüfung. Java nutzt dafür Annotationen.
  5. Reified Generics: List<int> bleibt zur Laufzeit ein eigener Typ. Es gibt kein Boxing der int. Java löscht die Typen (Type Erasure) und braucht Integer.
  6. LINQ: Where und Select sind lazy. Die Abfrage läuft erst bei ToList() oder foreach. Jedes neue Durchlaufen führt sie neu aus. Java Streams sind ähnlich, aber nur einmal nutzbar.
  7. Gleichheit: == kann überladen sein. Bei string und Records vergleicht es Werte. Bei object vergleicht es Referenzen. In Java vergleicht == immer Referenzen.
  8. using und IDisposable: using ruft am Blockende Dispose() auf. Das ist wie try-with-resources. Mit await using geht das auch asynchron.
  9. Keine Checked Exceptions: C# kennt nur ungeprüfte Exceptions. Methoden deklarieren sie nicht. Die Doku muss sie nennen.
  10. Extension Methods: Eine statische Methode mit this beim ersten Parameter wirkt wie eine Methode des Typs. LINQ besteht daraus. Der Compiler löst sie statisch auf.
  11. Pattern Matching: switch-Ausdrücke prüfen Typ, Wert und Bedingung. Sie liefern einen Wert. Das ist stärker als das klassische Java-switch.

4. Fallen

  • „Ein struct liegt immer auf dem Stack.“ → Falsch. Als Feld einer Klasse liegt es im Heap-Objekt. Beim Boxing kommt es als Kopie auf den Heap.
  • „== vergleicht in C# immer Referenzen wie in Java.“ → Falsch. Der Operator kann überladen sein. string und Records vergleichen Werte. Nur bei object zählt die Referenz.
  • „Nullable Reference Types verhindern die NullReferenceException.“ → Falsch. Sie erzeugen nur Compiler-Warnungen. Zur Laufzeit gibt es keinen Check. Der !-Operator schaltet die Warnung ab.
  • „LINQ führt die Abfrage sofort aus.“ → Falsch. Sie läuft erst bei ToList() oder foreach. Mehrfaches Durchlaufen führt sie mehrfach aus.
  • „Generics funktionieren wie in Java mit Type Erasure.“ → Falsch. In .NET bleiben Generics zur Laufzeit erhalten (reified). List<int> hat keine Wrapper-Objekte.
  • „.NET läuft nur auf Windows.“ → Falsch. Das heutige .NET läuft auf Windows, Linux und macOS. Das alte .NET Framework war nur Windows.

5. Selbsttest

Warum?

Warum kompiliert C# zuerst zu IL?

IL ist plattformneutral. Die CLR macht erst zur Laufzeit Maschinencode für die echte CPU. So läuft eine Assembly auf Windows, Linux und macOS.

Warum gibt es Value Types?

Ein struct braucht kein eigenes Heap-Objekt. Das spart Allokationen und GC-Arbeit bei kleinen Daten wie Punkten oder Beträgen.

Warum soll man Nullable einschalten?

Der Compiler findet viele mögliche Null-Fehler schon beim Bauen.

Wie innen?

Was macht die CLR beim Start?

Sie lädt die Assembly und liest die Metadaten. Sie kompiliert Methoden beim ersten Aufruf mit dem JIT. Der GC verwaltet den Heap.

Wie funktioniert using?

Der Compiler macht daraus ein try/finally. Im finally steht der Aufruf von Dispose().

Was ist Boxing?

Ein Value Type wird in ein Objekt auf dem Heap kopiert, zum Beispiel bei object o = 5. Das kostet Speicher. Unboxing kopiert zurück.

Warum ist LINQ lazy?

Where und Select liefern einen Iterator. Dieser berechnet Elemente erst, wenn jemand sie abruft.

Zahlen

Welche .NET-Version ist LTS?

.NET 10. .NET 11 ist eine STS-Version. Der Support beider endet am 14. November 2028.

Welche Versionen sind jetzt ohne Support?

.NET 8 und .NET 9. Ihr Support endete am 10. November 2026.

Wie viele GC-Generationen gibt es?

Drei: Generation 0, 1 und 2. Neue Objekte starten in Generation 0.

Vergleich

C# Property vs Java Getter und Setter?

Ein Property ist Sprachfeature mit get und init oder set. Java nutzt Methoden getX und setX oder Records.

LINQ vs Java Streams?

Beide sind lazy. LINQ-Abfragen auf IQueryable werden von EF Core in SQL übersetzt. Ein Java Stream ist nur einmal nutzbar.

.NET Generics vs Java Generics?

.NET behält die Typen zur Laufzeit. Java löscht sie. Darum gibt es in .NET new T() mit Constraint und keine Wrapper für int.

record in C# vs record in Java?

Beide haben Wertgleichheit. C# Records haben with zum Kopieren und können auch veränderbar sein. Java Records sind immer unveränderlich.

Produktion

Wann ist die Version eines Dienstes ein Problem?

Wenn der Support endet. Dann gibt es keine Sicherheits-Patches mehr. Zum Beispiel .NET 8 und 9 seit 10. November 2026.

Was tun bei vielen GC-Pausen?

Mit dotnet-counters die GC-Zahlen ansehen. Allokationen senken, zum Beispiel weniger Boxing und weniger kurzlebige Objekte.

Szenario: Ein Dienst läuft auf .NET 8. Was tun Sie?

Ich plane das Upgrade auf .NET 10 (LTS). Der Support für .NET 8 ist seit dem 10. November 2026 beendet. Ich ändere das Target Framework, baue neu und teste.

Szenario: Trotz Nullable enable gibt es eine NullReferenceException. Warum?

Nullable prüft nur beim Kompilieren. Daten aus JSON, Datenbank oder Reflection können null sein, obwohl der Typ es verbietet. Auch ! schaltet Warnungen ab.

Design

Wann nehme ich struct, wann class?

struct für kleine, unveränderliche Werte. Class für Objekte mit Identität oder grossen Daten. Ein grosser struct kostet beim Kopieren.

Wann nehme ich record?

Für Daten mit Wertgleichheit, zum Beispiel DTOs und Nachrichten. Für Objekte mit Verhalten und Identität nehme ich class.

Wann implementiere ich IDisposable?

Wenn die Klasse unmanaged Ressourcen oder andere IDisposable-Objekte hält. Der Aufrufer nutzt dann using.

Mehr

Gerüst

  • Warum? Gleiche Plattform-Idee wie Java, aber mit Value Types, Properties, LINQ und reified Generics.
  • Wie innen? Roslyn macht IL. Die CLR lädt, JIT übersetzt, GC räumt auf (Generationen 0, 1, 2).
  • Zahlen .NET 11 STS, .NET 10 LTS. .NET 8 und 9 ohne Support seit 10. November 2026.
  • Vergleich Generics reified, == überladbar, keine Checked Exceptions, Streams gegen LINQ.
  • Produktion Veraltete Version, Nullable-Fehler zur Laufzeit, Boxing und GC-Last.
  • Design record für Daten, struct nur für kleine Werte, Nullable immer an.

  1. Zwei Records mit gleichen Werten sind gleich (True), aber nicht dasselbe Objekt.
  2. Beim struct bleibt s1.X bei 1, denn s2 ist eine Kopie. Beim class zeigen c1 und c2 auf dasselbe Objekt.

Vergleich

  • Java: Bytecode, JVM, JIT, GC. Generics mit Type Erasure. Checked Exceptions. Streams.
  • .NET: IL, CLR, JIT, GC. Reified Generics. Keine Checked Exceptions. LINQ.
  • Properties: C# { get; init; }. Java Getter oder Record-Komponenten.
  • Null: C# Nullable Reference Types im Compiler. Java Annotationen und Optional.
  • Value Types: C# struct. Java hat nur primitive Typen.
  • Pakete: NuGet und .csproj. Java nutzt Maven oder Gradle.
  • Build-Ziel: Target Framework wie net10.0. Java nutzt die Release-Version.
  • Async: async/await mit Task. Java nutzt CompletableFuture oder Virtual Threads.

Produktion

  1. Version ohne Support: Ohne Patches bleiben Sicherheitslücken offen. Lösung: Target Framework auf die LTS-Version anheben und testen.
  2. NullReferenceException trotz Nullable: Daten von aussen (JSON, DB) können null sein. Lösung: Eingaben prüfen und required oder Validierung nutzen.
  3. Viele GC-Pausen: Zu viele kurzlebige Objekte. Lösung: Allokationen messen und senken. Server GC prüfen.
  4. Boxing in heissen Pfaden: object und Interface-Aufrufe auf structs kopieren auf den Heap. Lösung: Generics statt object nutzen.
  5. LINQ mehrfach durchlaufen: Dieselbe Abfrage läuft mehrmals, auch mehrfach gegen die Datenbank. Lösung: einmal mit ToList() materialisieren.
  6. Dispose vergessen: Verbindungen und Streams bleiben offen. Lösung: using und Analyzer-Warnungen beachten.

Diagnose: Werkzeuge und Befehle

  • dotnet --info zeigt SDK- und Runtime-Versionen.
  • dotnet-counters: zeigt live GC-Zähler, Heap-Grösse und Thread-Pool.
  • dotnet-trace: sammelt Traces für Profiling.
  • dotnet-dump und dotnet-gcdump: analysieren Abbilder des Speichers.
  • ILSpy oder JetBrains dotPeek: zeigen die IL und den dekompilierten Code.
  • Roslyn Analyzer im Build: finden fehlendes Dispose und Nullable-Fehler.

Senior-Punkte

  1. Der Support-Zyklus ist ein Betriebsthema. LTS-Versionen planen und rechtzeitig umsteigen.
  2. Nullable ist eine Compiler-Hilfe, keine Garantie. An den Rändern (JSON, DB) muss man trotzdem prüfen.
  3. struct nur für kleine, unveränderliche Werte. Ein veränderbarer struct erzeugt schwer sichtbare Fehler.
  4. Reified Generics ändern das Design. Man kann Typen zur Laufzeit abfragen.
  5. Async ist von oben bis unten ein Vertrag. Blockieren mit .Result ist eine Falle (siehe Seite async/await).
  6. Native AOT spart Startzeit und Speicher. Dafür fehlt Reflection-lastiger Code.
